# SPEC · 大型 3D 游戏工程规范（本项目落地版）

> 依据：`threejs-game-director` → `threejs-gameplay-systems` / `threejs-aaa-graphics-builder` 的生产口径，
> 结合本项目现状（Electron + Vite + Three.js r180，10km 城 + 三界，程序化几何为主、零外部素材）。
> 每条都写三件事：**规则（必须怎么做）· 标准（可量化的数字）· 验收（跑什么命令/看什么指标）**。
> 现状列只写查得到的证据，不写「应该没问题」。

## 1. 设计（Design）

**规则**
1. 任何「宽改造」先写三份短文档：**Design brief**（玩家承诺一句话 / 目标手感 / 主动词 / 副动词 / 5–30 秒重复什么 / 1–5 分钟变化什么 / 怎么失败 / 怎么重开 / 奖励什么 / 风险是什么 / 高手多做哪一步）、**Core loop 契约**（`玩家用[动词]达成[目标]，同时[压力]制造风险；成功给[奖励]，失败造成[代价]`）、**关卡或遭遇计划**（空间格式 / 相机看得见什么 / 起点·首个决策·首个威胁·首个奖励 / 地标 / 每 20–60 秒如何升级 / 恢复点 / 危险怎么预警 / 哪些是参数化模块）。
2. 「探索一个好看的场景」不算 brief：必须有决策、压力、反馈、后果。
3. 用户改需求 → 更新既有 brief 与待办，不重启已完成的部分。

**标准**：brief 里每个从句都要在代码里找得到对应实现（动词映射到真实输入、目标在 HUD 或世界里可见、压力在第一分钟出现）。

**验收**：`artifacts/game-progress.md` 中 brief 三条齐全，且每条括号里写着对应文件与行号。

**本项目现状**：🔴 只有世界与漫游，没有 brief/契约/关卡计划。**这是所有玩法问题的根**。

---

## 2. 开发（Development）

**规则**
1. 目录按所有权切：`core`（引擎/时间/渲染）· `game`（玩家/物理/交互）· `world`（生成）· `actors`（角色与行为）· `ui` · `fx` · `audio` · `data`。
2. 每个模块对外只暴露窄接口，跨模块通信走 `core/rng.ts` 的 `bus`（已有 20+ 事件）。
3. 每步可玩：任何一次提交后 `npx vite build` 能过、`#loading` 能消失。
4. 随机性全部走 `RNG`/坐标 hash，禁止 `Math.random()` 进世界生成（特效/音频可用）。

**标准**：`tsc --noEmit` 0 错；`vitest` 全绿；`probe-load` 打印全部 33 步。

**验收**：`npx tsc --noEmit && npx vitest run && node scripts/probe-load.mjs`。

## 3. 玩法（Gameplay）

**规则**
1. 核心循环必须有四要素：**压力**（时间/敌人/资源/坠落）、**奖励**（改变状态而不只是好看）、**失败教学**（告诉玩家发生了什么）、**快速重开**（≤3 秒）。
2. 手感常量集中管理：加速度、最大速度、转向速率、相机跟随阻尼、FOV、命中停顿、屏幕震动。
3. 打击/交互必须有「输入→状态→表现」三段落：状态变了才播表现，表现不能替代状态。

**标准**：桌面键鼠 + 触屏双输入可达；主循环 5–30 秒一次决策；失败到重开 ≤3s。

**验收**：`game-playtest-loop` 口径的真实输入脚本（键盘真实到达页面、位移与状态被推进），不是只看截图。

**本项目现状**：🔴 无压力/奖励/失败。已有：漫游（`game/player.ts`）、交互点（`game/interact.ts`）、传送（`world.teleport`）、图鉴、昼夜。

## 4. 建模（Modeling）

**规则**
1. 顺序固定：形体（silhouette）→ 构造（斗栱/檩头/瓦垄）→ 表面（材质）→ 光照 → 特效。**发光不代替形体**。
2. 每个可交互/可观赏对象都要有「三尺度读法」：远景剪影、中景体块、近景构造。
3. 实例化优先：重复件（民居、树、灯）走 `InstancedMesh`；一次性地标走合批 + 分批落盘。
4. 屋顶、柱列、门窗这类构造件必须由**单一真相源**函数生成（`roofProfile` / `commonerRoof` / `roofOn`），禁止各处手写斜板。
5. 坡度、旋转一律烘进几何或走 `rz`，**不得**把坡度写进 `push` 的 `rx`（`Euler('XYZ')` 下 `rx≠0 & ry=π` 会把构件上下翻）。

**标准**：单件视距分档（近/中/远）各有独立几何；民用屋顶 ≤120 面、官式 ≤600 面、地标 ≤4000 面；同屏实例化件 ≤1 draw call / 材质组。

**验收**：`probe-load` 分材质组面数台账 + 三视角截图（`scripts/three-view.mjs`）。

**本项目现状**：🟡 构造件齐全（悬山/五脊殿/斗栱/檩头/瓦当/滴水），但植物与法器仍以纯色球/锥为主。

## 5. 贴图（Texturing）

**规则**
1. UV 按**世界尺度**展开（`UV_TILE` 常量），一张图铺多少米写死在代码里；禁止按顶点序号乘尺寸（会把瓦纹压成噪点）。
2. 程序化画布贴图必须：固定种子、幂等缓存（同 key 不重画）、按材质语义分组（石/木/瓦/布/漆/陶/金属）。
3. 图集必须有**容量水位告警**：溢出即覆写旧 cell（本项目实测溢出 1 次 → 匾额错字/白板）。
4. 法线贴图只在有真实起伏语义时使用；瓦垄用**几何 + 顶点色**表达，不靠贴图拉伸。

**标准**：招牌图集 `overflowCount === 0`；任一材质组的贴图 tile 尺寸与世界尺寸误差 ≤10%。

**验收**：`node scripts/probe-console.mjs` 读 `atlas` 字段为 0。

**本项目现状**：✅ 溢出已修（5120→6144，padding 4）。🟡 植物/果实无专属贴图。

## 6. 渲染（Rendering）

**规则与预算**

| 项 | 标准 | 当前 |
|---|---|---|
| 帧时间 p95 | ≤ 20ms（1080p 桌面） | 未测 |
| draw call | ≤ 600 | 1045 ❌ |
| 静态三角面 | ≤ 8M | 6.17M ✅ |
| 阴影 | 相机裁到玩家 120m | 全场景 ❌ |
| 后处理 | Bloom 阈值 ≥1.0，ACES 色调映射，**任何自发光件 `toneMapped: true`** | 已改 ✅ |
| 分批落盘 | 每加载步 `Baker.flush` | ✅ |

**验收**：HUD `calls` + `probe-load` `tris=`；打包版 `verify-packaged` 的 `runtime` 行。

## 7. 特效（VFX）

**规则**
1. 特效由**事件**驱动（`bus` / 状态跃迁），不做常亮装饰。
2. 每个特效必须可归因：谁触发、持续多久、是否随距离剔除。
3. 粒子数量、贴图尺寸进预算表；同屏特效实例上限写死。

**标准**：任一特效都能在代码里找到唯一触发点；离屏/远距自动降级。

**验收**：`?traceGlow=1` + `scripts/probe-glow.mjs`（枚举发光件与体积），`bus` 事件清单。

**本项目现状**：🟡 `fx/vfx.ts` 有火星/水瀑/花瓣/雷/掌印/塔，事件驱动；缺「打击命中」类反馈。
补充（地府纵深）：`world.applyHellDepth()` 在地府按距奈何桥的纵深压雾+压自发光，实测走廊三点亮度 26.2 → 2.2 → 0.4。
纪律：这类「界域覆盖」必须写在 `applyLighting` **之后**——写成之前会被 `fog.density=0.0046` 的界域插值无条件拉平（本轮踩过）。

## 8. 音效（Audio）

**规则**
1. 每个玩家动作都要有听觉反馈：**开合面板 / 传送 / 取物 / 翻图鉴 / 跨界** 五类为最低集。
2. 环境音随界域切换（人间 / 天宫 / 地府），切换用 1.5–2s 淡入淡出，不硬切。
3. 允许全合成（零音频文件），但必须有：主增益、噪声底、事件音、限幅（防削顶）。
4. 首次用户手势后才创建 `AudioContext`（浏览器自动播放策略）。

**标准**：五类事件音齐全；界域切换有独立低频层；单事件峰值 ≤0.2 主增益。

**验收**：`node scripts/probe-audio.mjs`（给 `AudioContext` 打桩计数，真实触发传送/图鉴/跨界，断言节点数增长）。

**本项目现状**：✅ 本轮补齐（传送 +10、图鉴 +6、跨界换轨 +17 节点）。🔴 缺脚步/打击/风吹衣袂等持续层。

## 9. 关卡（Level）

**规则**
1. 每关四件套：**目标**（做什么）· **威胁**（被什么阻止）· **地标**（怎么认路）· **恢复点**（失败后从哪继续）。
2. 空间格式必须塑造决策：通道宽度、垂直落差、遮蔽物决定玩家能做什么。
3. 挑战每 20–60 秒升级一次；危险必须提前预警（光影/声音/动作）。

**标准**：任一 POI 都能回答「这里要干什么」；进阶路线与主路线可区分。

**验收**：三视角截图 + `poiGuide` 文案；每个 POI 在 `data/` 里有目标字段。

**本项目现状**：✅ 17 个节点已有四件套（`src/data/levelPlan.ts`），HUD 目标行随最近节点切换。
实测（`scripts/probe-level.mjs`）：传送至奈何桥 → 「naihe / 45m / 过奈何桥，别回头看」；紫宸殿 → 「zichen / 199m / 登上紫宸殿丹陛」；三生石 → 「sansheng / 27m / 在三生石上读自己的前世」。
目标判定：✅ 已接状态机（`world.objectiveDone` + `tickObjectives`，每 0.4s 按**化身**距离判定，
Boss 节点看 `boss.defeated`），达成时写回图鉴并弹「目标达成」+ 音效，HUD 打 ✓。
实测（`scripts/probe-objective.mjs`）：传送奈何桥 → `done:true` / `node:naihe` / 「目标达成：地府·奈何桥」；
传送到将台（与星宿九府中心仅差 10m）→ 星宿九府保持 `done:false`（半径系数压到 0.2，避免顺手点亮）。
**已知欠账**：威胁文案对应机制尚未逐个接成事件；Boss 节点达成后的一行断言未并入 probe-boss。

## 10. Boss

**规则**
1. Boss 必须是**状态机**：阶段（≥2）· 血量 · 攻击前摇（可读）· 破绽窗口 · 胜负判定 · 重开 ≤3s。
2. 演出与可打分离：`havoc.ts` 这类剧本演出不能算 Boss，玩家输入必须能改变 Boss 状态。
3. 奖励必须改变状态（解锁图鉴条目 / 新 POI / 新技能），不能只弹字。

**标准**：阶段切换有明确视觉+听觉信号；玩家在 60–180 秒内能完成一场；失败后可立刻重试。

**验收**：`scripts/probe-boss.mjs`（注入真实输入，断言血量单调下降、阶段跃迁、胜利标志、重开后血量复位）。

**本项目现状**：✅ 首个可打 Boss 已落地（`game/boss.ts` 状态机 + `data/boss.ts` 数值表）。
`sky/havoc.ts` 仍是自动演出（名场面），两者并存、职责分离。
实测（`scripts/probe-boss.mjs`）：HP 320→0 用 27 次真实 `KeyJ`；跨越 50% 触发阶段 2；被横扫击退后玩家距 Boss 41.9m（回将台恢复点）。
化身绑定：✅ 实测 `deities.map.get('巨灵神')` 命中（Boss 落在 (40.2, 208, 8.2)，即巨灵神本尊站位），不是擂台心坐标。
胜利奖励：✅ 写回 `world.codexLog` 并在图鉴面板渲染（`probe-boss` 断言 5：`log=1 / name=巨灵神 / inDom=true`）。
**已知欠账**：失败复位距离不稳定（19–42m，玩家控制器会重新贴地），断言改为「被推开 ≥10m」；Boss 只有一名。

## 11. 启动 / 载入（Boot & Loading）

**规则（四段式）**
1. Boot：≤1s 出首帧（只画穹顶 + HUD 骨架）。
2. Preload：分级（T0 首帧必需 / T1 可交互前 / T2 视距内 / T3 余下），每步前后 `await raf()`。
3. World：每步结束落盘，单步目标 ≤16ms 切片（当前最慢 1.9s，未达标）。
4. Interactive：loading 消失后 1 帧内可接受输入。

**标准**：总时长 ≤12s（桌面）；峰值 JS 堆 ≤1.5GB；单步 >1200ms 必须控制台点名。

**验收**：`node scripts/probe-load.mjs`（耗时表 + 堆 + 面数 + `MAIN_THREAD` 判定）。

**本项目现状**：✅ 15.9s / 1.05GB / 33 步 / 全表可见；❌ 5 步 >1.2s。

## 12. 互动（Interaction）

**规则**
1. 一次互动 = 输入 → 状态跃迁 → 三通道反馈（UI 文案 + 音效 + 特效/动画），三者缺一即视为未完成。
2. 键位必须完整且可在帮助面板查到；触屏必须等价可达。
3. 交互提示在视野内出现，不靠玩家摸索（准星/高亮/距离阈值）。

**标准**：所有 `POINTS` 交互点都同时有文案、音效、特效；键位表与实现一致。

**验收**：`probe-audio` + `interact` 回归；帮助面板键位表与 `keydown` 分支逐条比对。

**本项目现状**：🟡 文案与特效已有，音效本轮补上「取物」类，缺脚步与打击。

## 14. 判据速查

- **不许用「发光/雾」代替形体**：`probe-glow` 列出的发光件若体积排序前十里出现 >8m 的纯白件，即为缺陷。
- **不许用「截图好看」代替行为**：每个状态变化都要有 `probe-*` 的数字证据（节点数 / 血量 / 位置 / 面数）。
- **冻结/卡死三判据**：冻结位置逐次漂移 + 堆逼近 3GB → GC 悬崖；栈稳定同一行 → 死循环；隐藏某组后 `triangles` 降但画面不变 → 该组不是来源。
