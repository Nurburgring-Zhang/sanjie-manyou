# SPEC · R17 里坊只剩「灰盒子」（屋顶/门窗/铺装全丢）

> 用户截图（2026-11-01，紫宸殿 1215m）：整片里坊是**灰白色的无顶方盒**，铺地在沙土上，看不到屋顶、山墙、门窗、院墙、石板路。

## 现象拆解

| 该有 | 图上 | 判断 |
|---|---|---|
| 两坡屋顶（悬山：正脊+檐口+瓦垄） | **完全没有**，只有平顶方盒 | `infill_roof` / `infill_gable` 这批 InstancedMesh 被整批隐藏或被 LOD 判成 far/impostor |
| 院墙（断续 12–28m） | 无 | `infill_wall` 同批消失 |
| 石板铺装（`buildPavement`） | 无，露出沙土 | `ground`/`slab` 也被隐藏，或该区压根没铺 |
| 门窗/窗光 | 无 | `infill_glow` 消失 |
| 建筑尺度 | 方盒 10–20m，与预期一致 | 说明 **body 组正常，其余组被隐藏** |

## 最可能的根因（按嫌疑排序）

1. **O（LOD）的分桶/可见性 bug**：`Engine.LodManager` 把「档位:空间单元」注册为组，若某单元的 roof/gable/wall 组被注册成独立 group 而 body 组被注册成另一 group，档位解析不一致 → body 可见、其余隐藏。O 的交接里写「每组交出去的是同一批 InstancedMesh 的可见子集」——若某组只含 roof 不含 body，就会出现"有身无顶"。
2. **合批只合了 body**：`compactStatic` 只处理 `city_*`，`infill_*` 若也参与合批但只合了部分材质组，同样会"有身无顶"。
3. **`buildPavement` 在该区没跑或铺装被降到不可见档**。

## 判定（机检）

在紫宸殿 1.2km 机位、固定相机下统计：
- `infill_body` 可见实例数 > 0
- `infill_roof` + `infill_gable` 可见实例数 **≥ body 的 0.9 倍**（每栋都该有顶）
- `infill_wall` 可见数 > 0
- `ground` 组在该矩形内有铺装面（`__groundTrace` 查 y∈[0.05,0.25] 的 ground 构件）

任一条不满足即判「里坊残缺」。

## 与 R14b（巨型碎块）的关系

两处都出现在紫宸殿周边，且都是"几何批次可见性/缩放异常"。**大概率同一个根因**（LOD 或合批），必须一起查、一起修，不要分两次。
