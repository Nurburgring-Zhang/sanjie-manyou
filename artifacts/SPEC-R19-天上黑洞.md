# SPEC · R19 天上的「巨大黑洞」

> 用户截图（2026-11-01，东洋巨泽 5139m，仰视）：天空中出现一块**数百米级纯黑圆盘/穹顶**，边缘散布大量白色方块（云团），下方还有褐色棱柱块。

## 判断

那块黑 = **天宫云海盘的背面**。

证据链（此前已用隐藏-对照证过两次）：
1. 人间仰视看到的"天空"不是穹顶（藏穹顶 r=46000 画面逐位不变）；
2. 只有藏 `city_fabric` 才变 ⇒ 云海盘由 fabric 烘焙；
3. 云海盘是**大平面**（y≈190–196），从下方看是它的**背面**，`MeshPhysicalMaterial` 单面渲染 + 无光照到背面 ⇒ 纯黑；
4. 周围白色方块 = 云团/云托（fabric，同样从下方看到的是暗面或高光面），黑底一衬就是"白块"。

## 已有的修复能力（没接线）

`src/sky/expansion.ts` 里 `buildCloudSeaView(scene)` + `CloudSeaHandle.setViewerY(y)` 就是为这件事写的：
- y ≥ 180（天宫视角）→ 不透明 1.0；
- y ≤ 90（人间地面）→ 透明 ≤0.06 或 `visible=false`；
- 中间线性过渡。

**上一轮我接线后测到 p95=100ms 就回滚了，后来证明那次是测量环境污染（残留 chrome + 同时打包），v76 干净环境复测是 17ms。** 所以这路修复本该合入，却被错误回滚——这是我的判断失误。

## 修法（三步，按序）

1. `world.ts` 加载末尾：`this.cloudSea = buildCloudSeaView(scene)`；
2. `world.update()` 每帧：`this.cloudSea?.setViewerY(this.engine.camera.position.y)`；
3. `Engine.step` 里已有 LOD/材质更新顺序，确保 `setViewerY` 在相机定型之后调用。

## 判定（机检）

- 用 `probe-glare`/新 `probe-sky.mjs`：在人间地面（y≈4）仰视天顶，统计屏幕上半区**亮度 < 12 的像素占比**，修复前该值应 >25%（黑洞），修复后必须 **<3%**；
- 同时统计白色方块簇（lum>232 且面积 >200px）数量，修复后 **<2**。
