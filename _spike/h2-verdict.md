## 二、每帧预算账

- **推荐结构 b2（网格增量 @8m）**：p95 0.055ms = dev frame p95 33.3ms 红线的 **0.16%**，60fps 16.7ms 的 0.33%，打包态 58ms 口径的 0.09%。加上 P0-7 全员贴地（0.98ms）也只占 2.95%——**两条查询负载合计仍 <3.1%**，可以立字据。
- 最坏可接受 a1（npcSweep 式）：p95 1.86ms = 5.6%——单个系统勉强可活，但这正是现网 npcSweep 已经在付的成本（审计 P1-3/E1 的反面教材）；其中 per-candidate clone 的分配使自身耗时 +35%（p95）/ +42%（avg），且 52,812 次分配/帧的回收债以 GC 尾刺形式落在别人的 p95 里（b0 的 max 1.92ms 尖峰同机理）。
- 结论的量级依据：100 次 pointQuery 时结构选择是「优化题」（0.055 vs 1.86ms，差 34×）；到 P0-7 的 4,400 次/帧就变成「生死题」（0.98 vs 34.3ms）。**P0-2/P0-7 合并条目的查询结构必须按 4,400 次/帧的量级选，即必须网格。**

## 三、结构裁决：网格增量 > 网格重建 ≫ SAP > 线性扫

1. **增量 vs 重建（同语义）**：增量 p95 0.055ms，池化重建 0.266ms（4.8×），清空式重建 0.228ms。池化重建的分配为 0 但每帧仍要重插 4,400 条 + 维护 active 表，纯时间就输；清空式重建 avg 更低（0.143）但 1,079 数组/帧的分配债变成 max 1.92ms 的 GC 尖峰——H5 归因的「偶发尾部」正是这类东西。增量每帧实际只搬运 ~9.6 个换格实体（walk 速度 + 8m 格）。
2. **网格 vs SAP**：两者都远低于预算，但 SAP 在三次全量复跑间 p95 波动 0.046→0.098（2×），网格@8m 稳定（0.062/0.062/0.055）；且 SAP 的传送/spawn/dispose 需要重排处理，网格是 O(1) swap-remove；pointQuery 网格只要 1–4 次 `Map.get`，SAP 要二分 + 扫 14.4m 窗。**「broadphase 还是网格哈希」选网格哈希。**
3. **cell 尺寸 = 8m**：4m 窗口格数翻倍、p95 变差（0.060）且内存翻倍；16m avg 略优但 max 尾部更差（0.180）、单格更密（6m AOE/`cannonBlast` 退化成大桶）、复跑间波动更大。8m 下 2.2m 车撞半径 + hw≤5m 扩展 = ≤2–3 格/轴，三项负载都落在甜区。

## 四、对 P0-2/P0-3 spec 的三条修订建议

1. **P0-1 §6 / P0-2 查询路径改写**：「`groundHeight()` 遍历 `forEach('block'|'creation')`」必须改为「经 collider 网格（cell 8m）做 pointQuery，网格由 P0-3 增量维护」。forEach 线性路径只允许出现在初始化/批量建索引，禁止进每帧热路径——实测 4,400 点/帧时线性扫 p95 34.3ms = 爆预算，100 点/帧时也是网格的 25 倍。
2. **P0-3 broadphase 落名**：spec 的「collider registry + broadphase」直接定名为「均匀网格哈希：cell=8m、数字打包 key（禁字符串 key）、静态插一次 / 动态换格 swap-remove、结果缓冲池化复用」；SAP 与每帧全量重建两案否决（§三数据）。`dispose` 经 `onDispose` 摘格，传送/`setBounds` 走「摘格→插格」入口。
3. **全仓禁令 + 预算门**：查询热路径禁 per-candidate `clone()`（npcSweep 式分配 = 自身耗时 +35%、且 GC 债转嫁帧尾）；在 D7/G0 加预算行：**新增每帧碰撞查询 ≤0.5ms（p95）；P0-7 全员贴地场景 ≤1.5ms**。验收探针复用本基准的三校验和法（候选数/id 和/top 和跨结构比对），防「测得快是因为查得少」。

## 五、风险（一条）

**增量网格的正确性风险：非连续位移会留幽灵格。** 传送、击飞弹道（`launches` 积分）、造物 `setBounds`、`dispose` 都不经过逐帧积分，旧格数组会继续挂着已离开/已注销实体的索引——查询返回死者，而 P0-1 的「id 永不复用」救不了网格索引。处置：所有非连续位移必须走统一「摘格→插格」入口；probe 加三条不变量断言（每实体 slot 反查回自身；格数组无重复 id；dispose 后候选集不含死者），违规即红。

## 六、口径与限制

- 窄相成本（npcSweep 的点积判向、AABB 精判）为全结构公共成本，未计入；车辆是查询源不在 4,400 目标集内；体素地面走 D3 高度场（`Uint8Array`，O(1) 查表），不占本预算。
- 本基准是 Node 单线程 V8（v25.2.1，与浏览器同引擎）；浏览器主线程有渲染/合成竞争，绝对值会劣化，但结构间排序与倍数关系成立；dev/打包口径差异按 H5 结论不可混用，打包态复测归 P3-1b。
- 复现：`node _spike/h2-collision-bench.mjs`（自动经 `--expose-gc` 子进程重跑，输出同款 JSON 与表格；同 seed 结果逐位可复现）。
