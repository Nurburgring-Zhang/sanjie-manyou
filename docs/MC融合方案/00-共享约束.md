## 二、写作硬要求

0. **字数口径（唯一定义）**：**汉字数（CJK）**，8,000–9,000/卷。
   不是 `wc -m`（本机 Git Bash 默认 locale 下返回字节数）、不是字节数、不是总字符数。
   正文里大量 `文件:行号`、表格、ASCII 图会让总字符数变成 2–3 倍，**这是正常的，不要为此删减可执行细节**。
   量法：Python `len(re.findall(r'[\u4e00-\u9fff]', text))`。

1. **原子粒度**：每个系统拆到「可派给一个 agent 单独实现」的大小，给出：输入 / 输出 / 数据结构 / 文件落点 / 与现有系统的接口 / 验收断言。
2. **禁止空话**：不许出现「提升沉浸感」「优化体验」这类无判据表述。每条结论必须落到 ① 具体文件 ② 具体数据 ③ 具体 probe。
3. **必须写冲突**：Minecraft 是**体素、可破坏、无限世界**；本项目是**烘焙、静态、有限三界**。每一卷都要明确写「这一条与现有架构的冲突是什么、代价多少」。
4. **必须写取舍**：给 A/B 方案时写清各自的面数、内存、载入时间、开发量。
5. **不虚构**：不确定的写「待验证」，不写假的基准数据。

## 四、互审规则（双 AI 对抗）

写完后由**独立评审 agent**逐卷攻击，只许给两种结论：
- **放行**：论点成立、与代码事实一致、有可执行落点
- **打回**：指出具体段落 + 具体错误（事实错 / 与现有架构冲突未写 / 无判据 / 编造数据）

被打回的段落必须重写，重写后再次送审。
