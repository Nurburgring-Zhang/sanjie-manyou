# V12 路线图与验收

> 本卷把 V1–V11 的结论折成可执行的东西：**先做什么、做完凭什么算完、什么不做、出了问题怎么回滚。**
>
> 前置约定：V11 已证明「全量体素化不可行、局部沙盒可行」，V12 的路线图按这个结论排，不再给全量方案留里程碑。若后续要推翻这个结论，必须先推翻 V11 §11.6 的四道约束，而不是在路线图里偷偷加一条「重构三界为体素」。

## 12.1 路线图的三条原则

1. **每个里程碑都能独立出包。** 不做「憋六个月一次大爆炸」。M1 做完就有一个能挖能放的沙盒，M2 做完就有流式，任何一步停下来，前面的成果仍然可玩、可验收。
2. **先口径，后功能。** M0 不改一行 `src/`，只把探针、基线、三次取中位数的纪律固化。没有 M0，后面的「达标」都不可比。
3. **性能门先于玩法门。** 每个里程碑的退出判据里，回归门（静态面、载入、draw call、峰值堆）优先于新功能门。回归门红了，功能做得再多也不许进下一里程碑。

### M0 口径冻结与基线固化（3 人日）

**目标**：把「13.35M 还是 15.09M」「1.83GB 还是 2.62GB」「calls 420 还是 608」这三个已经吵过一轮的问题，用一份可复现的基线文件钉死。

**涉及卷**：V11、V12。

**退出判据**：

- `scripts/probe-mem.mjs --runs 3 --json artifacts/baseline-<build>.json` 产出三次采样，字段含 `staticTris`、`attrMB`、`heapPeakMB`、`heapEndMB`；
- `scripts/probe-calls-sweep.mjs` 产出六机位 `callsMax` 与 `frameP95`；
- `scripts/verify-packaged.mjs` 产出 `navToEngineMs + engineMs`、`flushMs`、`errors`；
- 新增 `scripts/probe-matrix.mjs --list` 能列出 12 卷的全部断言（此时可以全是 🔴）；
- **不改 `src/` 任何文件**；`git diff --stat` 只含 `scripts/` 与 `artifacts/`。

**风险**：探针本身有 bug（历史上有过「探针口径错，不是几何缺」的先例）。缓解：每个 probe 先跑 `--self-test`，负样本必须 BLOCK。

### M1 体素最小闭环（12 人日）

**目标**：一个 1 万方块的沙盒，能挖、能放、能走、能看见洞；现有三界一项不改。

**涉及卷**：V2（体素世界）、V3（方块与材质）、V11（性能）。

**退出判据**：

- `probe-voxel-edit.mjs`：连续 100 次破坏 + 100 次放置，A8/A10/A11 全绿；
- `probe-voxel-mem.mjs`：**1 万块档**常驻增量 ≤8MB、峰值增量 ≤16MB；64/128MB 是 M2 五万块档的上限，不许在 M1 就花光；
- `probe-voxel-mesh.mjs`：16³ 块 meshing p95 ≤4ms（A6）；
- `probe-mem.mjs` / `probe-calls-sweep.mjs` / `verify-packaged.mjs`：A1/A2/A5 与 M0 基线相比不回归；
- 方块类型 ≥8 种（土/石/木/砖/瓦/沙/水/空气），全部走 1 张图集、≤2 个材质（A14）。

**风险**：BatchedMesh 行为不符预期（R07）。缓解：M1 第一周先做 245 slot 的微基准，不行就退回「每 16³ 块一 Mesh + 只允许 5 万块」。

### M2 chunk 流式与 LOD（15 人日）

**目标**：沙盒扩到 5 万方块、256m × 256m × 64m，进出不卡、离开不泄漏。

**涉及卷**：V2、V11。

**退出判据**：

- `probe-voxel-stream.mjs`：连续 300 帧上传 ≤4MB/帧、≤2ms/帧（A7）；
- `probe-voxel-edit.mjs`：脏块队列 ≤500ms 排空、≤64 长度（A9）；
- A12 进出沙盒 3 次，`geometries` 回到基线 ±5%；
- `probe-voxel-degrade.mjs`：L1/L2/L3 三档都能被 `?voxdegrade=` 强制触发，动作生效且日志可查（11.9）；
- 视距 128m 下 `callsMax` 增量 ≤32。

**风险**：Worker 结果过期导致泄漏（R06）。缓解：`generation` 计数器 + 进出沙盒的 `geometries` 断言。

### M3 采矿·冶炼·合成（18 人日）

**目标**：矿石分布 → 开采 → 熔炉 → 锭 → 工具/武器的最小闭环，配方可完成率 100%。

**涉及卷**：V4。

**退出判据**：

- `probe-craft.mjs`：20 条基础配方，每条都能用「合法输入」产出目标物，且「缺料」时失败；
- 矿脉在沙盒内的可达性：从出生点步行 ≤120s 能到达至少 3 种矿；
- 熔炉有 tick 成本上限：100 台熔炉同时工作，`frameP95` 增量 ≤2ms；
- 配方表是数据驱动（JSON/TS 表），新增配方不改代码。

**风险**：配方系统与现有 `itemKit.ts` / `interiors.ts` 的器物体系重复。缓解：先复用现有物品 id，不另起一套命名。

### M4 建造与结构（20 人日）

**目标**：蓝图放置、脚手架、结构完整性（悬空过多会塌），且不破坏现有建筑。

**涉及卷**：V5。

**退出判据**：

- `probe-build.mjs`：10 张蓝图在 3 种地形上落位成功，占地不越界、不压河道；
- 结构完整性：悬挑 >8m 且无支撑 → 塌落；有支撑 → 稳定；两种用例都机检；
- 脚手架可搭可拆，拆除后无残留碰撞体；
- 建造 1000 方块后，A8 帧预算仍绿。

**风险**：结构完整性变成「物理模拟」，tick 成本失控。缓解：只做「静态支撑图 + 离散判定」，不做逐块刚体。

### M5 生存循环（14 人日）

**目标**：生命/饥饿/状态/天气/昼夜，三界差异（人间正常、天宫不饿、地府持续失温）。

**涉及卷**：V6。

**退出判据**：

- `probe-survival.mjs`：饥饿 0→100 用时 20 分钟（可配置），归零后每秒掉血；进食回补；死亡与重生闭环；
- 三界差异各有一条断言：天宫饥饿速率 = 0、地府体温持续下降、人间昼夜与现有 `palette.ts` 同步；
- 天气切换不影响 `frameP95` 超过 3ms；
- 所有数值在配置文件里，不散落在代码。

**风险**：与现有 `player.ts` / `behaviors.ts` 的状态机冲突。缓解：新增 `SurvivalState`，只读现有状态，不改造 `PlayerController`。

### M6 探索与地下（22 人日）

**目标**：洞穴、遗迹、三界传送门；地下可走、可挖、可返回。

**涉及卷**：V7。

**退出判据**：

- `probe-explore.mjs`：从沙盒入口进入洞穴，步行 300m 内遇到 ≥1 处遗迹；原路可返回；
- 三界传送：人间→天宫→地府→人间 闭环，落点误差 ≤2m，不卡在几何里；
- 洞穴不与现有河道/建筑地基冲突（射线检测 `buildingsInRiver` 同类断言）；
- 地下雾/光照不导致「满屏纯黑」（沿用 `probe-hell` 的亮度判据，中位亮度 ≥12/255）。

**风险**：三界坐标口径混用（R11），历史上已发生过传送落点偏 130m。缓解：所有传送点走 `heavenFrame.ts` 单一真相源，新增 `probe-frame.mjs` 静态检查。

### M7 生物与 NPC（18 人日）

**目标**：6 种被动、4 种敌对、繁殖与驯服；复用现有 `crowd.ts` / `creatures.ts`，不另起 actor 系统。

**涉及卷**：V8。

**退出判据**：

- `probe-mobs.mjs`：每种生物有「生成→行为→死亡/掉落」三断言；
- 繁殖：两只同种 + 食物 → 幼体，冷却与上限生效；
- 驯服：喂食 N 次后跟随，未驯服不跟随；
- 100 只生物同屏，`frameP95` 增量 ≤5ms；
- 不与现有 4496 角色池冲突（`liveCount` 仍可解释）。

**风险**：actor 数量膨胀，重蹈「4496 人已很重」的覆辙。缓解：生物用对象池，上限硬编码，超限不生成。

### M8 战斗与装备（16 人日）

**目标**：武器/护甲/附魔/Boss；复用现有 `ArenaBoss` 与 `playerWeapon`。

**涉及卷**：V9。

**退出判据**：

- `probe-combat.mjs`：武器伤害、护甲减伤、附魔生效各一条数值断言；
- Boss 三阶段状态机可复现，阶段切换有阈值；
- 战斗 60s，`frameP95` 增量 ≤5ms；
- 掉落物可拾取、可入背包、可再装备（roundtrip）。

**风险**：数值平衡无法机检。缓解：只机检「公式与边界」，平衡交给试玩，不假装能用断言证明「好玩」。

### M9 多人·存档·确定性（25 人日）

**目标**：种子确定性、存档 roundtrip、双客户端 lockstep。

**涉及卷**：V10。

**退出判据**：

- `probe-save.mjs`：存档→读档→再存档，两次存档的规范化哈希相同；
- `probe-seed.mjs`：同 seed 生成两次，地形/矿脉/生物初始位置哈希相同；
- `probe-lockstep.mjs`：两客户端跑 10,000 tick，状态哈希逐 tick 相同；
- 存档体积 ≤8MB（5 万方块沙盒）；
- 版本升级有迁移函数，旧档可读。

**风险**：浮点不确定（R10）。缓解：模拟层用定点数/整数坐标，渲染层才用 float；`Math.random` 全部替换为 seeded RNG。

### M10 全量验收与出包（8 人日）

**目标**：12 卷矩阵全绿（或显式标 🟡 并有理由），打包出可交付 exe。

**涉及卷**：V12。

**退出判据**：

- `node scripts/probe-matrix.mjs` 退出码 0，输出每卷 PASS/BLOCK；
- `verify-packaged.mjs`：`PACKAGED_BOOT=PASS`、`errors NONE`、`callsMax ≤600`、载入 ≤12s；
- `tsc` 0 错、`vitest` 全绿；
- `SPEC-总账.md` 新增 §MC 段，每条 ✅ 都能追到 probe 与证据文件；
- 回滚演练：`git revert` 任一里程碑，回归门仍绿（证明没有隐性耦合）。

**风险**：把「未验证」写成「已达标」。缓解：M10 只认退出码与 JSON，不认口头结论。

### 12.2.1 里程碑失败模式与止损点

每个里程碑都要提前写「怎么算失败、失败了砍什么」，否则超期时只会加人硬堆。

| 里程碑 | 失败信号 | 止损动作（砍什么，保什么） |
|---|---|---|
| M0 | 同一构建三次读数极差 >20% | 先修探针，不进 M1；宁可晚一周，不可带着噪声基线开工 |
| M1 | 1 万方块让载入增量 >50ms（目标 +10ms），或 `callsMax` +>8 | 规模砍到 2 千，先修 mesher 与 BatchedMesh，不扩功能 |
| M2 | 进出沙盒 `geometries` 不回基线，或队列排空 >1s | 退回 1 万方块静态沙盒，流式延期；不许「泄漏但先上」 |
| M3 | 配方系统与 `itemKit.ts` 物品 id 冲突 | 只做 8 条核心配方，全部复用现有 id，不另起命名 |
| M4 | 结构完整性退化成逐块物理 | 砍到「悬挑 >8m 无支撑必塌」一条离散规则，不做刚体 |
| M5 | 生存数值影响现有三界漫游 | 默认关闭，只在天宫/地府启用；人间保持现状 |
| M6 | 洞穴挖穿现有建筑地基/河道 | 洞穴限定在沙盒范围内，不碰三界；传送门单独验收 |
| M7 | actor 数膨胀，`liveCount` 失控 | 生物硬上限 200，对象池复用，超限不生成 |
| M8 | 战斗手感无法机检、只能靠主观 | 只验公式与边界；平衡交试玩，不假装断言能证明「好玩」 |
| M9 | lockstep 逐 tick 分叉且定位不到 | 降级为「单机存档确定性」，多人延期；不许把分叉当噪声 |
| M10 | 矩阵仍有 ⬜ 或 ✅ 缺证据 | 不发布正式版，只出 RC；⬜ 不许用「待验证」蒙混成 ✅ |

止损点的作用是**把「要不要继续」变成事先决定的事**。等到超期再讨论，讨论的就不是技术，是沉没成本。

矩阵的读法：

- **不是所有行都必须 ✅ 才能发布**。V1–V10 的玩法行允许 🟡（已实现未验收），但 V11 的回归门与 V12 的证据门必须 ✅。理由：玩法可以慢慢打磨，性能与证据一旦破了，后面所有结论都不可信。
- **⬜ 与 🔴 要分开**。⬜ 是「探针还没写」，🔴 是「探针写了但没实现/没达标」。把 ⬜ 混进 🔴 会掩盖「我们连测都还没测」这件事。
- **每行的阈值必须是数字或可判定的布尔**。「体验流畅」不许进矩阵。

### 12.3.1 空白怎么补：⬜ 的消解顺序

矩阵里有 **17 行标 ⬜**，对应 **17 个矩阵内待建 probe**；另有 2 个不在矩阵里的探针（`probe-voxel-mesh`、`probe-voxel-stream`），合计 **19 个待建 probe**。⬜ 不是「以后再说」，它必须按固定顺序消解，否则会出现「功能做完了才发现没法测」。

**顺序原则：先测能定生死的，再测算数值的，最后测好不好玩。**

1. **第一批（M0 内，6 个）**——`probe-matrix`、`probe-ledger`、`probe-voxel-mem`、`probe-voxel-edit`、`probe-voxel-mesh`、`probe-voxel-stream`。它们决定「体素能不能做」，必须先有。
2. **第二批（M1–M2，2 个）**——`probe-voxel-bounds`、`probe-voxel-material`（`probe-voxel-edit` 已在第一批）。它们是体素的地基，地基测不了，上面全是空中楼阁。
3. **第三批（M3–M7，5 个）**——`probe-craft`、`probe-build`、`probe-survival`、`probe-explore`、`probe-mobs`，覆盖 10 行断言。每条在对应里程碑的第一天写，不是最后一天补。
4. **第四批（M8–M9，4 个）**——`probe-combat`、`probe-save`、`probe-seed`、`probe-lockstep`，覆盖 5 行断言。lockstep 的探针必须早于实现，否则分叉了都不知道从哪一 tick 开始。
5. **收尾（M10，2 个）**——`probe-realm`、`probe-pillars`，对应 V1 的两条总纲断言；它们依赖前面所有系统，放在最后验收。

**每条探针的最低规格**（缺一条不算写完）：

- 输出 `PASS`/`BLOCK` + 退出码 0/1；
- `--self-test` 用合成数据跑正样本与负样本，负样本必须 BLOCK；
- `--json` 输出机器可读结果，字段名与总账证据列对齐；
- 失败时打印「期望值 / 实测值 / 取样点」，不只打印「FAIL」。

**成本**：19 条 × 0.5–1 人日 ≈ 10–19 人日。这笔钱已经摊进各里程碑的「人日」里（每个里程碑的退出判据都含自己的探针），但 M0 的 3 人日装 6 条偏紧，实际可能多 3–4 人日。这部分计入 ±40% 的估算误差，不单独加账。**不许因为「探针不算功能」就不给人日**——过去几轮「探针口径错」的返工，成本都高于写探针本身。

### 12.4.1 三个致命风险的证伪实验

风险登记最怕写成「许愿池」——列了、缓解了、没人验证缓解是否有效。所以 R02/R03/R05 各配一个**最小证伪实验**，在 M1 第一周就跑，跑完再决定要不要继续投功能。

**R02（draw call 负预算）**

- 假设：1 万方块沙盒用 BatchedMesh 后，`callsMax` 增量 ≤8。
- 实验：固定六机位，分别跑 `?vox=0` 与 `?vox=1`，各 1.5s，记录 max。
- 判据：`Δcalls ≤8` 则风险降级；`Δcalls >16` 则确认，M1 必须先做静态合批优化，不许先做玩法。
- 成本：2 人日（含 BatchedMesh 最小接线）。

**R03（峰值堆破 3GB）**

- 假设：1 万方块让 `heapPeak` 增量 ≤128MB、绝对值 <2.9GB。
- 实验：`probe-voxel-mem.mjs` 跑三次，feature on/off 对照；再跑一次 5 万方块，看增长是否线性。
- 判据：1 万档增量 ≤128MB 且 5 万档 ≤256MB 则风险可控；否则规模上限直接砍到 2 万，不讨论「再优化一下」。
- 成本：1 人日。

**R05（破坏后合批失效）**

- 假设：连续 100 次破坏，`frameP95 ≤25ms`、`max ≤50ms`。
- 实验：脚本在固定机位对同一面墙连续挖 100 块，每块间隔 30ms，记录 `engine.frameMs` 环形缓冲。
- 判据：`p95 >25ms` 或 `max >50ms` 即确认；先查是不是「一次编辑触发整块 64³ 重合并」，再决定退 16³ 还是改 BatchedMesh 粒度。
- 成本：2 人日。

三个实验加起来 5 人日，占 M1 的 42%。**这笔钱不能省**：如果 R02/R03/R05 任一确认，M1 的方案就要改，越晚发现越贵。先花 5 天证伪，比花 12 天做完再推翻便宜。

## 12.5 与 `artifacts/SPEC-总账.md` 的关系

### 12.5.1 总账是唯一真相源，V12 不另建账

`SPEC-总账.md` 已经有 100KB、1335 行、52 项 ✅ / 10 项 🟡。V12 的矩阵**不复制**这些条目，只新增一个 §MC 段，按里程碑挂 10–12 行汇总，明细留在本卷。这样总账不会从 100KB 涨到 150KB，也不会出现「两处都写了、两处不一致」。

### 12.5.2 新增项的登记格式

每条新增项在总账里占一行，**六列缺一不可**：

```
| MC-M1-03 | 破坏后邻面补全 | 🟡 | probe-voxel-edit.mjs · exit 0 · 2026-11-10 · build v95 | 洞边缘缺面数 = 0 | — |
```

- **ID**：`MC-<里程碑>-<序号>`，全局唯一，不复用。
- **断言**：一句话，含数字或布尔判据。
- **状态**：四档，不许自创第五档。
- **证据**：`probe 文件 · 退出码 · 日期 · 构建号`。缺任何一项，状态最高只能是 🟡。
- **阈值**：数字 + 口径（几次中位数、哪个字段）。
- **口径**：性能断言填 12.5.4 的枚举值；功能断言填 `—`，不许留空。

### 12.5.3 「每条都有 probe 证据」的四条机检规则

1. **✅ 行必须有 probe**：`probe-ledger.mjs` 解析总账，凡状态为 ✅ 且证据列不含 `.mjs` 的行，判 BLOCK。
2. **probe 文件必须存在**：证据里的路径 `fs.existsSync` 必须为真，否则 BLOCK。历史上有过「引用了不存在的探针」。
3. **probe 必须能自证**：每个 probe 跑 `--self-test`，负样本必须 BLOCK；自证失败则其名下所有 ✅ 降级为 🟡。
4. **证据必须新鲜**：✅ 行的日期与当前构建号必须匹配最近一次出包；超过两个构建号未复跑，自动降 🟡。这条防的是「三个月前绿过一次，之后再没跑」。

### 12.5.4 口径列必须写

总账现有表没有「口径」列，导致 13.35M 与 15.09M、1.83GB 与 2.62GB 被混着引用。§MC 段新增第六列「口径」，取值限定为：

- `staticTris`（`assetAudit` 分组合计，三次中位数）
- `callsMax`（六机位逐帧 max）
- `heapPeak`（40ms 采样序列最大值）
- `heapEnd`（载入结束瞬时值）
- `loadMedian`（`navToEngine + engine`，三次中位数）
- `frameP95`（固定机位，硬件光栅）

**同一行不许混两个口径。** 要同时报两个，就拆两行。

### 12.5.5 状态推进的纪律

```
🔴 未实现 → 🟡 已实现未验收 → ✅ 已验证
                  ↘ ⚠️ 做偏了（实现与断言不符，必须写清差在哪）
```

- 从 🔴 到 🟡 需要：代码存在 + probe 能跑 + 至少一次非 BLOCK。
- 从 🟡 到 ✅ 需要：三次中位数达标 + 证据四要素齐全 + 回归门未红。
- ✅ 可以被降级：回归门红了、probe 自证失败、证据过期，任一发生即降 🟡 并写明原因。
- **不许「因为载入达标了，所以静态面也标绿」**——总账里已经发生过一次这种「顺带标绿」，被专门写了覆盖说明纠正。

### 12.5.6 出包时的总账动作

每次出包追加一个「基线块」，不覆盖历史：

```
## 2026-11-10 · release-v95
- staticTris 13,xxx,xxx（3-run median）
- loadMedian 8,xxx ms（nav 3xx + engine 8,xxx）
- callsMax 5xx（六机位）
- heapPeak 2,xxx MB / heapEnd 1,xxx MB
- MC 段：✅ x / 🟡 y / 🔴 z
```

这样任何一次「是不是退化了」都能拿两个基线块直接比，不用翻聊天记录。

### 12.5.7 一个坏行与一个好行的对照

坏行（总账里真实出现过这类）：

```
| 1.1 | 启动四段式 | ✅ | 已优化 | — |
```

它的问题不是「写得不详细」，是**四个要素全缺**：没有 probe 文件、没有退出码、没有日期、没有构建号。半年后有人问「这个 ✅ 是哪次测的」，只能翻聊天记录；翻不到，它就从「已验证」退化成「某人说行」。更糟的是它把「载入达标」写成了整条 ✅，而同一行的静态面与峰值堆其实是红的——这就是「顺带标绿」。

好行：

```
| MC-M1-03 | 破坏后邻面补全 | ✅ | probe-voxel-edit.mjs · exit 0 · 2026-11-10 · build v95 | 洞边缘缺面数 = 0（100 次破坏，3 次中位数） | staticTris 口径 |
```

差别在可复现性：任何人拿 `build v95` + `probe-voxel-edit.mjs` 就能重跑，得到同一个 0 或非 0。**「✅」不是评价，是一个可以被推翻的断言。**

半好半坏的行（probe 有、日期没有）只能算 🟡。这不是苛刻：没有日期的证据无法判断是「这次构建」还是「三个月前」；而性能是会漂的，三个月前的绿对今天没有意义。

## 12.6 不做清单

还要写清「不做的代价」，否则这张表会变成「砍需求」的借口：

- 不做无限世界 ⇒ 沙盒边界可见。缓解：边界用山体、雾、城墙收口，让「走不出去」看起来是世界的一部分，而不是一堵空气墙。
- 不做完整红石 ⇒ 创造性建造的上限变低。缓解：把玩法支柱放在探索/生存/建造的**空间组合**上，而不是电路逻辑；三种离散联动足够做门、灯、陷阱。
- 不做公网多人 ⇒ 没有「服务器」叙事。缓解：本地双人 lockstep 已经能证明确定性；宣传上不说「多人联机」，只说「双人同屏/同机」。
- 不做移动端 ⇒ 少一个平台。这是明确取舍，不是遗漏；如果哪天要做，必须重做一套低模资产，不能拿现在这套 13.35M 直接压。

**「不做」的真正含义是「现在不做，且不为它预留复杂度」。** 最坏的情况是嘴上说不做、代码里却为它留了一堆抽象层——那既没省成本，又增加了维护面。

## 12.8 交付节奏

按 171 人日、单工程师算，约 **8.5 个月**；按 3 人并行（1 人引擎/性能、1 人玩法、1 人内容/验收），日历约 **3–3.5 个月**，但人日不变。并行的前提是文件所有权互斥——本项目已经有过「多 agent 并发改同一文件导致 vite 整页重载、`__qingming` 被清空」的教训。

建议节奏：

- **第 1 个月**：M0 + M1。这两个做完，才有资格谈后面；做不完说明体素方案在本地就不成立，及时止损。
- **第 2 个月**：M2 + M3。流式与采矿是「沙盒是否像一个世界」的分水岭。
- **第 3 个月**：M4 + M5 + M6。建造、生存、探索三条玩法线可以并行，但共用 `voxel/store.ts`，需要一个人守接口。
- **第 4 个月**：M7 + M8 + M9 + M10。生物、战斗、多人、验收。M9 的 lockstep 风险最高，应尽早启动而不是压到最后。

每个月的月末必须有一次「可出包」的构建，哪怕功能不全。**没有可出包的构建，就没有真实的性能数字；没有真实数字，路线图就是猜。**

人力假设要写清，否则「3 人 3 个月」会被当成承诺：

- **171 人日是工程人日，不含美术资产**。V3 的方块纹理、V8 的生物造型、V9 的武器护甲，若要走「宋代考据 + 手绘」路线，至少再加 20–30%，且这部分很难并行压缩。
- **3 人并行需要 1 名接口守门人**。`voxel/store.ts`、`voxel/palette.ts`、`src/world.ts` 的改动必须串行评审，否则会出现「三个人同时改 store，合并时互相覆盖」。本项目已经有过并发改同一文件导致页面重载、全局对象被清空的教训。
- **评审与返工按 20% 计**。每个里程碑的退出判据要跑一遍全套探针，红了要修；20% 是保守估计，不是余量。
- **估算误差 ±40%**。这不是免责声明，是提醒：M1 若从 12 人日变成 17 人日，属于正常区间；若变成 25 人日，触发 R14，按止损点缩范围。

## 12.10 本路线图不保证什么

写清楚「不保证」，比写「保证」更能防止误读：

- **不保证好玩。** 里程碑只能保证「机制存在、可机检、不破性能」，不能保证「挖矿 30 分钟不腻」。好玩要靠试玩与迭代，断言测不出来。
- **不保证移动端。** 所有数字只对桌面独显负责；集显/移动端需要另一套资产与预算，不在 171 人日里。
- **不保证与 V1–V10 的每一句设计一致。** 那十卷尚未定稿；本卷的矩阵是「最低可执行集」，它们定稿后可能加条目，但不能减。
- **不保证 171 人日。** 这是估算，±40%；真正的承诺是「每个里程碑独立出包、失败可止损」，不是日期。
- **不保证「一个实例都不删」在体素沙盒内也成立。** 沙盒是新增内容，不涉及删除现有实例；但如果未来要把沙盒嵌入现有街区，必须先过 V11 §11.6 的四道约束。

## 12.11 结论

1. **路线图按「局部沙盒」排，不给全量体素化留位置。** 这不是技术保守，是 V11 §11.6 的四道约束（不删实例、13.5M 静态面、600 draw call、1.5GB 峰值堆）逐条算出来的结果。
2. **M1 是 go/no-go 门。** 1 万方块做不到「载入 +10ms、常驻 ≤8MB、峰值 ≤16MB、draw call +1」，后面的 5 万、50 万都不必谈。
3. **验收的门槛是「可复现」，不是「看起来行」。** 三次中位数、固定机位、probe 自证、证据四要素——这四条比任何一条功能断言都重要，因为它们决定后面所有结论可不可信。
4. **不做的清单和要做的清单一样重要。** 每砍掉一个「无限世界/完整红石/公网多人」，就多出 20–40 人日给真正能形成闭环的机制。
5. **最大的风险不是技术，是「用单点读数宣布达标」。** 本项目已经因此误判过四次；V12 的 B3 与 R12 就是专门为它设的闸。

6. **先做 M1 而不是先做玩法，是因为玩法不能证明地基。** 采矿、建造、生存都可以做得像模像样，但如果 1 万方块就让 draw call 或峰值堆爆掉，那些玩法最终要推倒重来。M1 只用 12 人日就能回答「地基能不能站住」，比先花 60 人日做三条玩法线再发现地基是沙子便宜得多。

7. **证据门优先于功能门，是因为假绿的代价高于缺功能。** 缺功能是「少玩了什么」，假绿是「以为能玩、其实不能」。后者会让后续每一个决策都建立在错误前提上——项目历史上「载入达标就连带把静态面标绿」就是例子，纠正它花的时间远超当初多写一行证据。

8. **路线图的可执行性不在日期，在止损点。** 171 人日会漂，±40% 就是 ±68 人日；但「M1 做不到 +10ms/+2MB/+1call 就砍到 2 千块」不会漂。把不可控的日期换成可控的止损条件，是这份路线图唯一真正的承诺。

9. **V11 是预算，V12 是花法。** 两卷必须一起读：只看 V11 会得出「什么都别做」，只看 V12 会得出「什么都能做」。合起来才是「在这些红线内，先做哪一小块，做完凭什么算完」。
