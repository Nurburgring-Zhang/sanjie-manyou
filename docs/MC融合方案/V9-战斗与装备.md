## 1. 战斗基础：帧、判定、状态

### 1.1 时间基准：60Hz 固定逻辑帧

现引擎是可变步长：`src/core/engine.ts:752` 每帧 `dt = Math.min(0.1, max(0, (now-last)/1000))`，直接传给 `world.update(t, dt)`。这带来两个后果：① 同一招式在 30fps 与 144fps 下判定次数不同；② 无法回放、无法联机对账。V9 引入固定步：

```
SIM_HZ = 60
SIM_DT = 1 / 60            // 16.6667ms
MAX_CATCHUP = 4            // 单帧最多补 4 步，超出丢弃（防死亡螺旋）
```

`Engine.start()` 改为累加器：`acc += dt; while (acc >= SIM_DT && n++ < MAX_CATCHUP) { world.stepFixed(); acc -= SIM_DT; }`，渲染时用 `alpha = acc / SIM_DT` 在前后两个逻辑状态间插值。**代价**：多 1 帧输入延迟（16.7ms），或接受插值带来的 0.5 帧视觉滞后；二者选一，不可同时为零。

帧号约定：`f = tick % 60`，1 秒 = 60 帧。下文所有「帧」均指 60Hz 逻辑帧；括号内给毫秒。

### 1.2 近战判定：胶囊扫掠，不是点球

现有 `playerAttack` 是「以玩家为心、2.4m 球、前向 70° 锥」的一次性判定。它有三个毛病：快速挥砍会穿透（一帧跨过目标）、长兵器打不到该有的距离、无法表达「剑尖 vs 剑身」的伤害差。V9 改为**扫掠胶囊**：

- 兵器用一条**线段**表示：`grip`（握把）到 `tip`（尖端），长度 `L`，半径 `r`。
- 目标用**胶囊**表示：脚下点 `p0` 到头顶点 `p1`，半径 `R`。
- 判定 = 线段到线段的最短距离 `d`，若 `d ≤ r + R` 则命中。
- 每个 active 帧取 **3 个子步**（`sub = 0, 1/3, 2/3`），用上一帧与当前帧的兵器端点线性插值，得到 3 条扫掠线段。

线段-线段最短距离用 Ericson《Real-Time Collision Detection》§5.1.9 的 `segSegDist2`，纯 `+ - * /`，不用 `Math.hypot`（跨引擎实现有差异，见 V10）。伪代码：

```
function sweepHit(prevGrip, prevTip, grip, tip, hurt): boolean {
  for (let s = 0; s <= 2; s++) {
    const k = s / 2;
    const a = lerp(prevGrip, grip, k), b = lerp(prevTip, tip, k);
    if (segSegDist2(a, b, hurt.p0, hurt.p1) <= (weapon.r + hurt.r) ** 2) return true;
  }
  return false;
}
```

**为什么 3 个子步够**：剑尖最快线速度按 30m/s 估，60Hz 下单帧位移 0.5m；3 子步后相邻采样间隔 0.167m，小于玩家受击胶囊半径 0.36m，不会穿透。枪类尖端速度上限 22m/s，间隔 0.122m，同样安全。若未来加「突进刺」到 50m/s，子步要提到 5。

**各兵器判定形状**（与 §2 武器表一一对应）：

| 类 | 形状 | 半径 r | 长度 L | 说明 |
|---|---|---|---|---|
| 剑 | 胶囊 | 0.12m | 0.95–1.10m | 中段与尖端同伤；尖端 +10% |
| 刀 | 胶囊 | 0.14m | 0.90–1.05m | 前 1/3 段 +15%，符合「劈砍在刃前」 |
| 枪 | 胶囊 | 0.09m | 2.40–3.20m | 只有尖端 0.6m 有伤害，枪杆无伤 |

| 弓 | 抛射体 | 0.04m | — | 初速 38–62m/s，重力 9.8，每帧线段扫掠 |

### 1.3 命中盒（Hurtbox）

每个角色挂 2–4 个胶囊，按 `Actor.scale` 缩放。玩家（scale≈1.0）：

| 部位 | 胶囊 | 半径 | 伤害倍率 | 备注 |
|---|---|---|---|---|
| 躯干 | y 0.55→1.35 | 0.34m | 1.0× | 主判定 |
| 头 | 球心 y 1.58 | 0.22m | 1.5×（暴击） | 仅精确命中 |
| 腿 | y 0.05→0.55 | 0.26m | 0.75× | 扫腿/低姿 |
| 全身兜底 | y 0.10→1.65 | 0.36m | 0.9× | 防漏判，不与前三叠加 |

Boss 用多胶囊：巨灵神（4.1m）分「左腿/右腿/躯干/头/持斧手」五段，弱点在**右腋下**（`y 2.9m`，半径 0.45m，2.0×）。命中盒数据不放几何里，放 `src/data/hurtboxes.ts`，按 `code` 索引；`Actor` 只加一个 `hurtId` 字段。

**与现有代码的冲突**：`Actor` 没有骨骼，`writeActor` 只写实例矩阵（`src/actors/crowd.ts:741`）。因此命中盒**不能跟随动画**，只能跟随 `pos + yaw + scale` 的刚体变换。视觉上会有「手还没抬到位、判定已生效」的 1–3 帧误差。代价：每个招式必须把前摇留足（≥6 帧），靠前摇而不是靠骨骼对齐来让玩家读懂。

### 1.4 无敌帧（i-frame）与闪避

新增 `dodge`：`KeyShift + 方向` 或右键，消耗 25 体力，位移 4.2m，总时长 30 帧（500ms）。帧结构：

| 段 | 帧 | 行为 |
|---|---|---|
| 起手 | 0–3（0–50ms） | **无 i-frame**，可被打断 |
| 无敌 | 4–21（67–350ms） | 全身 i-frame；可穿过普通敌人，不可穿 Boss |
| 收招 | 22–29（367–483ms） | **无 i-frame**，可被惩罚 |

其他无敌窗口：

| 来源 | 帧 | 毫秒 | 备注 |
|---|---|---|---|
| 闪避 | 18f | 300ms | 见上表 |
| 后跳 | 11f | 183ms | 位移 2.4m，体力 15 |
| 受击后 | 30f | 500ms | 防止连击锁死；Boss 连段例外，见下 |
| Boss 阶段转换 | 72f | 1200ms | 只免伤，不免控；给玩家看阶段演出 |
| 复活 | 120f | 2000ms | 与 `respawnDelay: 3` 并存，取长者 |
| 处决动画 | 全程 | — | 双方都免伤，防止第三方抢人头 |

**Boss 连段例外**：Boss 的 `multiHit` 招式（如哪吒三连刺）每段之间只给 12 帧（200ms）受击无敌，而不是 30 帧；否则三连只有第一段有效。这个值写在 `BossMove.hitInvuln` 里，默认 30，三连段覆写为 12。

### 1.5 受击硬直（Hitstun）与削韧（Poise）

新增 `poise`：玩家 60，巨灵神 240，天兵 40，鬼魂 20。每次命中造成 `poiseDamage`，归零则进入 `stagger`，硬直期间受伤 +20%。韧性在脱离战斗 3s 后以 20/s 恢复。

硬直分级（逻辑层，与 `src/actors/actions.ts` 的视觉动作分离）：

| 等级 | 触发 | 逻辑硬直 | 视觉动作 | 可取消 |
|---|---|---|---|---|
| 轻硬直 | 轻击 | 11f（183ms） | `staggerHit` 前 0.18s | 不可 |
| 中硬直 | 重击 | 25f（417ms） | `staggerHit` 前 0.42s | 不可 |
| 大硬直 | 削韧归零 | 36f（600ms） | `staggerHit` 0.6s | 不可 |
| 倒地 | 击倒 | 72f（1200ms） | `knockedDown` 前 1.2s | 起身前 12f 可翻滚取消 |
| 击飞 | 击飞 | 至落地 + 48f | `launched` → `knockedDown` | 落地后 12f 可翻滚 |

**命中停顿（hitstop）**：命中瞬间双方逻辑帧冻结，轻击 2f（33ms）、重击 4f（67ms）、削韧 6f（100ms）。实现上不是 `dt=0`，而是给 `AttackState.hitstopTicks` 计数，期间不推进招式帧但推进 VFX 与相机抖动。

**与现有代码的冲突**：`src/game/physics.ts:80-92` 直接把 `target.impactUntil` 设为 `performance.now()+1200/3500/4000`，`src/actors/actions.ts:618-643` 的 `staggerHit` 是 1.1s、`knockedDown` 是 3.4s。逻辑硬直（0.18–1.2s）比视觉动作短得多，两者必须拆开：`stunTicks` 管能不能动，`actionT` 管动作演到哪。否则玩家会被「已经能动了但看着还在地上」骗。

### 1.6 击退

击退速度：

```
v0 = knockback / (1 + mass / 2)
```

`knockback` 由招式给（轻击 2.5、重击 6、Boss 横扫 14），`mass` 取 `src/game/physics.ts:18` 的 `PhysProfile.mass`（平民 1、军汉 1.1、巨灵神 4、阎罗 1.6）。代入：平民被重击 `6/(1+0.5)=4m/s`，巨灵神被重击 `6/(1+2)=2m/s`。地面摩擦 18m/s²，空中重力 21m/s²（与 `physics.ts:221` 一致），击退在 0.33s 内衰减到 0。

**与力分级的关系**：`ImpactSystem.resolve` 仍按 `F=power*speed+extra` 算 tier，决定「趔趄/击倒/击飞/碎裂」的**表演**；V9 的 HP 伤害走另一条管线 `DamagePipeline`，两条管线共享一次命中事件，但互不替代。理由：现有 tier 对神佛是「无效」（`F<0.8T`），如果直接拿它当伤害，玩家永远打不动 Boss。

### 1.7 输入缓冲与取消窗口

- 输入缓冲 6f（100ms）：在收招最后 6 帧按下的攻击，会在收招结束时立刻接出。
- 轻击可取消到闪避：从 active 第 1 帧起。
- 重击不可取消，只能被 Boss 命中打断。
- 连段：轻-轻-轻 三段，第三段伤害 1.4×、削韧 1.5×；每段之间窗口 18f（300ms），超时回到第一段。

### 1.8 一次命中的完整时序（铁剑轻击 → 天兵）

把上面所有常量串起来，走一遍真实链路，验证每一步都有落点：

| 时刻 | 事件 | 数据 |
|---|---|---|
| tick N | 玩家按 `KeyF`，写入 `inputBuffer` | `{action:'light', tick:N, yaw:1.57}` |
| N+0…6 | 起手 7f | 不能移动、不能转向；`MovesetState='startup'` |
| N+7 | 判定开始 | `active` 4f（N+7…N+10）；`hitbox` 用 N+6 与 N+7 的兵器端点插值 |
| N+8 | 首个命中 | `segSegDist2 ≤ (0.12+0.36)²`；目标 `hurtId='tianbing'` |
| N+8 | 命中停顿 2f | `hitstopTicks=2`；VFX/相机抖动继续 |
| N+8 | 伤害管线 | `raw 11 → 跨界 1.0 → A=40，减免 40/160=25% → 8.25 → round 8` |
| N+8 | 削韧 | `poiseDamage 11`，天兵 poise 40 → 未破韧 |
| N+8 | 硬直 | `stunTicks=11`；`action='staggerHit'` |
| N+8 | 击退 | `v0 = 2.5/(1+1.1/2)=1.61m/s`，摩擦 18 → 0.09s 停下（与命中同帧结算，之后才进 2f 停顿） |
| N+11…24 | 收招 14f | N+21 起可被下一段轻击取消 |
| N+25 | 回到 idle | 总 25f = 417ms；对 A=40 目标 DPS = 8/0.417 ≈ 19.2/s |

**伤害管线的固定顺序**（写在 `damage.ts` 的 `applyDamage()` 里，禁止各处自行调换）：

```
raw → 淬炼/铭刻加成 → 跨界倍率 → 暴击 → 护甲减免 → 固定格挡 → 下限 1 → 扣 HP
```

顺序会改变结果：先暴击后护甲，与先护甲后暴击，在 A=226 时相差 1–2 点。V9 选「先暴击后护甲」，因为玩家对「暴击被护甲吃掉」的感知更差。

### 1.9 与现有 `ImpactSystem` 的接线

`CombatSystem` 每帧产出 `combat:hit` 事件：

```ts
bus.emit('combat:hit', { attackerId, targetId, damage, poiseDamage, tier, point, weaponId });
```

`ImpactSystem` 订阅该事件，只对 **NPC** 调用 `apply(tier, target, dir, force)`，对玩家和 Boss **不再走力分级**（它们的受击由 `stunTicks` 与 `BossBrain` 管）。这样避免「一次命中既扣 HP 又被 `launch()` 抛一次」的双重结算。现有 `physics.ts:120-144` 的 `playerAttack` 保留为「无武器时的徒手攻击」，内部转调 `CombatSystem.lightAttack()`，不再直接改 `impactUntil`。

**八类手感的差异必须落到判定上，而不是只换数值**：

- **剑**：起手 6–7 帧，收招 14–15 帧，允许「轻-轻-闪」；尖端 +10%。
- **刀**：起手 7–10 帧，前 1/3 段 +15%，但收招 11–21 帧，挥空惩罚重。
- **枪**：范围 2.6–3.2m，只有尖端 0.6m 有伤害；被贴身到 1.2m 内伤害 ×0.5（枪杆推）。
- **棍**：两端 0.5m 伤害，中段 0.6×；横扫 `arc` 140°，可同时命中 3 个目标（`maxTargets: 3`）。
- **弓**：蓄力 0.4–1.0s，满蓄 +30% 伤害与穿透；箭矢每帧线段扫掠，重力 9.8。
- **弩**：hitscan，无下坠；装填 0.6–1.6s，装填时不可移动（`moveScale 0.35`）。
- **暗器**：可移动施放，伤害低、削韧低，但**不触发 Boss 的格挡**；对鬼魂 +50%。
- **法器**：伤害吃「灵力」而不是体力；对阴兵/鬼魂 +100%，对凡人 -50%（业力反噬）。

**耐久与修理**：每次命中 -1，重击 -2，箭矢/暗器每次 -1。耐久归零不消失，变成「钝器」：伤害 ×0.4、攻速 ×0.8，提示「去铁匠铺修」。这个设计让「耐久」成为经济压力而不是惩罚性销毁。

这里要修正一个会算爆的数：若按 1 文/点修理，铁剑 220 耐久 = 220 文，是售价 80 文的 2.75 倍，玩家修一次不如买新的。V9 改为 **0.3 文/点（向上取整）**：铁剑满修 66 文、偃月刀满修 156 文、金箍棒满修 210 文。修理费约为售价的 40%–80%，「修」和「换」才构成真实选择。

## 3. 护甲与附魔

### 3.1 四槽与总护甲

槽位：头 `head`、身 `body`、手 `hands`、足 `feet`。总护甲 `A = Σ A_slot × setBonus`，套装 2 件 +5%、4 件 +12%（乘算）。

减伤公式（单一真相源，落在 `src/game/combat/damage.ts`）：

```
A_eff = max(0, A - penetration)
mitigation = A_eff / (A_eff + 120)        // 0→0%，120→50%，360→75%，480→80%
damage = max(1, round(raw × (1 - mitigation) × elementMul × critMul) - flatBlock)
```

选 `K=120` 的理由：现有巨灵神一击 12，玩家穿布衣（A=32）时受伤 `12×(1-32/152)=9.47→9`；穿步人甲（A=124）时 `12×(1-124/244)=5.90→6`；穿锁子黄金甲（A=226）时 `12×(1-226/346)=4.16→4`。三档差距 9/6/4，既让护甲有意义，又不至于「穿了就无敌」。上限 80% 是硬闸，防止叠满后 Boss 打不动。

### 3.2 三套改造体系：符箓 / 淬炼 / 铭刻

原版附魔是「一件装备随机词条」。本项目是宋代三界，改成三套**来源不同、代价不同**的体系：

**① 符箓（消耗品，临时）**
- 来源：上清观画符、地府纸扎铺、Boss 掉落。
- 用法：贴在兵器/护甲上，持续 60s 或 60 次命中，二者先到。
- 特点：可叠 1 层，换符覆盖；**不改变装备本身**，死亡后消失。
- 数值：单符效果约为同档铭刻的 1.6 倍，但有时限。

**② 淬炼（永久，线性）**
- 来源：铁匠铺/兜率宫丹炉。
- 规则：每件装备最多 +5；每级 +2 伤害或 +6 护甲；费用 `40 × (n+1)²` 文。
- 特点：**无随机失败**（避免赌博式挫败），但 +5 后不可再淬，且重量 +1 档（移速再 -2%）。
- 代价：淬炼过的装备不能卖回原价，只能拆成材料（返还 40%）。

**③ 铭刻（永久，条件触发）**
- 来源：Boss 掉落、图鉴达成、地府判官笔。
- 规则：每件装备 1 条铭刻，不可更换，只能覆盖（旧铭刻永久丢失）。
- 特点：**条件触发**，强度高但有前置；同一 Build 最多 3 条同时生效（头/身/武器）。
- 代价：铭刻是不可逆决策，逼玩家做取舍。

### 3.3 三套体系的取舍与三个 Build

三套体系不是「三个附魔槽」，而是三种决策节奏：

| 维度 | 符箓 | 淬炼 | 铭刻 |
|---|---|---|---|
| 生效期 | 60s / 60 击 | 永久 | 永久 |
| 可逆性 | 可覆盖 | 不可逆（+5 封顶） | 不可逆（覆盖即丢失） |
| 强度 | 同档 1.6× | 线性 +2/级 | 条件触发，上限最高 |
| 来源 | 画符/纸扎 | 铁匠/丹炉 | Boss/图鉴 |
| 决策重量 | 轻（战前准备） | 中（资源分配） | 重（Build 定型） |
| 主要成本 | 铜钱 | 铜钱 + 材料 + 重量 | 机会成本 |

三个可算的 Build，用来验算数值不是拍脑袋：

**① 破军剑客**：七星剑（19/34）+ 淬炼精铁 V（+10）+ 铭刻破军（对 Boss +12%）+ 火符（+8）。
轻击对 Boss：`(19+10+8) × 1.12 = 41.4`。巨灵神护甲按 60 算：`41.4 × (1-60/180) = 27.6`；打右腋 1.6× → **44**。320 HP 需 8 次弱点命中。
这个数说明：**弱点倍率不能再用 2.0**。2.0 时 55 伤害、6 次结束，Boss 活不过两个连段。V9 把巨灵神弱点从 2.0 下调到 **1.6**，并把 Boss 护甲从 0 提到 60；两条一起改，才让「打弱点」有意义但不秒杀。

**② 镇魂道士**：桃木剑（8/16）+ 道袍（符箓 +15%）+ 净魂符（对鬼魂 +60%）+ 铭刻业火。
对阴兵：`8 × 2.0（符箓克制）× 1.6（净魂）× 1.15（道袍）= 29.4`；对凡人只有 `8 × 0.6 × 1.15 = 5.5`。
这是一个**场景特化** Build：地府极强、人间极弱。它验证了 §5 的跨界定则真的能改变玩法，而不只是换数字。

**③ 铁壁禁军**：宋军步人甲（A=124）+ 厚背 V（+30）+ 铭刻反震 + 金刚符（+30）。
总 A = 184，对 12 伤害的巨灵神横扫：`12 × (1-184/304) = 4.7 → 5`；反震 15% → 0.75/次。这不是「无敌」：移速 -10%、体力回复 -20%，玩家躲不开连续三连，必须靠站位而不是硬吃。

**淬炼的重量代价**必须写进 UI：每 +2 级重量 +1 档，重甲 +5 后移速再 -10%。否则「无脑淬满」是唯一解，三套体系就退化成一条线。

## 4. Boss 战（7 场）

### 4.1 数据结构：把 `BossSpec` 扩成表驱动

现有 `src/data/boss.ts` 的 `BossSpec` 只有「横扫/抓取」两个写死招式。V9 扩为：

```ts
export interface BossSpecV2 {
  code: string; name: string;
  arena: { center: [number, number, number]; radius: number; floorY: number };
  maxHp: number; poise: number;
  phases: BossPhase[];                  // 至少 2，至多 3
  moves: Record<string, BossMove>;      // 招式表
  weakness: { part: string; mul: number }[];
  drops: { id: string; chance: number }[];
  havocPhase?: string;                  // 对应 havoc 十幕中的哪一幕
}
export interface BossPhase { at: number; name: string; moves: string[]; invuln: number; }
export interface BossMove {
  id: string; telegraph: number; active: number; recovery: number;  // 秒，内部换算帧
  range: number; arc: number; damage: number; poiseDamage: number;
  knockback: number; hitInvuln: number; maxTargets: number;
}
```

旧 `BossSpec` 保留为 `LegacyBossSpec`，`ArenaBoss` 构造时做一次 `legacyToV2()` 适配，保证 `scripts/probe-boss.mjs` 不改也能跑。

### 4.2 七场 Boss

### 4.3 与 `havoc.ts` 的共存规则

`havoc` 是自动演出，Boss 是可打；两者不能同时驱动同一演员。规则：

1. `Havoc` 构造时仍创建 22 天兵 + 5 分身，但 Boss 战期间对应演员 `freeze=true`，由 `ArenaBoss` 接管 `pos/yaw/action`。
2. `Havoc.update` 增加 `if (this.suspended.has(phaseName)) return;`；Boss 战开始时 `havoc.suspend('giant')`，结束时 `resume()`。
3. 若玩家在 Boss 战中离开竞技场 60m，`ArenaBoss` 回到 `idle`，`havoc` 自动恢复该幕。
4. `havoc.hold` 仍保留给探针，语义不变（整场停摆）。

**代价**：`havoc` 的 10 幕循环不再是「唯一真相」，Boss 战会打断它；如果玩家反复进出竞技场，会出现「演出-战斗-演出」的切换抖动。缓解：加 3s 冷却，且 Boss 战期间不推进 `havoc` 的 `pt`。

### 4.4 失败、重开与代价

现有 `ArenaBoss.knockback()` 的代价是「位置清零 + Boss 4%/s 回血」（`src/game/boss.ts:124-150`），没有玩家 HP，所以「失败」只是被弹开。V9 引入 HP 后，必须明确三种难度下的失败规则，否则「打不过」会变成「无限重来」：

| 模式 | 玩家死亡 | Boss HP | 掉落 | 金币 | 适用 |
|---|---|---|---|---|---|
| 剧情（默认） | 回 `recoverPoi`，3s | 保留 | 保留 | 不掉 | 首次通关 |
| 挑战 | 回 `recoverPoi`，3s | 重置 100% | 保留 | 不掉 | 重复挑战 |
| 硬核 | 回 `recoverPoi`，8s | 重置 100% | 保留 | -10% | 成就 |

**重开必须 ≤3s**：`respawnPlayerAt()`（`src/world.ts:1595`）已经能同时移动化身与机位，`player.ts:376-390` 的淡入淡出是 0.45s；V9 只加一个「死亡 → 0.45s 黑屏 → 复活」的序列，不重新载入世界、不重建 Boss。这条与 `artifacts/游戏设计三件套.md:20` 的「≤3 秒」一致。

**失败教学**：死亡面板列出「本次伤害来源 Top 3」（招式名 + 次数 + 总伤害），数据来自 `combat:hit` 事件缓存（最近 60s，环形 120 条）。这不是装饰：它直接告诉玩家「你吃了 4 次横扫」，比任何文案都有效。

**Boss 战的存档点**：进入竞技场时写一次 `save.autosave`（V10 的 `slot.autosave`），记录 `bossCode/phase/hp`；玩家死亡读档回竞技场入口，Boss 状态按上表处理。**不写**「战斗中每帧存档」，那会让存档 IO 进入战斗循环。

## 5. 战斗与三界差异

| 维度 | 人间（y≈0） | 天宫（y≈2150） | 地府（y≈−260） |
|---|---|---|---|
| 移动 | 步行 3.6 / 跑 8.2 m/s（`player.ts:33-34`） | 可飞，`realmY` 钉高（`player.ts:338`），无重力 | 步行，阴气拖慢 10% |
| 战斗平面 | 2D 地面 + 跳跃 7.5m/s | 3D 球面，可上下夹击 | 2D 地面 + 桥面多层 |
| 主伤害类型 | 物理（刀/枪/棍/弓/弩） | 仙术（雷/火/光） | 阴气（业火/诅咒） |
| 玩家资源 | 体力 | 灵力（代替体力） | 阳气（持续流失） |
| 敌人 | 市井泼皮、军汉、禁军 | 天兵、雷部、神将 | 阴兵、鬼差、亡魂 |
| 死亡代价 | 官府牢房 + 罚金 | 坠回人间，HP 10% | 轮回，业力清零 |
| 特殊规则 | 通缉度 0–5 | 云台边界坠落 | 业力 -100..+100 |

**人间·市井械斗**：不刷「怪物」，刷「人」。在街面拔刀（武器耐久 >0 且 `wanted` 上升）会触发：
- 围观人群 `crowd` 四散（复用 `behaviors.ts` 的避让网格，半径 8m）；
- 更夫/军汉在 8s 内到达，`profileOf` 的 `军汉` 参数（`physics.ts:30`）直接复用；
- 车辆冲撞仍走 `ImpactSystem.vehicleSweep`（`physics.ts:147`），但新增「被马车撞到会掉武器耐久 10%」；
- 通缉度 5 时禁军出场，带弩，伤害 14；躲进寺庙/茶坊 30s 可降 1 级。

**天宫·神通与飞天**：新增 `shenTong` 资源（3 格，60s 回 1 格）：
- 筋斗云：向前冲刺 40m，0.6s 无敌，可穿云台边界但不穿建筑；
- 七十二变：变身为最近见过的 NPC，脱战 8s，期间不能攻击；
- 毫毛分身：召 3 个分身，各 30 HP，继承 50% 伤害，持续 12s。
- 飞天战斗：`realmY` 钉高改为「自由高度 + 悬停」，按 `Space/Ctrl` 升降；空战判定用 3D 胶囊，不投影到地面。
- **冲突**：现有 `player.ts:338` 在异界把 `p.y = realmY` 钉死，无法空战。需要把 `realmY` 改成 `realmFloor`（下限）+ `flyY`（当前高度），并让 `groundHeight` 在天宫返回平台高度而不是 `-Infinity`。

**地府·业力与阴兵**：
- `yang`（阳气）100，离开命名 POI 后 1/s 流失；归零后每秒掉 2 HP，直到回 POI 或喝孟婆汤。
- `karma`（业力）-100..+100：杀阴兵 +2，杀鬼差 +5，超度亡魂 -3；业力 >50 时阎罗王伤害 +20%，< -50 时鬼魂不主动攻击。
- 阴兵：物理伤害 ×0.25，符箓/法器 ×2.0；必须带符箓或法器才能有效清怪。
- 生死簿：Boss 战中显示敌方 HP/弱点，但每看一次 +5 业力。

**跨界定则**（落 `damage.ts` 的 `realmMul`）：

| 攻击类型 \ 目标 | 凡人 | 天兵/神将 | 阴兵/鬼魂 |
|---|---|---|---|
| 物理 | 1.0 | 0.6 | 0.25 |
| 仙术 | 0.8 | 1.0 | 1.2 |
| 阴气 | 0.5 | 0.4 | 0.8 |
| 符箓/法器 | 0.6 | 0.9 | 2.0 |

这张表是 V9 三界差异的**唯一数值出口**；所有「天宫打不动鬼、地府物理无效」的叙事都从这张表来，不另写 if-else。

### 5.1 人间通缉度：把「市井械斗」变成可执行规则

人间不能只刷怪，要刷「官府反应」。`wanted` 0–5 存在 `player` 状态里，规则如下：

| 等级 | 触发行为 | 响应 | 响应时间 | 衰减 |
|---|---|---|---|---|
| 0 | 无 | 无 | — | — |

## 9. 未决与待验证

- **Boss 体型**：4.1m vs 设计文档 9m，需产品决策；本卷按 4.1m 写。
- **7 场 Boss 的场地**：除巨灵神（将台）外，其余 6 场的精确坐标需在 `realm.ts` 的 `SkyCenters` 与 `UNDER` 上二次实测，本卷只给锚点（arenaN/E/S、palaceFront、阎罗殿心），未逐点跑 `probe-ground`。
- **法器对凡人的 -50%**：与「法器是高级武器」的直觉冲突，需 playtest 确认是否改为「对凡人 0.8×」。
- **铭刻「续命」**：致死留 1 HP 在 Boss 多段攻击下可能连续触发，需加 120s 冷却（表中已写），但冷却是否跨场景保留待定。
- **耐久损耗速度**：按 34 把武器、每场 Boss 约 30 击估算，铁剑 220 耐久约 7 场；是否符合经济节奏待实测。
- **天宫空战的相机**：现有第三人称相机 `camPitch` 上限 ±85°（`engine.ts:22`），空战俯冲时可能看不到脚下，需单独设计锁定/自由视角切换。
