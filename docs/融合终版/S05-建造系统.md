# S05 · 建造系统（融合终版）

> 素材：V5《建造系统》× D3§建造 × 代码实测（**建造零实现，既有为预制摆放 props/interactProps**）。

## ① 代码现状（实测锚）

**建造为零。** `src/` 无蓝图/脚手架/撤销栈/结构完整性代码；玩家侧「放置」只有预制件摆放（props / interactProps 注册路径）与 61+1 个交互点消费。可复用边界五条（V5 §0 实读，行号按当前树核）：`Baker` 14 组累积 + `flush`（`src/city/bake.ts:677/:1297`）运行时不能反复 flush；`push` 有 30km 越界守卫拒收计入 `rejected`（NaN 参数会静默丢件）；静态面 13.35–15.09M 超红线（新预算独立立账）；屋面曲线唯一真相源 `roofProfile=(1−t)^1.35`（`bake.ts:266`）；可行走面 `ensureWalkSurface()` 一次性构建 4m 空间哈希、台阶参数 `WS_STEP_UP=0.95 / WS_STEP_DOWN=1.05`（`src/actors/behaviors.ts:89-90/:146`），**新建/拆除必须局部失效重建对应哈希格**，否则人穿墙或悬空。交互判距 `distanceToSquared` 三维判（`src/game/interact.ts:273`）；锚点必须带 realm 与 y（`world.ts` 把 POI 注册在固定标高，同名 x/z 不同界是两个点）。开间模数既有事实：`buildings.ts:959` `baysOf` 开间步长写死 3.2m。

## ② V 系设计要点（V5 卷）

网格 **0.32m=1 宋尺**（考古 31.2–31.4cm 取整为整除；由 `baysOf` 的 3.2m 步长反逼出来：3.2m=10 尺整，「一间十尺」成立；`ROOF_RIB_PITCH=0.34` 是显示值与结构模数不互算）。整数格坐标 `BuildGrid`（cellKey 打包哈希）保证撤销栈可哈希、蓝图可去重；旋转只允许 0/1/2/3 四正交朝向。**中式营造规则（本卷核心）**：材分制把「份」做成整数；开间模数表；进深与架数；举折直接复用 `roofProfile`（不许另造曲线，否则脊与瓦面脱开）；生起；侧脚；斗栱层高；瓦垄走向；三开间厅堂完整算例；约束表可表驱动。结构完整性：荷载、梁抗弯、悬挑、柱与榫卯、塌落模型、墙体开洞、损伤累积（橙区可建有后果）。蓝图系统：数据格式、校验四层、哈希、**离线烘焙**（headless page 调 `bakeBlueprint(json)` 返回顶点/索引/材质组写入 `src/data/blueprints/<id>.bin`）、分享与不可信蓝图（走 ADR-5 沙箱）。机关系统（红石等价物）：信号模型是「气」、十二种基础元件、五个组合示例。撤销栈语义边界：玩家建造必须有独立面预算，不并静态账。

## ③ D 系设计要点（D3 §2/§3/§4）

D3 §2 建造=**构件制**：0.32m 理由同 V5（引用既有代码反逼）；网格与开间（模数表对齐 `buildings.ts`）；**结构完整性只做三条几何判据，不做刚体**（支撑连通/悬挑比/落地柱，物理引擎不进建造）；构件数据结构；**构件与体素分工断言**（建筑包围盒内体素占比 0、体素域内建筑构件占比 0，双向机检）；十五种构件面数台账。§3 三级格网 0.32/0.5/8.0：**1.6m 不是公倍数（LCM=8.0m）**，灰缝 [3,3,4,3,3] 吸收量化残差，灰缝是量化残差不是砌筑缝；三开间殿落体素台基完整算例；三种冲突情形的判定序。§4 预算：口径按暴露面不按方块数；容量契约 9,000 合并 quad + greedy ≥6.7×；三档预算表（面数/内存/draw 全带 T 口径）；探针与 Δ 账（ADR-7：先算 Δ 再谈）。

**V5 中式营造细则补充（本卷核心）**：材分制把「份」做成整数后，开间模数表、进深与架数、举折（直接复用 `roofProfile(t)=(1−t)^1.35`，不许另造曲线）、生起、侧脚、斗栱层高、瓦垄走向逐条成表；§2.9 给三开间厅堂完整算例；§2.10 汇总的约束表可直接表驱动进校验器。结构完整性一节（V5 §3）含荷载、梁抗弯、悬挑、柱与榫卯、塌落模型、墙体开洞、损伤累积（让「橙区可建」有后果）——本层按 D3 判据裁剪为三条几何判据后，V5 的荷载/抗弯账转为**校验器参数来源**（悬挑比、跨度的具体阈值取自 V5 算例，不再另定）。蓝图四层校验 + 哈希去重；离线烘焙命令样例（V5 §4.4 原文：headless page 加载 preview → `window.__qingming.world.bakeBlueprint(json)` → 返回顶点/索引/材质组 → 写 `src/data/blueprints/<id>.bin`）；§4.5 分享与不可信蓝图明确走 ADR-5 沙箱（与本层 S11 同一条管线，不许为蓝图开第二条执行通道）。机关系统（§5）：信号模型是「气」，十二种基础元件 + 五个组合示例——本层裁定不做（见裁决 2），但「气」的信号语义保留为 D4 造物 `behavior` 五值的扩展候选记录。

**V5 建造基础补充**：§1.2-1.5 放置/拆除/旋转/替换四操作的语义边界（替换不是先拆后放，不产生两次撤销记录）；网格吸附与半格例外（哪些构件允许半格偏移、哪些一律整格）；批量框选；撤销栈的语义边界（跨系统操作如「放置+消耗材料」必须原子撤销，材料返还与几何回退同帧）。§1.1b 构件到材质组映射表（PartId→BGroup）：玩家可放置构件**全部落在 Baker 已有 14 组内**，每加一种新材质就多一次 draw call，12s 载入红线吃不起——这张表是构件库扩容时的硬边界，与 D3 十三组账（S03 裁决 2）互为印证：构件侧按 `BGroup` 直落、体素侧按 13 组配额，两表不得各自漂移。V5 §0 第五条易漏事实在此重申：建造锚点/蓝图原点/重生点**必须带 `realm` 与 `y`**——`InteractSystem.update()` 用 `distanceToSquared` 三维判距而 POI 注册在固定标高，同名 x/z 不同界是两个点，只存 x/z 必错（本条与 S02 的 realmY 解钉互为前提）。

## ④ 冲突裁决

1. **V5 完整物理化结构（荷载/抗弯/塌落）vs D3 三条几何判据不做刚体。** 判给 **D3**：塌落模型需要刚体物理与质量传播，与 74ms 载入余量、p95 红线、确定性门三面相撞，代价不可承受；V5 的损伤累积/橙区思想降级为「三条几何判据 + 损伤状态位」，完整版列为远期未决（不进路线图）。
2. **机关系统（V5「气」十二元件）vs V16 砍法。** V16 Plan A 明砍红石；清单 v3 无对应条目。判给 **不做**（勘误原则 1：清单 v3 唯一胜出）——但 V5 的「信号模型」保留为 D4 造物行为规格（`behavior` 五值）的扩展候选，不排期。
3. **蓝图离线烘焙（V5 headless `bakeBlueprint`）vs D1 运行时只能追加。** 三方一致：蓝图构建属**载入期/安装期**一次性烘焙，产物以数据形态挂 `rt_` 命名注册 LOD；运行时只挂载不烘焙。与 ADR-2/ADR-4 相容，无裁决项。
4. **网格归属：V5 BuildGrid 独立实现 vs D3 三级格网。** 判给 **D3 三级格网**：0.32/0.5/8.0 一套坐标系统吃下构件与体素两侧，避免两套格网换算；V5 的整数格 cellKey 打包方案被 D3 吸收为实现手段。
5. **V5 「撤销栈」vs 现状零实现。** 无分歧：撤销栈进 P1-2/P1-7（失败与挽回：建造可撤销是 P1-7 明文）。
6. **步行面失效。** V5 提局部重建、清单 v3 P0-7 只覆盖 NPC 侧脏区重建。判给**合并进 P0-7 统一地面模型**：AABB 脏区重建 API 同时服务 NPC 落地与玩家建造，避免两套哈希。
