## ① 代码现状（实测锚）

**载入链**：世界生成入口在 `src/world.ts`。种子 `new RNG(20260905)` 在 `src/world.ts:296`；街屋内饰独立子种子 `new RNG(0x5e7a1)` 在 `src/world.ts:371`。tasks 数组声明于 `src/world.ts:303`（卷内旧引 `:284`，行号已漂移，语义不变）。链的时序：`__loadStartAt`（`src/world.ts:716`）→ 循环执行 task、每步 `await baker.flush(scene)`（`src/world.ts:802`）→ 单步超预算 `console.warn`（`src/world.ts:823`，只告警不阻断）→ `await compactStatic()`（`src/world.ts:848`）→ `__loadEndAt`（`src/world.ts:861`）。

**Baker**：`export class Baker` 在 `src/city/bake.ts:677`；14 个材质组 `BGroup` 联合类型在 `bake.ts:4`；`flush` 实现在 `bake.ts:1297`；图元 `b.box/cyl/sphere/roofC` 累积到 14 组各四段量化缓冲。瓦垄显示模数 `ROOF_RIB_PITCH = 0.34`（`bake.ts:239`）；屋面曲线唯一真相源 `roofProfile = (1−t)^1.35`（`bake.ts:266`）；UV 缩放 `scaleGeoUV` 定义在 `bake.ts:386`；带 UV 的组共 10 个（`UV_GROUPS`，`bake.ts:591`）。

**天宫几何变换**：`scaleHeavenGeometry` 定义于 `src/sky/expansion.ts:294`，对 `city_*`/`sky_cloudSheets` 命名网格做 2.2× 变换；`LINGXIAO_ANCHOR.y = LINGXIAO_ANCHOR_PRESCALE.y + HEAVEN_LIFT`（`expansion.ts:335-338`，pre-lift 口径陷阱）；`enlargeLingxiao` 在 `expansion.ts:343`。

**compactStatic**：按 `m.name.startsWith('city_')` 筛选合并（`src/world.ts:735`），把同材质网格并成 ≤48MB 批次。合并后对象身份消失——D1 §1.0 的核心结论「合并之后场景里不再有『某一栋楼』」。

**LOD**：`LodManager` 在 `src/core/engine.ts:150`；档位阈值 `LOD_ENTER = [120, 400, 1200]`（`engine.ts:38`）；`register()` 在 `engine.ts:189`；`isReady` 在 `engine.ts:316`（要求 `mid.size > 0`，空 mid 组永不隐藏——新增分组必须给 far 塞空 Group）。注册调用点在 `src/city/infill.ts`（随建随注册，不是链尾统一注册）。

**主循环**：可变步长 `dt = Math.min(0.1, Math.max(0,(now-last)/1000))`（`src/core/engine.ts:844`）。`ImpactSystem` 有自己的固定物理步 `FIXED_DT = 1/120`、`MAX_SUBSTEPS = 16`（`src/game/physics.ts:61-63`），但引擎主循环未接固定步——player/behaviors 走可变 dt。

**基线数字**（重建纲领 §0，口径必须连名带号）：`T_static` 18,959,342；`T_scene` 19,873,969（536 Mesh / 452 InstancedMesh / 1,011,881 实例）；`T_frame` 45,911,485 / 378 calls；峰值堆 2,615MB（目标 ≤1,536）；`navToEngineMs + engineMs` 11,926ms / 红线 12,000 ⇒ 余量 74ms。live 4,496 / heroes 165（`artifacts/game-progress.md:213`，v 打包门实测 calls 556、frameP95 25ms）。

## ② V 系设计要点（V2 卷）

V2 的冲突对账表给出烘焙 vs 体素四条结构性冲突：**所有权**（compactStatic 后顶点归属信息消失）、**生命周期**（`flush` 只增不删，现有代码无一条 `scene.remove` 针对城市几何）、**预算形态**（一次性载入预算 vs 持续操作预算不能混账）、**命名空间即协议**（`city_` 前缀会同时触发天宫 2.2× 缩放与合并，体素区统一 `vox_` 前缀并配断言）。三条路线对照后**推荐路线 A：局部体素沙盒 + 烘焙背景**（+0.2–0.6M 面 / +44MB / 载入 +0.3–0.9s / draw +30 / ≈6,500 行），B 分块烘焙否决（builder 非纯函数），C 全量体素硬否决（+2e8 面起步）。路线 A 的三条隔离：命名空间（`vox_<sandboxId>_<group>`）、材质实例（克隆 6 组，因 `WardInfill` 三个 `onBeforeCompile` 补丁按世界 Y 上色会污染方块）、加载时序（沙盒必须在 `compactStatic` 之后创建，避免全场景 traverse 白付 240 节点）。区块 16³、沙盒 48 区块（64×64×48 格 @0.5m）、5 沙盒体素数据共 1.88MiB；沙盒对角 25.6m 远小于 LOD 近档 120m ⇒ 路线 A 不需要流式加载。确定性契约：新系统禁用全局 RNG 共享序列，必须自建独立种子。

## ③ D 系设计要点（D1 卷）

D1 把链的真实拓扑逐段落位并实测（复测口径 dist + http + headless）：`Baker` 累积 35 步共 9,288ms，其中四步超 1,200ms 预算线（山河地形 1,714 / 里坊民居 1,633 / 宫城 1,519 / 云海宫阙 1,277）但只告警不阻断 ⇒「加载卡一下」是结构性的；`flush` 35 次共 999ms（每步 flush 的依据是 bake.ts 注释：全城累积 10M 面 / 3GB 堆会撞 GC 悬崖）；`compactStatic` 273→36 个网格、释放 −641MB（2,458→1,817MB）；天宫缩放一遍 220ms（56.7M 顶点）；凌霄放大一遍 136ms（13 mesh / 137,466 顶点）；LOD 注册单次测不出开销。三条口径纪律：`engineMs` 只覆盖载入期（`__loadStartAt..__loadEndAt`）；面数必须带 T_static/T_scene/T_frame 口径；draw 只按**绝对增量**记（`+36 calls`），百分比换个机位就漂。运行时追加路径（ADR-2）：运行时新增几何必须**世界坐标直建**、自带包围球显式注册 LOD、命名 `rt_` 前缀（禁 `city_*`）、过 `probe-runtime-assets` 断言。85ms 级热替换（ADR-4）五阶段四回滚点，不影响 `engineMs`。LOD 与合批冲突的三选一判据：按「独立 Mesh / InstancedMesh / BatchedMesh」顺序问，命中即停；运行时追加额度 `+36 calls`。

**D1 载入链逐段补账**（复测口径）：`compactStatic` 273→36 个网格、堆 2,458→1,817MB（−641MB）、批预算 48MB；天宫缩放一遍处理 56.7M 顶点、耗时 220ms；凌霄放大 13 个 mesh / 137,466 顶点、一遍 136ms；LOD 注册单次开销测不出（随建随注册）。`flush` 的让帧策略在 `bake.ts:1309` 附近（累计装配量超 8ms 才让一帧；注释记录旧实现「每装一组让一帧，271 次让帧等掉 4.6s」的历史——该参数不能随手调小）。D1 §4.5 还给了反例：D3 的 200 座运行时建筑若每座独立 Mesh 将击穿 +36 calls 额度，必须走实例化判据。引擎侧 `dt` 夹取 0.1s（`engine.ts:844`）意味着一帧最多 12 个 1/120 物理步，`MAX_SUBSTEPS=16` 是余量不是常态（`physics.ts:63` 注释原文同口径）。

## ④ 冲突裁决

1. **区块尺寸：V2 16³ vs D3 32×32×16。** 判给 **D3**。D3 的 32×32×16 有本机实测吞吐（2.36M 格/秒 ⇒ 6.9ms/区块）、调色板 8 位整除、与沙盒 12 区块整除三条硬账；V2 的 16³ 是从「内存常量 + 位运算」出发的推断。体素细节裁决权归 S03，本系统只锁结论：接 D3 的区块参数，V2 的路线 A 框架与三条隔离不变。
2. **材质组：V2/V3 克隆 6 组 +30 draw vs D3 13 组 65 draw。** 判给 **D3 的组数账、V3 的克隆手段**：`BGroup` 实测 14 组（`bake.ts:4`）中 `glow` 不承载方块，方块落 13 组是事实账；但 `onBeforeCompile` 补丁污染问题真实存在（V3 实测 `Material.copy()` 不复制钩子），克隆手段保留。详见 S03 裁决 2。
3. **V2「体素沙盒必须在 compactStatic 之后创建」vs D1「运行时只能追加」。** 三方一致：体素沙盒属载入期末尾的一次性构建，不属运行时追加；运行时只有造物/蓝图走 `rt_` 追加路径。无裁决项。
4. **V11/D7 的帧预算数字 vs 红线。** 凡与「p95 红线 dev 33.3 / 打包 58 / 发布 50」冲突者以红线为准（裁决原则 2）。H5 已定性 dev 尾部卡顿为呈现侧偶发错过 vsync、GPU 填充假设被否（像素比 0.5 在 600 帧口径下仅 −0.15ms），**禁止在打包态归因（P3-1b）出结果前做砍像素/砍阴影决策**。
5. **行号漂移。** V/D 卷引用的 `world.ts:277/710/783/804/821/834` 等在当前工作树实测为 `:296/:728-735/:802/:823/:848/:861`（本文件①段已按实测改写）。判给**实测行号**；卷内行号视为写作时点快照，本融合层为唯一引用基准。
