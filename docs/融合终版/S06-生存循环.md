# S06 · 生存循环（融合终版）

> 素材：V6《生存循环》× 代码实测（雏形：boss.ts 血量/攻击、小吃摊饮食；无玩家四维、无天气、无死亡流程）。

## ① 代码现状（实测锚）

**玩家无敌方数值体系。** `src/game/player.ts` 现有：`RUN_SPEED = 8.2`（`:35`）；`busyUntil` 交互锁定（`:62`，时钟已可注入 `:64` 注释「默认 legacyClock（宿主 performance.now）」——P0-0 的墙钟改造**已完成注入接口**）；跳跃 `vy = 7.5`、重力 22（`:413/:409`，跃高 ≈1.3m，boss.ts:143 注释同口径）；`speedScale` 由 `src/world.ts:1298` 每帧无条件覆盖 `near ? 0.55 : 1`（任何状态系统写它都会被抹掉——V6 §0.3 的坑在当前树仍然成立）。`impactUntil` 受击窗口由 `ImpactSystem` 写（`src/game/physics.ts:104/108/112/127`：3600/1200/3500/4000ms 分级）。**没有 hp/hunger/stamina/spirit 字段，没有死亡与重生流程**；玩家可被打飞（physics 分级）但不会死。

**饮食雏形**：`src/data/interactPoints.ts` `kind:'eat'` 摊位（如 `:15` 茶坊点茶 2 文）只扣钱发 toast，无任何数值回报。

**昼夜**：`TimeOfDay.paused`、`speed=1/420`（V6 实读 `src/core/palette.ts:35-36`，一昼夜 420s、开局停黄昏）；`isNight` 判定区间 `phase 0.16–0.86`（`src/world.ts:1284`）。**昼夜钟默认停摆 ⇒ 任何挂 phase 的生存结算都不会走**。

**Boss 数值雏形**：`src/data/boss.ts:38` `maxHp: 320`、`:41` `meleeRange: 12`、`:43-44` sweep/grab 前摇判定；`src/game/boss.ts:166` 脱战回血 `maxHp * 0.04 * dt`（注释与代码历史不一致已按代码为准 4%/s）。Boss 是唯一有血量的实体。

## ② V 系设计要点（V6 卷）

三处先纠事实：玩家文件是 `src/game/player.ts`（`src/actors/player.ts` 不存在）；昼夜钟默认停；`speedScale` 每帧被覆盖。**四维整数千分位**（hp/hunger/stamina/spirit 0–1000，不用 0–100 浮点——确定性存档防跨机 ULP 分叉、状态乘法可逆）；界域附加维 `extra`（天宫香火/地府阴寿）。消耗恢复曲线按 420s 昼夜折算：饥饿静止 −0.95/s（满→空 1053s≈2.5 昼夜）、奔跑体力 −35/s（满→空 28.6s 跑 235m=虹桥到州桥一个来回）、精神夜间 −3.4/s（294s 整夜恰好掏空，睡 60s 补 720）。阈值分档与惩罚表（饿殍 hp −0.5/s + speedScale×0.7；疲乏跳跃 ×0.7 后 0.63m 跨不过 0.95m 台阶——有意设计）。**三界差异化不是换皮**：人间正常四维；天宫饥饿冻结、换香火维（耗尽=金光黯淡 hp 上限 600 + 禁传送）+ 戒律（说谎/杀生/偷供品累计 3 次贬谪）；地府阴寿 600s 倒计时（受击 −30s/击杀 −60s/落忘川 −120s，归零魂散）逼出潜行玩法；业力 0–9999 只增不减（≥100 挂业障：商人加价 50%、掉落翻倍），**死了也不清零**。天气八种 + 插入点唯一（对齐 `palette.ts` 字段）；`paused=true` 坑；天气渲染预算。死亡与重生：三界死亡规则、重生锚点表、与 `PORTALS` 兼容、掉落物去向、三界资源不许互通。接线五处：`player.ts` / `physics.ts` / `world.ts applyLighting` / crowd / HUD。数值单一真相源集中一处。

## ③ D 系设计要点（D 系无独立生存卷）

D 系十卷无生存卷；相关约束来自：D7 性能（生存 HUD 不得每帧重排——P3-1 归因候选含「HUD 每帧重排」，生存 UI 必须走脏标记）；D9 UI/UX（状态图标与提示区占用，进 P1-8 布局矩阵统一裁）；D10 操作响应（判定类输入固定步采样 + 100ms 缓冲，P3-4——饮食/睡眠等交互在冷却期不得静默丢弃）。工程侧把 V6 的实现拆进 P1 段位：Vitals 数值核（确定性门内）、三界规则层、天气层、死亡重生层。

**V6 补充**：§1.5 一昼夜资源曲线按 `crowd.isNight` 区间切成五段（黄昏 0.00–0.16 共 67.2s 精神 +100.8；夜 0.16–0.42 共 109.2s 精神 −371.3，夜市/瓦子/酒楼开门时段与消耗曲线对齐——生存节奏与商业时段互为因果是本卷的隐性设计）。§2 状态效果：状态机 + 二十四条状态 + 状态间连锁（如醉酒→寒冷易感）+ 与既有系统接缝 + 数值单一真相源（集中一处，禁散落）。§3 天气：与 `palette.ts` 字段级对齐（不另立光照参数源）、八种天气、**插入点只有一处**（避免散布 patch）、对四类对象（人/生物/几何/玩法）的影响表、`paused=true` 坑的显式处理、天气渲染预算单列。§4 死亡与重生：三界死亡规则、重生锚点表、与 `PORTALS` 的兼容（死亡重生不得绕过门冷却语义）、死亡流程分步、掉落物去向、**三界资源不许互通**（掉落就地结算，不跨界面转移）。§5 接线五处：`src/game/player.ts`（主战场）、`src/game/physics.ts`、`world.ts` 的 `applyLighting`、crowd 与 HUD、HUD 提示。§6 验收断言之外另列「手工验收三件事」（探针覆盖不到的体感项）；§7 冲突与代价 + 开发量估算（标注「本项目取值，非实测工时」）；§8 本卷自认最弱三处。

**V6 §1.2 补充（刻意的对齐，验收时防误修）**：饥饿满→空 1053s≈2.5 昼夜（1000/0.95）让「出门带干粮」是真需求；精神整夜刚好掏空是按 `crowd.isNight` 判定区间（夜长 294s × 3.4 = 999.6）反算的，不是巧合；体力满→空 28.6s 全速跑 235m（`RUN_SPEED=8.2`，实测 `player.ts:35`）正好虹桥到州桥一个来回——「跑得动但跑不远」是核心手感，改任一参数前先看这三个对齐关系是否被破坏。疲乏跳跃 ×0.7（7.5→5.25，跃高 1.28m→0.63m）刚好跨不过 `WS_STEP_UP=0.95`（`behaviors.ts:89`）——疲乏时连台阶都要绕，这条与 S05 的步行面参数是同一张网上的两个结，禁止单边调整。

## ④ 冲突裁决

1. **V6 千分位整数 vs V10 SaveV4 样例的 hp 0–100。** 判给 **V6 千分位**：V6 的确定性论证（跨机 ULP、可逆乘法）是硬理由；V10 §3.2 JSON 样例里的 `hp: 86` 属 schema 示意，P0-4 实施时字段域按 0–1000 收敛，`minReader` 升版记录。两卷对「整数千分位」无实质分歧，只有样例漂移。
2. **V6 昼夜 420s 开局停摆 vs 玩法需要时钟走。** 判给 **V6 但带条件**：解 paused 必须先过确定性门（`TimeOfDay` 若用 `performance.now` 会撞 7 文件 A 类零命中红线）——时钟推进用固定步累计（SIM_DT）而非墙钟；开局是否起摆由 P1 段开关决定，默认黄昏起摆。
3. **V6 精神/体力效果写 `speedScale` vs `world.ts:1298` 每帧覆盖。** 判给 **V6 的解法**：速度结算改为单一出口 `effectiveSpeed()`（把 walk/run/base 与状态乘子合成，`world.ts:1298` 改写该出口的输入而非直接覆盖）——V6 §5.1 已给此接缝，落点核实为当前 `:1298`。
4. **V6 三界死亡规则（地府魂散/天宫贬谪）vs V13 六道阶位（业力系统）。** 判**职责切分**：死亡流程、掉落、重生锚点归本系统（S06）；业力累计、六道阈值 480、阶位动词归 S10（V13）；两系统共享的唯一字段是 `karma`（0–9999，存档单点真相）。V6 的「业力 ≥100 业障」与 V13 的累积表合并为一张表，禁止两处定义。
5. **Boss 4%/s 回血注释漂移。** 判给**代码为准**（`boss.ts:166` 0.04），注释修正随 S09 任务。
6. **天气八种 vs 性能。** 判给 **V6 但降级启动**：天气渲染预算未实测前，先落「数据+状态层」，视觉层（雨雪粒子）待 P3-1b 归因后再排，避免重蹈「砍负载不知砍哪」。
