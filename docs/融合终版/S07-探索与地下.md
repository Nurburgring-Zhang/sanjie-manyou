# S07 · 探索与地下（融合终版）

> 素材：V7《探索与地下》× D2（地下落位部分）× 代码实测（地府/十八狱/丰都=静态烘焙场景，无程序生成）。

## ① 代码现状（实测锚）

**地府是静态烘焙几何。** `src/sky/underworld.ts:10` `UNDER = { y: -260, gateZ: -130, bridgeZ: -60 }`；十八狱/阎罗殿/孟婆庄在 `src/sky/hells.ts`（`:11` 注释「B2：十八狱逐狱装置 + 阎罗殿法庭内饰 + 孟婆庄」；`:925` 十八狱环总装「狱体 16×16×9 半地下 3m，狱门朝环心」；`:710` 注释承认「刑具全被门叶挡住，十八层读不出」）。丰都鬼城经 `world.ts` tasks 烘焙（「幽冥·丰都街」步，D1 §1.1 实测 216ms）。**无洞穴、无程序生成、无遗迹点**；地下探索=走完现成场景。

**入口**：`PORTALS` 仅阴阳界两向（`src/game/player.ts:495-498`），地府落点 (0,−260,−130)；天宫无玩法门（S02 已裁）。`groundHeight` 对 `refY < -100` 恒返 −260（`player.ts:235-237`）。

**地形**：`TERRAIN_SIZE=62000 / TERRAIN_SEG=300`，格距 206.67m（`src/world/terrain.ts:329`）——洞口物理不可表达（V7 F1）。`terrain.ts` 现有 `Math.random ×9`（probe-determinism B 类，地形散点；H6/清单口径「应种子化（地形是碰撞面）」——当前实测这些调用在烘焙期种子流内）。

**探索现状**：17 个目标节点纯距离判定（`objectiveReached` 只判 `d ≤ max(6, radius×0.2)`，清单 v3 P1-4）；图鉴/传送走 `World.teleport`（`world.ts:1538`）。

## ② V 系设计要点（V7 卷）

硬结论：**洞穴不是挖出来的，是另做一具几何再用结构物盖接缝**（地形加密到 6m 格距需 1.07 亿顶点）。洞穴两族噪声：方案 A 3D 值噪声+Marching Cubes（奶酪洞：大空腔短支洞，全项目限 4 个洞厅，6m 体素后 3.3MB/厅共 13.2MB，需生成 256 项边表）；方案 B 脊线抽取+管体放样（意面洞：长走廊主隧道）。接缝三层遮蔽；`caveGroundY` 新增地面查询与 `walkSurfaceY` 并列；洞内光照雾载入按 CaveUnit（非 chunk）；**谁下洞先把范围钉死**（玩家+指定 NPC）；阴河水体是玩法不是装饰。矿脉与遗迹 14 类可探索点（统一数据契约：生成条件/结构模板/掉落/危险度/数量成本核对）。三界互通三组门（`heavenGate` 泰山⇄南天门、`yinYangGate` 补冷却、`abyssGate` 单向蟠桃 1 + 180s 冷却）+ POI 五铁律 + 门与 `teleport()` 两套并存。维度边界：垂直分层，地下垂直预算单独立账。探索激励：地图揭示只加三字段、成就复用 `codexLog` 不新建系统、稀有资源接三币、逐类遗迹给产出。12 条可执行验收断言；冲突代价表；本卷自认最弱三处。

## ③ D 系设计要点（D2 §3/§4 地下相关）

D2 给了 S5 地府·西鬼市沙盒落位 (−200,−260,−150)：地面 `city_ground` −260.00 ×5 射线、高差 0.00、头顶净空 125.5m（`city_ash_3`）、距奈何桥抵达点 220m、建议新增传送——五块沙盒中唯一在地下的一块，体素原点取 −260。六条选位判据 J1–J6 对地下同样适用（J3 避河在地下不适用，改判「不压奈何桥/阎罗殿 POI」）。D2 §4 的 100m 生成区与 `insertionMask` 载入期索引同样约束地下生成物落位。D1 侧约束：地府几何已进 14 组烘焙，任何洞穴几何不得复用 `city_*` 命名（会被合并吃掉身份）。

**V7 细节补充**：方案 A（奶酪洞）代价账完整可复算——512m×96m×512m 区域 @4m 体素 = 393,216 采样、约 9.4M 次整数运算（JS 10–25ms/洞）、≈10.3 万 tris、11.1MB/洞；降 6m 体素后 3.3MB/洞、4 个洞厅合计 13.2MB；Marching Cubes 256 项边表不可手写必须生成。方案 B 脊线抽取 + 管体放样（「意面洞」）承担主隧道。接缝三层遮蔽；`caveGroundY` 与 `walkSurfaceY` 并列；洞内光照与雾单独配；载入按 **CaveUnit**（不是 chunk）；「谁下洞」先把范围钉死（玩家 + 指定 NPC，不全量人群进洞）；阴河是玩法不是装饰。§2 可探索点统一数据契约（生成条件/结构模板/掉落/危险度）+ 逐类表 + 数量与成本的现实核对（V7 自认最弱三处之一）。§5 激励：地图揭示只加三个字段、成就复用 `codexLog` 不新建系统、稀有资源接三币、逐类给产出。§6 十二条验收断言全部可跑；§8 可派单 agent 的原子任务表。D2 S5 地府·西鬼市（本系统在沙盒落位上的地下代表）：五射线全部命中 `city_ground` −260.00、高差 0.00（五块中最平）、头顶净空 125.5m（`city_ash_3`）、距奈何桥抵达点 220m（压 J5 可达线，故「建议新增传送」）。

**V7 §1.2-1.7 补充**：与静态地形的接缝用三层遮蔽（洞口构筑物 / 地形裙边 / 雾与光照衰减），三层各有失败模式；`caveGroundY` 的查询语义与既有 `groundHeight` 的关系（洞内优先、洞外回退，不许两套答案打架）；洞内光照与雾单独配（沿用烘焙光照会全黑或全亮）；载入按 **CaveUnit** 单元而非 chunk（单元=一次可完整生成+卸载的最小闭环）；「谁下洞」——只有玩家与指定 NPC 进洞，全量 4,496 人群不做洞内寻路（成本不可接受且无玩法收益）；阴河水体接 S04 资源轴（阴河特产）与 S06 生存（落水惩罚）。§2.1 可探索点统一数据契约的五字段（生成条件/结构模板/掉落/危险度/重访语义）是 14 类共用的唯一 schema——本层把它降为 6 类先落（裁决 3）时，契约字段不变，砍的是类型数不是字段数。§2.5 数量与成本的现实核对是 V7 自认最弱处：14 类逐类的数量账未全部实跑，进 P1-4 时按「先跑探针、再定数量」的 E1 方法论补课。

## ④ 冲突裁决

1. **V7 洞穴系统（噪声+MC+洞厅）vs 现状静态场景 + 面数红线。** 判**分级执行**：洞穴属 MC 全量诉求，V16 Plan A 砍全局体素时一并弱化；本融合层的定案是「**不做全局程序洞穴**，仅在五沙盒（尤其 S5 地府）内做可挖域 + 预制遗迹点」。V7 的方案 A/B 技术储备保留为未决（不进 P0–P4 排期）；若未来进，必须先过 `T_static` 不增 0.3M 的红线门。理由：清单 v3 是唯一路线图（裁决原则 1），其中无洞穴条目；V7 自认最弱三处已承认数量成本核对是软肋。
2. **V7 三组门 vs 清单 v3 无对应条目。** 判给**部分采纳**：`yinYangGate` 补冷却/落地锁（并进 P1-4 传送断链任务）采纳；`heavenGate`/`abyssGate` 依赖度牒/蟠桃经济与阶位前置（P1-1/P1-5 落地后）才可排——归 P1 段尾部，不设独立编号。
3. **V7 14 类可探索点 vs P1-4 条件节点。** 判给 **P1-4 框架吸收**：17 节点改条件判定的「交物/战斗/对话/建造」四类条件，直接以 V7 的可探索点为素材源；14 类全表不做，先落 6 个条件节点（P1-4 原验收）。
4. **V7 caveGroundY vs P0-2+P0-7 统一地面模型。** 判给**统一地面模型吸收**：洞内地面查询作为 P0-2 动态体积查询的一种输入源（体素域），不新增并列函数。
5. **hells.ts「十八层读不出」注释 vs V7 遗迹设计。** 三方一致：这是内容可读性缺陷，归 P4 美术体验段（门叶遮挡/导引），不改几何结构。
6. **地形散点 `Math.random`。** 判给**保持现状**：烘焙期种子流已定，改动会重排全城外观（V10 §1.1 同判）；B 类清单维持 REPORT。
