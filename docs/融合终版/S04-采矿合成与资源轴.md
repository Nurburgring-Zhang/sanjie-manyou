## ② V 系设计要点（V4 卷）

V4 边界三句话：矿只在沙盒里（五沙盒之外烘焙地形不可挖 ⇒ 经济模型必须是「稀缺+回收」不是「无限产出」）；方块由 V3 注册表定义（本卷只引用 `BlockDef.key`）；**经济只扩展不修改**（`interact.ts` 三币逻辑一行不动，只加 sell/burn/unlockRecipe 三方法）。矿种表 24 种，按沙盒分布（人间城外矿洞主产区 0..−48m、营造场只出黏土砂、河滩只出砂卵石、天宫云根矿 48m 稀有矿、地府矿位）。冶炼：炉体/温度/风箱 + 24 条配方 + 品质与市场；**燃料温度裁定**：生铁 ≤1100、熟铁 ≤1400、钢只能靠天火 1700（D3 §0.1 登记为经济卷持有）。合成：工匠台分级 + 69 条配方 + 依赖链门控 + 失败模式。**三界结算律**（V4 §5.2）：人间卖给 61 交互点商人售价=原料基准价×0.6（折价 40% 防套利，合成永远是「亏损的变现」，价值在产物有用不在值钱）；地府冥器在王家纸马焚烧换阴德 = max(1, floor(原料价/10)) 上限 3/件（给阴德一个出口）；天宫配方需蟠桃点解锁、产物不可售（防「蟠桃→铜钱」间接兑换绕过 1:100）。反套利三闸门：单步不赚、中间品按原料价×1.15 递推定价（n 越大越亏）、熔炉 output 满 3 组即停 + 矿脉有限。诚实边界：只证明了单链不赚，跨链组合不赚需对 69 配方做全图最长路径/最小成本搜索（B5 扩展断言）。价格锚定既有物价（`interactPoints.ts` 商品带 1–500 文：米 3、麻鞋 15、絹 60、皮靴 120、杭緞 150、銀鐲 200、蜀錦 300、龍腦 500）。

## ③ D 系设计要点（D3§资源 + V16）

D3 只登记矿石方块 id 与掉落，**不涉及熔炼**（温度裁定归经济/工艺卷，避免两处漂移）；矿=脉状体素簇按品位分 3 档，不改 `terrain.ts` 山体。V16 经济章：五种货币分「钱包/账本/场所属性」三类，关系图必须是有向无环图；**先算清现有两台印钞机**（通胀风险）；跨阶折算「什么能过界什么不能」；阶位改规则不改场景。V16 §0 五条硬判断与 Plan A/B/C 三套砍法（Plan A 推荐并明确砍 V2 全局体素/V3 全局方块/V5 全局建造/V10 多人 ⇒ 「242 人日」是 Plan A 的数，全 16 卷是 478 人日——清单 v3 R4 已裁定两套账不得拼接）。

**V4 §1/§2/§3/§4 补充**：矿脉按沙盒分布五处（人间城外矿洞主产区可挖 0..−48m〔按 D2 24m 上限重算，见裁决 4〕、城内营造场只出黏土/砂、河滩只出砂/卵石、天宫云根矿 y≈2126–2174 稀有矿、地府矿位补齐五沙盒），配生成算法、巷道与支护、所有权关系（§1.5）、单沙盒矿脉账与矿洞空间布局。冶炼 24 条配方：炉体/温度/风箱、燃料体系、炉渣副产物与品质、冶炼失败模式、一次冶炼完整算例、品质与市场分层。合成 69 条配方：原料与中间品、工匠台分级、依赖链与门控、配方 UI、合成失败模式。宋代工艺考据一节自带「待核实清单」（§4.1，与共享约束的「待检索核实」纪律同源——未核实项不得写成事实）。V4 §5.5/§5.6 自带「开局 30 分钟路线验算」与「一天的收入与支出」两张账，P1-1 落地时按 2.44 文/s 重算后引用。V4 §5.7 明列本卷不做的三件事（不碰三币存量语义、不做无限产出、不做跨沙盒套利通道）。V16 五币侧补充：货币分「钱包（可花）/账本（可累计）/场所属性（不可携走）」三类，兑换率表必须构成有向无环图，跨阶折算单列「什么能过界什么不能」；五币×系统耦合矩阵回答「谁在印钞、谁在回收」。

**V4 §1.5/§1.7 补充**：矿脉与所有权的关系（沙盒内矿脉归属谁——公共矿/领地矿的判定在挖下第一镐时锁定，防止「半路截胡」纠纷）；矿洞空间布局（巷道网络/支护密度/通风与矿种埋深的关系）。§2.4-2.6：炉渣与副产物进回收流（渣不是废料，是 S05 建造的填料来源之一）、品质分档与市场分层（同矿不同价，品质是合成链上唯一的随机度出口且必须走注入 RNG——S12 确定性门覆盖）、一次冶炼完整算例可复算。§3.3 依赖链与门控：69 条配方构成 DAG，门控节点同时是 P1-1 资源轴的「解锁新矿与新部件」跳点——两张表（配方 DAG 与资源轴链条）必须是同一张图的两视图，禁止两处各画各的。

## ④ 冲突裁决

1. **V16「资源轴已闭合可设计汇率」vs H6「三轴全断」。** 判给 **H6（勘误层第 2 条，凌驾卷内）**：先补 sink/source，后设计汇率。顺序定为：①蟠桃 source（蟠桃宴任务线）→②阴德 sink（冥器焚烧，即 V4 §5.2 地府律，可直接采纳）→③五子棋收费或限次→④劳动秒数锚定（扛包 2.44 文/s）→⑤才谈 V4 三界结算律与 V16 汇率表。
2. **V4「不修改 interact.ts 三币逻辑一行不动」vs P1-1「定义唯一资源轴」。** 判**有限修订**：单向兑换两条（烧纸/蟠桃赏赐）与三键存储**语义不动**；但实现载体按 P0-4 迁往 IndexedDB（`localStorage` 三键作为迁移源保留），V4 的三个新增方法落在 `interact.ts` 旁路模块（`src/econ/`），不碰 `:104-109` 现行分支。理由：H4 GO 后存储形态已升级，V4 写作时的「storage 不动」前提部分失效，但「防套利不动单向律」的核心意图完整保留。
3. **V4 售价折价 0.6 vs H6 劳动锚 2.44 文/s。** 三方一致兼容：0.6 管的是「合成变现」侧，2.44 文/s 管的是「劳动产出」侧；P1-1 落地时全链数字须同时过两把尺（合成链终端售价 ≤0.6×原料×1.15^n 且每小时劳动收益与 2.44 文/s 同量纲），由 B5 扩展断言机检。
4. **V4 矿洞可挖 0..−48m vs D2/D3 沙盒 24m 高。** 判给 **D2/D3**：沙盒高度按 32×32×24m 重算，主矿洞「0..−48m」改为「0..−24m 或双层沙盒（上下两块 S 位）」——S4 天宫与 S5 地府已占两块，人间三块中指定一块为矿洞加深方案待 P1-2 设计时二选一，本层只锁「24m 上限」。
5. **62 vs 61 交互点。** 判给**实测 62**：`interactPoints.ts` 现有 62 个 id（61 点 + `PEACH_GRANT` T1 蟠桃宴位）；V4/H6 写作时为 61，蟠桃赏赐修复后并入。引用时写「61+1」。
6. **五子棋。** 判给 **H6**：P1-1 首批内必须落地「收费或限次」，二选一由实现时按误伤面定，默认限次（每游戏日 3 局），保留收费为备选。
