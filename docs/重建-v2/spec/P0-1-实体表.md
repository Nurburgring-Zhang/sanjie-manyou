# SPEC P0-1 · 实体表（Entity Registry）

> 强制顺序第一项。**它不直接让玩家看到任何东西**，但 P0-2/3/4/5 全部依赖它。
> 依据：`docs/重建-v2/全量工作清单.md` §1；审核 A「三块地基不存在」。
> 约束：ADR-1（坐标唯一真相源）、ADR-2（运行时追加）、ADR-3（确定性）、ADR-9（本体改动）。

## 0. 目标 / 非目标

**目标**
- 给场上每一个「可被碰撞、可被存档、可被注销」的对象一个**稳定 id**。
- 提供统一的**注册 / 查询 / 注销**入口，注销必须真正停止更新与渲染。
- 成为 P0-3（碰撞）、P0-4（存档）、P0-5（循环）的公共键。

**非目标**
- 不做通用 ECS（不引入 archetype/查询缓存/系统调度）。**只要 id + 生命周期 + 组件槽。**
- 不改动既有 `crowd.actors` / `pools` / `beast` 的内部实现——只**包一层 id**。
- 不做序列化本身（属 P0-4）。

## 1. 现状（三套并存，无统一键）

| 结构 | 位置 | 形状 | 问题 |
|---|---|---|---|
| 人群 | `src/actors/crowd.ts` 的 `actors: Actor[]` | 数组下标即身份 | 删除一个就全体错位 |
| 部件槽 | `src/actors/pools.ts` 的 slot 分配器 | `{body, head, leg, …}` 槽位号 | 只表达"渲染件"，不表达"实体" |
| 兽体 | `src/sky/creatures.ts` 的 `beasts: Beast[]` + `beastReport()` | 数组 + 池计数 | 与 crowd 两套生命周期 |
| 更新表 | `src/core/engine.ts` 的 `updatables` | 有 `addUpdate`，**无 `removeUpdate`** | 注销后 updater 继续跑 |

## 2. 数据结构

```ts
// src/rt/entity.ts
export type EntityId = number;            // 单调递增，不复用（复用会破坏存档与回放）
export const NONE_ENTITY: EntityId = 0;   // 0 恒为无效 id

export type EntityKind =
  | 'npc' | 'beast' | 'creation'   // P0-3 需要碰撞
  | 'block' | 'building'           // P2/P1 需要
  | 'prop' | 'fx';                 // 只渲染

export interface EntityRecord {
  id: EntityId;
  kind: EntityKind;
  /** 渲染根：注销时从这里 remove；null 表示纯逻辑实体（如碰撞体、触发器） */
  object3d: import('three').Object3D | null;
  /** 位置来源：优先读这里，而不是 object3d.position（天宫必须走 heavenY，见 ADR-1） */
  pos: { x: number; y: number; z: number };
  /** 组件槽：按需挂，未挂即 undefined。P0-3 挂 collider，P0-4 读 persist */
  collider?: { kind: 'capsule' | 'box' | 'sphere' | 'mesh'; params: unknown };
  behavior?: { kind: 'static' | 'patrol' | 'follow' | 'fly' | 'swim'; params: unknown };
  /** P0-4 用：false 的不入档 */
  persist: boolean;
  /** ADR-3：生成式实体必须带来源，可重放 */
  provenance?: { seed: number; moduleHash: string; apiVersion: string };
  /** 注销回调（注销引擎 updater、LOD、物理体）；**按注册逆序调用** */
  onDispose: Array<() => void>;
  alive: boolean;
}
```

**关键约束**
- `id` **单调递增、永不复用**。复用会让旧存档里的引用指到新对象（存档毒药）。
- `pos` 是**权威位置**，`object3d.position` 是它的投影。天宫/地府必须经 `heavenY()`（ADR-1）后再写入 `pos`。
- `onDispose` **逆序调用**：后注册的先拆，保证依赖（如 LOD 注册晚于 mesh 创建）不会拆在半空。

## 3. API 契约

```ts
export function allocate(kind: EntityKind, init: Partial<EntityRecord>): EntityId;
export function get(id: EntityId): EntityRecord | undefined;
export function alive(id: EntityId): boolean;
/** 只做逻辑注销：置 alive=false、移出索引、按逆序跑 onDispose。可从 onDispose 内重入。 */
export function dispose(id: EntityId): boolean;
/** 按 kind 遍历（不含已 dispose 的） */
export function forEach(kind: EntityKind, fn: (e: EntityRecord) => void): void;
/** 诊断：当前存活数、已分配总数、最近一次注销原因 */
export function entityStats(): { alive: number; allocated: number; disposed: number; byKind: Record<string, number> };
```

**错误码**（全部返回值，不抛异常——抛异常会中断帧）
| 情况 | 返回 |
|---|---|
| `get(0)` / `get(未分配)` | `undefined` |
| `dispose(已注销)` | `false`（幂等，不报错） |
| `allocate` 时 `kind` 非法 | 编译期拦（联合类型） |

## 4. 迁移策略（分三步，每步可回滚）

**步 1（不改变行为）**：只**建表**。在 `crowd.spawnActor`、`creatures.spawn`、`scene.add` 之后补一行 `allocate(...)`，把已有对象登记进去；谁都不读这张表。
- 验收：`entityStats().alive` 等于「人群 + 兽体 + 造物 + 建筑」的实测数（人群 4495 量级）。
- 回滚：删掉登记调用即可，零副作用。

**步 2（只读接入）**：P0-3（碰撞）与 P0-4（存档）改**从表里读**，不再自己维护数组。
- 验收：碰撞体数量 === `forEach('creation')` 的计数。

**步 3（写路径接管）**：新增对象一律先 `allocate` 再挂场景；删除一律走 `dispose`。
- 这一步才动 `updatables`：`dispose` 里调 `removeUpdate`（需 P0-5 先补该 API）。

## 5. 验收断言（全部可机检）

新建 `scripts/probe-entity-registry.mjs`（浏览器内执行）：

| # | 断言 | 方法 |
|---|---|---|
| A1 | `entityStats().alive` === 场景内被判为实体的对象数 | 与 `crowd.actors.length + beasts.length + creations.length` 交叉核 |
| A2 | `allocate` N 次后 `allocated` 增加 N，且 **id 严格递增无重复** | 收集 1e4 个 id 做 `Set` 去重 |
| A3 | `dispose(id)` 后 `get(id) === undefined`、`alive(id) === false`、`forEach` 不再返回它 | 逐项断言 |
| A4 | `dispose` 幂等：连调 3 次，返回 `true, false, false` | 逐次记返回值 |
| A5 | **注销后对象真的消失**：`scene` 里 `getObjectByName` 找不到、`renderer.info.render.calls` 不回升 | 注销前后各采一次 calls |
| A6 | `onDispose` **逆序**执行 | 注册 3 个回调 push 到数组，断言执行顺序为 3→2→1 |
| A7 | **无泄漏**：分配 1000 → 全部 dispose → `alive === 0`，且 `performance.memory.usedJSHeapSize` 不高于基线 5% | 两轮循环，第二轮不增长 |
| A8 | **不破坏确定性**：同种子两次跑，`entityStats()` 逐值一致 | 复用 `probe-sim-determinism` 的哈希法 |

## 6. 与后续条目的接口

| 条目 | 依赖方式 |
|---|---|
| **P0-2** 动态碰撞 | `groundHeight()` 遍历 `forEach('block' \| 'creation')` 取 collider |
| **P0-3** collider registry | `allocate` 时挂 `collider`，`dispose` 时用 `onDispose` 摘除 |
| **P0-4** 存档 | 遍历 `forEach` 且 `persist === true`；`provenance` 是重放键 |
| **P0-5** 固定步循环 | `dispose` 里调 `removeUpdate`；遍历顺序必须稳定 |

## 7. 风险与回滚

| 风险 | 处置 |
|---|---|
| 步 1 登记时漏了某类对象 ⇒ A1 不过 | A1 就是为此设的；漏了会当场红 |
| `id` 复用导致存档毒化 | 用单调计数器，**永不回收**；`allocated` 只增 |
| 每帧 `forEach` 分配闭包导致 GC | `forEach` 内部用 for 循环 + 复用迭代器，不建临时数组 |
| 与 `crowd`/`beast` 双写不一致 | 步 2 之前只读不写；步 3 才接管写路径 |

## 附：H2 spike 选型修订（2026-11-04，实施前必须遵守）

> 来源：`_spike/h2-verdict.md`（增量网格哈希 @8m = 0.055ms p95 = 0.16% 帧预算；P0-7 全员贴地场景线性扫 34.3ms 爆帧 103%）。

1. **查询结构定案**：collider 索引用「均匀网格哈希 + 增量更新，cell 8m」——数字打包 key、静态件注册时插一次、动态件每帧换格 swap-remove。
2. **`groundHeight` 禁 forEach**：实体表落地后，`groundHeight(x,z)` 的 'block'|'creation' 遍历必须走网格 `pointQuery(x,z)`（4,400 次/帧时线性遍历直接吃满整帧）；forEach 只许留在初始化与全量重建。
3. **幽灵格**：高速实体跨多格移动时旧桶必须清干净（swap-remove + 换格校验双保险），P0-3 实现时加一条「移动 100 帧后全表对账」断言。
