# SPEC P1-8 · UI 布局矩阵与键位裁决（一次定死）· 2026-11-05

> **文档地位**：本文件是 D9（许愿 UI）与 D10（操作响应）在 **UI 布局与 G 键归属上的唯一裁决层**——两卷冲突处一律以本文件为准；本文件未覆盖的键位以 D10 §1.5（K1–K14）为准。
> **裁决依据**：D9:52/128（G=许愿）vs D10:97（G=开 hotbar）实锤冲突；清单 v3 P1-8 验收 = `probe-hud-occlusion` 全绿。
> **一次定死纪律**：三套矩阵（4 模式 × 3 分辨率 × 占用矩形）是后续 P1-2（MC 中间层）/P1-5（六阶动词）/P2-6（落点）的布局合同——改这里必须走「修订提案 → 双 AI 对抗 → 本文件+清单同步」三步。

## 1. G 键归属裁决

| 冲突双方 | 主张 |
|---|---|
| D9:52 | `G` 展开许愿命令条（不抢焦点，再按 G 或点击才聚焦） |
| D10:97 | `G` = T3 转移：`avatar` + human + inSandbox → `build` 模式开 hotbar |

**裁决：`G` 归建造（D10 胜），许愿改 `Y`（D10 T10 本就定了 `Y`=wish，D9 的 G 表述视为早期草案）。**

理由（三条，可证伪）：
1. **频率与拇指经济**：建造是高频操作（D10 §1.4：放置 1–4 次/秒的进入键），许愿是低频操作（全流程 3–5 分钟一次）。高频给单手易达键。
2. **模式语义**：D10 的 T3 把 G 定义为**模式转移**（avatar→build），模式键被挪用为面板键会破坏 §1.3「Esc 是唯一退一层」的心智模型——`G` 进 build、`Esc` 退，键位对称。
3. **D9 自身兼容**：D9 的许愿条已有 `Y`（T10）入口，G 只是它的另一入口；删 G 入口不影响 D9 任何交互设计（§1.1–1.4 全部保留）。

**连带修正**：D9:52/128 的「按 G」在实施时一律读作「按 Y」；`probe-hud-occlusion` 将断言 `KeyG` 只出现在 build 模式转移、`KeyY` 只出现在 wish 面板（源码级 grep 断言，防两卷回归）。

## 2. 三套 UI 布局矩阵（4 模式 × 3 分辨率 × 占用矩形）

**模式**（D10 §1.3 的 4 个 base/overlay 模式）：`soul` / `avatar` / `build`（含 create 折叠）/ `wish`（overlay）。
**分辨率档**（D10 §3 的实测设备谱）：`1280×720`（下限）/ `1920×1080`（主流）/ `2560×1440`（高端）。
**锚点约定**：全部 DOM HUD 挂 `#ui`（既有），占用矩形以**锚点+边距**表达（非绝对像素），探针按 getBoundingClientRect 实测。

### 矩阵 M1 · soul / avatar（共用，差异仅 bossbar）

| 区 | 锚点 | 尺寸（1080 基准） | 内容 |
|---|---|---|---|
| 顶部品牌条 | top-center | 420×36 | brand + 目标链 |
| 右上状态 | top-right | 300×96 | fps/calls + 三币 + 昼夜 |
| 右上小地图 | top-right 下方 | 220×150 | minimap |

### 矩阵 M2 · build（含 create）

| 区 | 锚点 | 尺寸（1080 基准） | 内容 | 与 M1 的差 |
|---|---|---|---|---|
| hotbar | bottom-center | 10 槽 ×56 + 页签 ≈ 640×96（**置换 dock：dock 收缩为 4 图标角标置右下**） | 物品/方块槽 + 96 件分页页签 | **dock 置换** |

### 分辨率缩放规则（一次定死）

- **720 档**：M1 状态条折叠为一行 220×32；M2 编辑器降两栏（左栏折叠为图标列 48px，属性移底部抽屉 640×180）；dock/hotbar 按钮缩至 48px。
- **1440 档**：全部按 1080 基准 ×1.0 居中，不放大（HUD 过大是反效果）；余量给视口。
- **可用区红线**：任何模式 × 任何分辨率，**中央 640×360（视野核心区）禁止任何 HUD 侵入**——这是 `probe-hud-occlusion` 的硬断言之一。

## 4. 实施顺序（本 spec 内）

1. **本文件即裁决交付物**（矩阵+G 键）——先行落盘供 P1-2/P1-5/P2-6 引用。
2. `probe-hud-occlusion.mjs`：H1/H2/H4/H6 先行（H3/H5 待 hotbar/编辑器实装后补测——当前代码尚无 hotbar DOM，如实标注）。
3. DOM 实装（hotbar/工具条/编辑器骨架）属 P1-2/P1-5 的 UI 部分，**不在本切片**（本切片只定死矩阵与键位——「先做背包 UI 再改布局是确定返工」的教训反着用：先矩阵后 DOM）。
