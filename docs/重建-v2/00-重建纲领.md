## 1. 不可协商的架构裁决（ADR）

### ADR-1 坐标与单位只有一个真相源
- 天宫：`src/sky/heavenFrame.ts` 的 `heavenY()` / `heavenPoint()` / `LINGXIAO_*`。
- **禁止**任何文件再写一份换算（已踩过 3 次：神像低 21.8m、演员低 21.8m、POI 水平偏 96–180m、凌霄阈值差 3m）。
- 机检：`probe-heaven-convention` / `probe-heaven-transform-consistency`。

### ADR-2 几何管线分层：烘焙是基底，运行时只能「追加」
- 载入期：`Baker` 累积 → `flush` → `compactStatic` → `scaleHeavenGeometry` → `enlargeLingxiao` → LOD 注册。**这条链只跑一次**。
- 运行时新增的任何几何：
  - **必须**直接以**世界坐标**构建（不走载入期变换链）；
  - **必须**自带包围球并显式注册 LOD；
  - **禁止**落在 `city_*` 命名空间（否则下次合并/缩放会误伤）。
- 机检：新增对象名前缀 `rt_`，`probe-runtime-assets` 断言其世界坐标与设计值逐值一致。

### ADR-3 确定性：一切可复现，否则可回放/可联机都免谈
- 模拟路径零 `Math.random` / `performance.now`（`probe-determinism` 已把 physics/behaviors/crowd 清零，`Math.random` 189→107）。
- 生成式内容必须记录 `seed + promptHash + modelVersion`，可离线重放。
- 机检：`probe-sim-determinism` / `probe-crowd-determinism` 的**负对照**必须仍然分叉。

### ADR-4 热更新：打包态没有 HMR，只有「资产热替换」
- Electron 打包后 **Vite HMR 不存在**。可行的是：**资产清单 + 动态加载 + 场景图替换**。
- 形态：`asset manifest (JSON)` → `fetch` GLB/JSON → 校验（hash + schema）→ 卸载旧对象 → 挂新对象 → 更新碰撞与 LOD。
- **禁止**：运行时 `eval` / 动态 `import()` 任意代码 / 从网络加载可执行 JS。
- 机检：`probe-hotswap` 断言「换装前后场景对象数一致、无泄漏、帧时间不超基线 1.1×」。

### ADR-5 游戏内 Agent 可以**写代码**，但代码在**游戏进程外**执行，跨界只传数据

> **2026-11-03 修订**：原版写的是「输出必须是数据，不是代码」。用户指出「部件库缺失没关系，
> agent 直接代码构建，只要确定构建标准与交互方法即可」——这个反驳成立：
> 只要构建 API 足够，代码生成的表达力远超预烘焙部件库。真正的问题从来不是「能不能写代码」，
> 而是「代码在哪里执行」。改为下面的三段式。

**分三段，跨界只在第 2→3 段，且只传数据：**

1. **生成**（可在游戏内，也可在云端）：Agent 产出一个**构建模块** `build.ts`
   —— 它只允许调用白名单构建 API（见 ADR-8），不得 import 任何东西，不得访问 fs/net/dom。
2. **执行**（**必须在游戏进程外**）：
   - 首选：**Node 子进程 + 权限模型**（`--experimental-permission`，无 fs/net/child_process），
     或 Electron 的**隔离 BrowserWindow**（`nodeIntegration:false`、CSP `connect-src 'none'`、`worker-src 'self'`）。
   - 必须带**硬超时**（默认 180s，可用 3 分钟档）与**硬内存上限**；超时即 `terminate()`。
   - 产物：`CreationBundle`（几何 Buffer + 材质参数 + 行为/交互规格 + 碰撞 + LOD + 缩略图），**纯数据**。
3. **加载**（游戏内）：只吃 `CreationBundle`。校验 → 挂载 → 注册 LOD/碰撞 → 可回滚。

**为什么这条既满足「任意表达」又不放 RCE 进门**：
任意 JS 只在第 2 段那个**没有 fs/net/dom、有超时和内存上限**的进程里跑；
即使被 prompt 注入写坏，最坏结果是「这次生成失败」，不是「用户机器被控」。
而第 3 段永远只接收经过 schema 与预算校验的数据。

**禁止**：在渲染进程内 `eval` / `new Function` / 动态 `import()` 未签名的构建模块。

> **2026-11-03 已由上面的三段式取代**。原文「禁止 Agent 生成 TS/JS」作废。
> 预烘焙部件库（`creatures.ts` 九型、`pools.ts` 人形件、`palace.ts` 构件）的定位降级为
> **L1/L2 的快路径**（300ms / 3s 档），不再是表达力的天花板；L3 档走代码生成。

### ADR-6 双 AI 议会是**设计期**机制，运行期只保留「轻量评审」
- 设计期：两路 agent 对抗（提出/攻击/收敛），产物是 ADR 与卷册——本轮已验证有效（抓出 8 条打回 + 1 条编造）。
- 运行期：可以是玩法（用户许愿 → 两路 agent 分别起草与反驳 → 收敛成 **`build.ts` + `CreationSpec`**），但**必须设时延与成本上限**：
  - 本地小模型或规则引擎兜底，目标 ≤3s 出结果；
  - 云端大模型做「深度许愿」，≤30s 且显式提示；
  - 每会话 token 预算硬上限。

### ADR-7 性能预算前置
- 任何新增系统，先算 `ΔT_static / Δ常驻MB / ΔengineMs`，写进卷册表格；
- 合计超 `engineMs 11,451` 或 `T_static 18.96M` 的方案，**先砍再谈**；
- 当前余量：**74ms**。

### ADR-8 构建标准与交互契约（用户裁定：「确定构建标准与方法和交互方法就 OK」）

**这是 Agent 写代码的说明书。** 没有它，代码生成就是自由发挥；有了它，生成物才可能被引擎接受。

#### 8.1 构建 API（白名单，只能调这些）

| 类别 | API | 说明 |
|---|---|---|
| 图元 | `box(w,h,d,x,y,z,color,ry?,rx?,rz?)` | 与 `Baker.box` 同签名 |
| | `cyl(rt,rb,h,seg,x,y,z,color,…)` / `sphere(r,seg,…)` / `roofC(...)` | 同 `Baker` |
| | `lathe(profile[][],seg,…)` / `extrude(path[][],h,…)` / `tube(pts[][],r,seg)` | 车载曲面与扫掠，覆盖"龙身盘绕"这类形态 |
| | `isosurface(field:(x,y,z)=>number, bbox, res)` | Marching Cubes，用于无定形（液态/云雾/骨架） |
| 材质 | `material(id)`，id ∈ 现有 14 组（wood/wall/roof/ash/earth/ground/glow/leaf/trunk/water/ceramic/metal/fabric/lacquer） | **不许新建材质组**（会破合批） |
| 变换 | `at(x,y,z,ry?)` 作用域 | 递归组合 |
| 输出 | `emit()` → 返回几何缓冲 | 唯一出口 |

**禁止**：`import` / `require` / `fetch` / `fs` / `document` / `window` / `Date.now` / `Math.random`（用注入的 `rng(seed)`）。

#### 8.2 预算校验门（生成物必须先过这四关，否则拒收）

| 门 | 阈值 | 不通过的处置 |
|---|---|---|
| 面数 | 单件 ≤ 20,000 三角面（≈20 倍于当前最大兽体 952） | 拒收，回传"超预算，请降级" |
| 包围盒 | 最大边 ≤ 200m；不得含 NaN/Infinity | 拒收 |
| 内存 | 顶点+索引 ≤ 8MB | 拒收 |
| 确定性 | 同 seed 两次生成逐字节一致 | 拒收（说明用了禁用的随机源） |

**为什么是 20,000**：场上 24 只 × 20k = 480k 面，占 T_static 18.96M 的 **2.5%**；一次性生成、不与烘焙几何合并，可接受。

#### 8.3 交互契约（决定"能不能玩"，不是"能不能看"）

每个 `CreationBundle` 必须声明四件事，缺一不可：

1. **碰撞**：`collider: { kind: 'capsule'|'box'|'sphere'|'mesh', params }` → 交给现有物理；无声明则视为可穿过的装饰物。
2. **可交互**：`interact: { verb: '骑'|'采集'|'对话'|'攻击'|'无', range: m, poi?: id }` → 接入 `src/game/interact.ts` 的拾取路径。
3. **行为**：`behavior: { kind: 'static'|'patrol'|'follow'|'fly'|'swim', params }` → 接入 `src/actors/behaviors.ts`；**必须走 `walkSurfaceY` 落地**（天宫需走 `heavenY`，见 ADR-1）。
4. **生命周期**：`lifecycle: { ttl?: s, persist: bool }` → 决定是否进存档；`persist:false` 的生成物不得写入存档，避免存档膨胀。

#### 8.4 产物 schema（`CreationBundle` v1）

```jsonc
{
  "schema": "creation/1",
  "id": "gen_20261103_0007",
  "prompt": "我要一条龙",
  "seed": 20261103,
  "modelVersion": "…",
  "geometry": { "positions": "<base64|bin>", "normals": "…", "colors": "…", "indices": "…" },
  "materials": ["metal", "glow"],
  "collider": { "kind": "capsule", "params": { "r": 1.2, "h": 6 } },
  "interact": { "verb": "骑", "range": 3 },
  "behavior": { "kind": "fly", "params": { "speed": 6, "altitude": 12 } },
  "lifecycle": { "persist": true },
  "budget": { "tris": 1840, "bytes": 421000 },
  "hash": "sha256:…"
}
```

**加载协议**：`hash` 不符即拒；`schema` 版本不符走迁移或拒；加载失败**必须回滚到上一状态**（保留旧对象直到新对象就绪）。

#### 8.5 一句话总结

**「构建标准」= 8.1 的 API + 8.2 的门；「交互方法」= 8.3 的四条声明。**
这两样定死之后，Agent 写什么代码都行——**它只能产出这四类东西，引擎也只认这四类东西。**

### ADR-9 本体必须改动：这不是外挂，是第一方子系统

> **2026-11-03 用户判断**：「游戏本体需不需要改动？我认为需要的，毕竟要加一个 agent 外挂」。
> **判断正确，但「外挂」这个词不成立。** 真正的外挂能零侵入；这里做不到——见下面四条实测阻塞。

#### 9.1 四条「零改动不可能」的硬证据（均已 grep 核实）

| # | 位置 | 现状 | 后果 |
|---|---|---|---|
| ① | `electron/main.cjs` | **没有 `preload`、没有 `ipcMain`**，`webPreferences` 只有 `contextIsolation:true, nodeIntegration:false`（无 `sandbox:true`、无 CSP） | 渲染进程**没有任何 IPC 通道**，无法请求主进程启动沙箱构建器 |
| ② | `src/core/engine.ts:150` | `class LodManager` 只有 `register(spec)`（`:189`），**没有 `unregister`** | 运行时生成的对象**无法摘除**，只能标记 orphan；反复许愿会累积泄漏 |
| ③ | `src/actors/behaviors.ts:127` | `ensureWalkSurface()` **无参数、一次性**构建 4m 空间哈希 | 新增可站立物体（骑龙、可登的建筑）**无法局部重建**，只能全量重建或悬空 |
| ④ | `world.ts:713` / `expansion.ts:300` | `compactStatic` 只合并 `city_*`，`scaleHeavenGeometry` 只变换 `city_*` 与 `sky_cloudSheets` | 生成物若命名不当会被合批或二次缩放；**命名即协议**，必须新前缀 `rt_` |

#### 9.2 本体改动清单（按依赖排序）

| 序 | 文件 | 改什么 | 不改的后果 |
|---|---|---|---|
| 1 | `electron/main.cjs` | 加 `sandbox:true`、CSP；注册 **3 条白名单 IPC**（`wish:build` / `wish:status` / `wish:cancel`）；spawn 构建器并限制 fs/net | 整条链路没有起点 |
| 2 | `electron/preload.cjs`（**新建**） | `contextBridge` 暴露上述 3 个方法，别的一概不给 | 渲染进程只能干瞪眼 |
| 3 | `src/core/engine.ts` | `LodManager` 加 `unregister(id)` 与运行时 `register` 入口 | 对象删不掉，内存只增不减 |
| 4 | `src/actors/behaviors.ts` | `ensureWalkSurface` 加**局部失效/重建**入口（按 AABB 脏区） | 新物体要么悬空、要么全量重建卡 80ms+ |
| 5 | `src/world.ts` | 新增 `runtimeAssets` 注册表（id → Object3D + collider + behavior + lifecycle）；导出 `addRuntimeObject/removeRuntimeObject` | 没有任何地方知道"场上有哪些生成物" |
| 6 | `src/game/physics.ts` / `interact.ts` | 动态 collider 集合；拾取时识别 `interact` 声明 | 生成物"看得见摸不着" |
| 7 | 存档 | 新增 `runtimeAssets` 段 + 版本迁移；`persist:false` 不入档 | 存档会无限膨胀，且老档打不开 |
| 8 | `src/ui/` | 许愿面板（输入 / 进度 / 取消 / 回滚） | 用户没有入口 |
| 9 | `package.json` / 打包 | 沙箱构建器随包分发 | 打包态没有构建器可调 |

#### 9.3 与「不可改」的边界

- **不改**：载入期烘焙链（`Baker`/`flush`/`compactStatic`/`scaleHeavenGeometry`）、14 个材质组、`T_static` 的构成。
- **只加不改**：以上 9 项全部是**新增**（新文件 / 新方法 / 新字段），不改既有函数签名语义。
- 唯一例外：`ensureWalkSurface` 需要加可选参数（向后兼容，旧调用不变）。

#### ADR-5 附注：沙箱能力边界（D5/D6 本机实测，2026-11-03）

| 隔离手段 | 实测结果 | 结论 |
|---|---|---|
| `node --experimental-permission` | fs 读越界返回 `ERR_ACCESS_DENIED` | ✅ 文件系统确实拦住 |
| 同上 | **`http` / `net` / `fetch` 全部仍然可用** | ❌ **网络没拦住** |
| 同上 + `--allow-worker` | worker **可读目录外文件** | ❌ 开 worker 就漏 |
| `--max-old-space-size=32` | **320MB typed array 照样分配** | ❌ 堆上限管不住 ArrayBuffer |
| Electron-as-node 子进程启动 | p50 **63.9ms** | ✅ 启动成本可接受 |

**因此 ADR-5 的三段式必须加两条硬措施，否则「沙箱」名不副实：**

1. **网络**：`--experimental-permission` 不管网络 ⇒ 必须叠加 **OS 级**手段（Windows Job Object / 防火墙规则 / 无网容器）或**进程级 DNS 黑洞**；仅靠 Node 权限模型不够。
2. **内存**：`--max-old-space-size` 不管 `ArrayBuffer` ⇒ 必须**在产物侧卡死**（`CreationBundle` 大小 ≤8MB，由 `probe-creation-bundle` 校验），并在子进程侧限制单次分配。
3. **worker**：不开 `--allow-worker`；若必须开，则 worker 内同样禁止 fs。

**这条附注把「安全」从口号变成了实测边界**：原来写「无 fs/net」是乐观假设，现在知道 net 是漏的。

### ADR-11 产品定义变更：从「叙事游戏」改为「创造沙盒」

用户第 3 条裁定（「玩家创造世界创造万物」）**改变了产品类别**，不是加功能。

**这条裁定反转了三处优先级：**

| 项 | 叙事游戏里的位置 | 创造沙盒里的位置 |
|---|---|---|
| **存档层** | 锦上添花（重开就重开） | **地基**。玩家创造的万物必须存得住、跨版本能打开。审核 A 已指出「存档层不存在、localStorage 装不下 28.7MB」 |
| **动态碰撞** | 可延后（方块只是视觉） | **地基**。放下的方块与生成的造物必须有实体，否则"创造"是假的。审核 A 已指出 `groundHeight()` 纯解析式 |
| **三套编辑器（建造/造物/许愿）** | 三个子系统 | **产品本体**。它们不是玩法之一，它们就是玩法 |

**随之降级或作废的项：**
- 审核 B 指出的「17/17 = 17 次点击」——在创造沙盒里，观光点只是**引导线**，不是关卡设计缺陷。**不修**。
- 「三条成长线不相交」——在创造沙盒里，玩家不需要三条线同时推进；**取舍自由**本身就是设计。**不修**，但需要一条**统一资源轴**（造物↔建造↔解锁）作为工具间的公共货币。
- 「30 分钟循环」——不再要求线性循环，改为**工具可用性**指标（首次造物成功用时、建造完成率）。

**风险提示（一句话，不阻塞）**：创造沙盒 + UGC 分享 + Steam，必然撞上**用户生成内容的审核义务**（违法/色情/侵权）。
用户已裁定「不考虑合规」，故不排期；但**开放分享功能之前**必须回头处理，否则是平台侧下架风险，不是自选项。
