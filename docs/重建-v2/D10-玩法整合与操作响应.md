# D10 玩法整合与操作响应

> **本卷服从 D0《重建纲领》的 ADR-1、ADR-2、ADR-3、ADR-4、ADR-5、ADR-7、ADR-8、ADR-9。** ADR-6 不直接约束输入层，但它的运行期档位（≤3s / ≤30s）经 D5 落进本卷的 L2/L3。凡与 ADR 冲突以 ADR 为准；本卷只细化，不改裁决。行号基线：工作树 `806fa79`（v93）+ v96 未提交改动，**未锁 commit**，行号只作线索。
>
> **一句话结论**：三套玩法的输入冲突不是"将来可能"，而是**代码里已经发生**——一次单击同时触发锁指针、出拳、聚焦英雄（§1.2）。`frameP95 = 50ms` 也压不到 16.7ms；本卷不假装压到，而是把"手感"从"帧率"里拆出来，用三条可测指标替代一条会被截断的指标（§2.7）。

## 0. 复述裁定与边界

### 0.1 八条 ADR 对输入层的约束

| ADR | 要求 | 落点 | 改动 |
|---|---|---|---|
| ADR-1 | 坐标唯一真相源 | 建造吸附调 `heavenY()`/`heavenPoint()`，输入层不自算坐标 | 不改 |
| ADR-2 | 运行时几何只能追加，前缀 `rt_` | 建造/造物预览是运行时几何：world 坐标 + 包围球 + 注册 LOD，前缀 `rt_prev_` | 新增前缀 |
| ADR-3 | 模拟路径零墙钟、零随机 | 输入采样进固定步；`player.ts:259` 现在用 `performance.now()`（§1.7） | 登记缺口 |
| ADR-4 | 打包态只有资产热替换 | 加载生成物只能表现为 L2，不能"卡一下然后出现" | 不改 |
| ADR-5 | 代码在进程外执行，只传数据 | 许愿的 3 分钟是 **L3**，UI 不得伪装成 L0/L1 | 不改 |
| ADR-7 | 新增系统先算 Δ | 路由与 UI **Δdraw = 0、ΔT_static = 0**；§2.2 的 pending 层若采纳另记 **+5 draw**（已登记） | 遵守 |
| ADR-8 | 交互契约四声明 | `interact.verb`（骑/采集/对话/攻击/无）就是叙事侧的操作面 | 引用 |
| ADR-9 | 本体必须改动 | 输入归口属于 §9.2 第 8 项（`src/ui/`）同批，并新增"第 10 项 `src/input/`" | 新增依赖 |

ADR-9 的九项改动里没有任何一项负责"输入归口"。九项做完，玩家仍面对五套 keydown（§1.1）——这是三套玩法能否共存的前提。

【实测】有 release 与探针可复现｜【代码】由常量与算式推出｜【推算】按明确公式外推、未跑过｜【待验证】设计假设。

### 1.2 一次单击触发三件事（可复现）

同一 canvas 的 `pointerup` 被三个模块订阅，判据阈值完全相同（6px）：

1. `engine.ts:659` 位移 <6px → **锁指针**；
2. `player.ts:181` 位移 <6px 且 avatar → **出拳**；
3. `ui.ts:424` 位移 >6px 直接 return，否则遍历 165 名英雄做屏幕投影，34px 内 → **聚焦并弹信息卡**。

所以每一次"干净的单击"都同时锁视角、出拳、弹卡。玩家想打一拳，结果视角锁了、卡片盖住屏幕；按 `Esc` 关卡片，`ui.ts:95` 又会关掉所有面板，浏览器同时退出指针锁——一次操作退两层。

这不是三套玩法叠加后才出现的风险，**当前版本就有**。三套玩法只是把三选一变成五选一。

### 1.3 输入模式状态机

模式是**栈**：底层（base）一个，上层（overlay）可叠。理由是"许愿面板打开时人还站在人间"，底层必须继续存在。

| 模式 | 类型 | 守卫 | 谁拥有输入 |
|---|---|---|---|

| `avatar` 附身 | base | `state==='foot'` 按 `V` | `PlayerController.update` |
| `build` 建造 | base | human 阶 **且** 在沙盒 AABB 内（D3 §1.1） | 建造控制器 |
| `create` 造物编辑器 | base | `realm==='human'`（D4 §2.2） | 编辑器控制器 |
| `talk` 对话 | overlay | 最近交互点 `verb==='对话'` | 对话控制器，**冻结移动、保留相机** |

### 1.6 路由器：单一入口 + consumed 协议

```ts
dispatch(e):
  1. 从栈顶往下找第一个声明消费此键的 context
  2. 命中 → handler 返回 true 则 preventDefault + stopPropagation
  3. 全未消费 → 落全局表（F1/F12/Esc）
  4. 仍未消费 → 丢弃，不冒泡到 window
```

三条规则：**`repeat` 逐 binding 声明**（移动/连放 true，`V/E/F/K/Y` false，这是修"按住 V 翻转"的唯一办法）；**单击只允许一个消费者**（锁指针改双击或 `L`，因为单击语义已被占满）；**`preventDefault` 集中一处**（现状只有 `F1` 调了，`Tab` 一进来就暴露）。

派发成本 3–8 次表查找 **<1µs**【推算】，相对 16.7ms 可忽略。价值不在快，在**冲突可枚举、可静态检查**（A6）。

不复用一套全局 keymap 的原因是可判：全局表只能表达"这个键归谁"，不能表达"在这个模式下这个键归谁"；而 14 处冲突里有 9 处是**同键不同模式**，全局表会强行二选一。

### 1.7 输入采样与 ADR-3 的缺口

玩家移动是每帧 `dt` 积分（`player.ts:249-407`），不是固定步；而 `physics.ts:73` 的 `ImpactSystem` 已有 `FIXED_DT = 1/120` 与 `MAX_SUBSTEPS = 16`——模式在项目里存在，只是玩家没接。

更实的一条：`player.ts:259` 与 `:208` 用 `performance.now()` 判 `busy`，而 `probe-determinism.mjs:27-31` 的 `SIM_FILES` 只列 `physics.ts`/`behaviors.ts`/`crowd.ts`，**不含 `player.ts`**。所以门是绿的，但玩家位置是最需要可复现的状态之一。这是**清单缺口，不是门禁缺陷**；加进去的那天这两处墙钟会变红，那是预期。本卷不改，因为 `player.ts` 与 `probe-determinism.mjs` 属 D1 领土。

## 2. 操作响应预算

### 2.1 四级定义

| 级 | 上限 | 判据 | 允许的实现 | 必须有的 UI | 可取消 |
|---|---|---|---|---|---|
| **L0** | **≤1 帧 16.7ms** | 输入被读到、状态改变，画面下一帧反映 | 同步、无 IO、无分配 | 无 | 不适用 |
| **L1** | **≤100ms** | 操作完成且可见 | 一次 DOM 更新 / 一次上传 | 无进度条，可 120ms 淡入 | 不需要 |
| **L2** | **≤3s** | 完成或给**阶段进度** | Worker / async fetch / 模型 | 阶段名 + 已用时 + 取消 | **必须** |
| **L3** | **≤180s** | 完成、失败或超时，**必发生其一** | 子进程（ADR-5） | 上述 + 失败原因 | **必须，且可杀** |

L0 的边界条件必须写死：**"1 帧"指 16.7ms 的目标帧预算**；当实际帧是 50ms 时，L0 的绝对上限退化为"1 个实际帧"。不写这句，A2 不可判。L2 与 L3 的分界不是时间，是**是否需要杀进程**：L2 取消是 abort Promise，L3 是 `SIGKILL`（D5 §1.1）。

### 2.2 逐操作归类

| 操作 | 级 | 目标 | 现状 | 依据 / 冲突 |
|---|---|---|---|---|
| 视角转 | L0 | 下一帧 | `dragLook` 同步改 yaw | `engine.ts:728` |
| 移动 | L0 逻辑 / ≤2 帧画面 | 16.7 / 33.3ms | 每帧读 `keys` 积分 | `player.ts:262-276` |
| 跳跃 | L0 | 按下帧内 `vy=7.5` | `update` 内读 `Space` | `player.ts:391` |
| 攻击起手 | L0 起手 / L1 结算 | 16.7 / 100ms | `F`/左键 → `attackHook` | Boss 冷却 0.28s（`data/boss.ts:42`） |

**必须正面写的卷间冲突：放置 300ms vs L1 100ms。** D3 §1.7 把"敲掉一格"写成 标脏 → 300ms 去抖 → Worker 27.6ms → 上传 1.6ms，理由是"碰撞已立即更新，属挖掘手感"。这对**连挖**成立，对**单放**不成立：玩家放下一块砖，300ms 看不到，只会认为"没放上"。

本卷裁决（对齐项，不推翻 D3）：

- **单发走 pending 层**：沙盒内维护极小动态网格 `rt_prev_<sandbox>`，只装本次未合并的新面；按下一帧就画（L0），300ms 后重建完成、pending 清空、实体接管。代价：窗口内每个活跃沙盒 +1 draw（≤5）。
- **连发仍走 300ms 去抖**，pending 累积到 64 quad 或松手强制提交。
- **拆除不适用 pending**：删一块要露出内部六面，不是加 quad 能伪造的，所以拆除视觉**就是 300ms**，归 L2。补偿是按下当帧给粒子、音效、邻面裂纹（L0），让"已生效"在 16.7ms 内被感知。
- Δ 账：`+5 draw`（对 D7 §1.4 的 228 是 2.2%）；pending 不计入 `T_static`（ADR-2）。

同一个 300ms，放在连挖上是节奏，放在单放上是失灵——这就是为什么手感不能只看一个数字。

另有一条与 D5 的接口：许愿的 `tier` 必须在 P1（200ms）结束时**告知玩家**，否则玩家不知道自己要等 3 秒还是 3 分钟。档位是响应分级的前提，不是结果。

### 2.3 50ms 换算成手感：三个算例

【代码】，逐位可复算。

**① 跳跃的空中窗口被吃掉 7.3%。** `vy=7.5`、`g=22`（`player.ts:391/387`）⇒ 滞空 `2×7.5/22=0.682s`，最高 `7.5²/(2×22)=1.28m`。50ms 是滞空的 **7.3%**，"跳上台子"的容错本来就只有几十毫秒。

**② 连击节奏被吞掉 17.9%。** Boss 冷却 `0.28s`（`data/boss.ts:42`）。50ms 是冷却的 17.9%；落在冷却尾部的输入被 `if (this.cd>0) return false`（`boss.ts:92`）**静默丢弃**——没反馈、没音效、没提示。这才是"发飘"的直接来源：不是动作慢，是**动作被吞且不告知**。

**③ 走位位移 0.18–0.41m。** 步行 3.6、疾行 8.2 m/s（`player.ts:33-34`）⇒ 50ms 对应 0.18m 与 0.41m。在 0.5m 体素格上，0.41m 已接近一格。

三例共同点：**50ms 的伤害在"吞输入"，不在"慢"。** 修复方向因此不是"每帧都压到 16.7"，而是"即使这帧是 50ms，也让玩家知道收到了"。

### 2.4 p95 的口径有三处缺口（含对 D7 的订正）

**① `frameMax = 100ms` 是截断值。** `engine.ts:752`：`dt = Math.min(0.1, Math.max(0, …))`，随后 `frameMs.push(dt*1000)`、`maxFrameMs` 取的也是夹过的 `dt`。所以 `frameMax` 的**理论上限就是 100**；读到 100 只意味着"至少一帧 ≥100ms"。历史上那次"高空 2160ms"是 `probe-prewarm` 自带采样器测的，两边不矛盾但**不能互引**。

**② 窗口是冷的，且样本量未记录。** `frameMs` 是 600 帧环（`engine.ts:754-756`），只在 `start()` 里 push，而 `start()` 在 `world.init()` 之后（`main.ts:36`）；`verify-packaged.mjs:78` 在加载层消失后 `sleep(2500)` 才读。关键是**读数时刻的缓冲长度不确定**：若在 2.5s 读，60fps 下只有约 150 帧，全部落在载入后头 2.5s（着色器首编译、LOD 首落档、可能的第一次降档）；若 `readInfo` 因渲染忙重试到 10s 之后，缓冲才满 600 帧、窗口变成"最近 10s"。**150 帧与 600 帧的 p95 不是同一个统计量**（前者取第 8 大，后者取第 31 大），而 v96 的记录里没有帧数。

**③ 不记录 GPU 后端。** `verify-packaged.mjs:27` 只有 `--no-sandbox`、`--disable-gpu-sandbox`，未读 `UNMASKED_RENDERER_WEBGL`。同一份包在独显、核显、SwiftShader 上的 50ms 不是同一个 50ms。

**对 D7 §0.3 的订正**：D7 写"`frameMs.shift()` 写了两遍，窗口实际是 599 帧"。逐句推：push 后 601 → 第一次 shift 变 600 → 第二次 `if (600>600)` 为假，**不执行**。所以窗口是 **600**，那行是死代码，不是偏移；D7 由此推出的"影响约 0.17%"也不成立（影响 0）。不影响 D7 结论，但依据要改。

三处缺口合起来说明：**"50ms"目前只能定性为"存在尾部卡顿"，不能归因到任何系统。** 本卷不替它编原因。

### 2.6 六条削减项（含两条明确否掉）

收益一律【推算】。

**S-A 交互提示"变了才写" + 8 帧节流。** `interact.ts:243-266` 现在每帧写 `textContent` 与 `classList`。改成缓存上次字符串 + `frame & 7` 节流（照 `poiGuide.ts:45`）。收益：主线程 −0.3～1.5ms/帧，且它是 T3"隐藏提示"的天然载体。验证：A4 的 MutationObserver + H4 的 A/B。风险：提示最多晚 133ms，可接受。

**S-B 小地图分层 + 降频。** `ui.ts:348-392` 4Hz 全量重绘，`:377` 每次调 `heroEntries()`，后者每次 `filter().map()` 生成 165 个新对象（`world.ts:1602-1608`）⇒ **660 对象/秒**。改：静态底图一次性画进离屏 canvas，动态层 2Hz，英雄坐标原地更新。收益：单次 −2～4ms、分配 −660/秒。验证：`byGCDrop`。风险：0.25s→0.5s，感知不到。

**S-C `#stats` 分字段、1Hz。** `ui.ts:408` 每 0.5s 用 `innerHTML` 重建整块，同一次还调 `liveCount()` = 对 `crowd.actors` 全量 `filter`（其非隐藏计数 v96 为 4,495，`world.ts:1610`）。改：三个 `<span>` 各自 `textContent`、值不变不写、1Hz、计数用维护值。收益：每次 −0.2～1ms、分配 −4,495 元素/次（下界）。验证：同 S-A（值不变时 `#stats` 的 `childList` 应为 0）。风险：无。

**S-D `followCam` 去分配。** `player.ts:409-417` 每帧 `new Vector3`×3 + `clone()`×2 ⇒ **300 次/秒**【代码】。改模块级 tmp（`engine.ts:413-416` 已有范式）。收益：若 H1 成立，这条可能最大。验证：`performance.memory` 曲线 + GC 计数。风险：零，注意别嵌套复用 tmp。

**S-E 自适应降档"只降不升"并移出测量窗口。** `engine.ts:558-587`：`avg>30ms` 降、`avg<15ms` 连 4 次升，每次 `applyQuality` 都 `onResize` + `shadow.map.dispose`。改成载入期定档、运行期只降不升（升档只在回主菜单/传送后），并把每次切换记进 `__qualityChanges[]` 供探针剔除。收益：消除每会话 1–2 次 50ms+ 尖峰。验证：`byQualityChange` 必须为空。风险：设备变快不会自动变好，设置面板有手动画质（`ui.ts:296`）。

**S-F 目标链事件驱动 + 2s 兜底。** `ui.ts:415` 的 0.4s 轮询是冗余的（`objective:done` 已存在）。改成事件 + 2s 兜底。收益：−2.5 次/秒 的 `renderGoal()`，目标行延迟 400ms → ≤16.7ms。验证：`objective:done` 事件时刻与 `#goalMain` 文本变更时刻之差，采样 50 次取 p95。风险：外部直接改写目标时最多晚 2s，可接受。这是 L1 达标的必要项。

**五条削减的收益不能相加。** S-A/S-B/S-C/S-D 作用在同一段主线程时间上：删掉了 DOM 写入，就不能再把"少了 DOM 写入"算进 GC 的收益里。可分属不同资源的只有两类（S-D 的分配 → GC，S-E 的切档 → 尖峰）。所以本卷只给单条收益，不给合计——合计必然高估，而高估的预算会变成下一次返工的理由。

**两条明确否掉：**

- **`renderer.info` 读取不是成本。** `engine.ts:794-795` 是两个属性读取，`info.reset()`（`:783`）是计数清零，O(1)。删它换不来一帧，只会让所有 draw 断言失去数据源。
- **减小地图画布不是成本。** 216×150 只有 32,400 像素（`ui.ts:60`），4Hz 光栅成本远小于一次 DOM 布局。成本在 JS 侧（165 次投影与分配），不在画布。

### 2.7 压不到 16.7ms 时的降级设计

**本卷不承诺 `frameP95 ≤16.7ms`，也不假装可达。** 理由是算术：backbuffer `1982×1078×2² = 8,546,384` 像素【代码，`engine.ts:27` + v96 的 `canvas [1982,1078]`】，渲染链 4 个 pass（`engine.ts:513-526`）。把 p95 压到 16.7 等价于"95% 的帧一次 vsync 都不掉"，杠杆在像素与几何预算，不在输入层；而这两样的改动属 D7 §3.1 的"内容变更"，需 lead 裁定（U1）。

**所以拆成三条可测指标，替代一条会被截断、且混入 vsync 量化的指标：**

| 指标 | 定义 | 目标 | 为什么它才是手感 |
|---|---|---|---|
| `inputToLogicMs` | handler 内 `performance.now()` → 模拟状态改变 | **p95 ≤16.7ms** | 只受主线程占用影响，不受 GPU 影响 |
| `inputToPhotonMs` | 同上 → 屏幕可见 | **p95 ≤100ms** | 含渲染与合成，是玩家真正感知的一段 |
| `inputQueueDelayMs` | `performance.now() - e.timeStamp` | **p95 ≤16.7ms** | **直接量出"主线程被占住导致输入排队"** |

第三条是本卷的核心论点：**一帧 50ms 的真正伤害不是"画面晚 50ms"，是"这 50ms 里主线程不处理输入"。** 浏览器在主线程忙时不派发事件；`e.timeStamp` 是事件产生时刻，`performance.now()` 是 handler 跑起来的时刻，差值就是排队时间。它比 `frameP95` 更接近玩家说的"发飘"。

**降级四层：**

**第一层：判据前置，几何后置。** 三套玩法里所有"**允不允许**"必须在 L0 同步完成，只有"**长什么样**"允许异步。放置：结构三判据（支撑链 / 悬挑 ≤2.4m / 倾覆 ≥0.15，D3 §2.3）是 O(子树) 浮点，三开间殿 40 节点 ≤40 次运算，任何机器 <0.1ms——**能否放置按下当帧就知道**，被拒就红框 + 音效，绝不"先显示后消失"。造物：面数门禁 1,400、槽位合法性、`girth/legLen` 范围全是查表与加法。许愿：置信度与越界是 200ms 预算，但"是否受理"必须 200ms 内回执。

**第二层：预测只用在可回滚处。** 可预测：移动、视角、跳跃起跳、攻击起手动画、预览体变换。不可预测：方块实体化、构件提交、阶位切换、许愿落位。判断标准只有一条：**预测错了要不要道歉**，要道歉的不许预测。

**第三层：异步操作的"已接收"回执。** 所有 L2/L3 在按下的那一帧必须给三种反馈之一：音效（WebAudio 可精确调度）、准星脉冲、目标格高亮。这不是补偿动画，是**把"收到"与"完成"分开告知**。反面例子就是 §2.3 ②：冷却期点击被静默吞掉。

**第四层（不做）：不把 UI 做成"乐观成功"。** 不许"先画成实体、100ms 后发现被拒再撤回"——撤回比等待更伤信任，玩家会记住"东西自己消失了"。

### 2.8 一帧内的预算分配

设计目标，**未实测**，用 `frameJsMs`/`frameRenderMs`（`engine.ts:428-429`）验证：

| 段 | 目标 | 说明 |
|---|---:|---|
| 输入派发 | ≤0.2ms | 3–8 次表查找 |

## 3. 反馈与容错

### 3.1 每个 L2/L3 的五要素

| 操作 | 进度 | 可取消 | 失败原因 | 可重试 | 可撤销 |
|---|---|---|---|---|---|
| 许愿·模板（L2，≈700ms） | 四段：解析 200 / 构建 150 / 预算门 50 / 落位 300 | 是（段边界） | `E_INTENT_LOW_CONF`、`E_GATE_*`（D5 §1.5） | 同参数 1 次（seed 固定，幂等） | 删 `rt_` 并恢复旧对象 |
| 许愿·代码（L3，≤180s） | 五段 + 已用时，**不给百分比** | 是（`SIGKILL`） | `E_HARDKILL`、超内存、非 JSON | 第 2 次必须换参数或降档 | 同上（P5 原子回滚） |
| 造物装配（L2，≤300ms） | 单段，无进度条，120ms 淡入 | 否（太短） | `E_BUDGET`、`E_PART_INCOMPAT`（D4 §1.5） | 改一个槽再试 | 保留上一份 spec |
| 进入沙盒（L2，≈21ms+300ms） | 无进度条，0.25s 遮罩（D3 §1.6） | 否 | Worker 失败 → 回退高度场 | 是 | 不适用 |
| 热加载（L2，42–264ms） | 四段：fetch/校验/装配/挂载（D7 §2.4） | 是（fetch abort） | hash、schema、帧超 1.1× | 是 | **必须**：旧对象留到新对象就绪 |
| 跨阶（L2，460ms+结算） | 单段 | 否（不可逆） | 阈值不足 → 事前拦截 | 否 | 否（D4 §2.4） |

**进度必须阶段式。** P2 预算是 150ms（模板）到 120s（模型），跨度 **800 倍**【代码，D5 §1.1】；线性百分比在这条路径上必然撒谎。**取消只在段边界生效**：P4（50ms）与 P5（300ms）比取消动作本身还短，强行中断只会留下半挂载，所以按钮置灰并写"正在完成最后一步"。

### 3.2 三套玩法切换的状态保持

| 状态 | 切模式 | 切阶位（D4 §2.4） | 依据 |
|---|---|---|---|
| 已提交建造（`editTx`） | **保留**（是数据） | **留在原界** | D4"坐骑/宠物留在原界"的同构推论 |
| 未提交预览 | **显式丢弃 + 报数量** | 丢弃 | 静默保留会"切回来突然多出东西" |
| 造物草稿 | **留内存 + 角标**，不写 localStorage | 保留 | 半成品不入库，避免污染蓝图库 |
| 蓝图（已 validate） | 保留 | **100% 保留** | D4 §2.4 |
| 目标链 | 保留（world 状态） | 保留 | — |
| 输入缓冲（按住的键） | **清空** | 清空 | 否则切模式瞬间的 W 会在新模式继续生效 |

**"建筑留在原界"必须写死**，否则会出现"人道的房子跟着亡魂进地府"，且 D3 §3.5 情形 B 的"先拆 XX"会指向不在当前界的对象。

### 3.3 三类静默失败必须显式化

1. **建造被结构判据拒**（`E_UNSUPPORTED`/`E_OVERHANG`/`E_OVERTURN`）：红框 + 一行原因 + 音效。
2. **造物被面数门禁拒**（`E_BUDGET`）：显示"1,412 面 / 上限 1,400，超 12 面"并指出最重的槽，只说"超预算"等于没说。
3. **许愿超时**（`E_HARDKILL`）：区分"你的机器慢"（给重试）与"模型写了死循环"（给换说法）。

一条纪律：**乐观 UI 只用于可回滚的操作**；跨阶、删蓝图、清空沙盒必须先进确认态，且确认态本身不能有淡出动画（会被误读为"已执行"）。

### 4.2 z 序与安全区

| 带 | z | 内容 | 规则 |
|---|---|---|---|
| 世界 | 0 | canvas | — |
| 常驻 HUD | 10–19 | 顶栏、dock、小地图、三币 | 始终可见 |
| **上下文 HUD** | **20–29** | hotbar、配额条、造物槽位、准星 | 只在模式内可见 |
| 面板 | 30–49 | 图鉴/传送/设置/帮助/交互 | 同时最多两个（左右各一） |

**安全区**：上 `y < topbar 高`（按 **44px** 预算【推算】）；下 `y > H − dock 高 − 14`（按 **72px** 预算【推算】）；右 `x > W − 230`（216 + 14）。新增建造/造物 UI 只能落在中间带 `y∈[44, H−86]`、`x∈[0, W−230]`。hotbar 是例外：它必须贴 dock 上方，所以规则改成"hotbar 出现时 dock 上移，或 hotbar 覆盖 dock 下半"，二选一由 D9 定。

### 4.3 不遮挡三条规则与机检

1. **常驻带不可侵入**：新增常驻元件不得与 `#topbar`/`#minimap`/`#dock` 的 boundingRect 相交。
2. **模态必须遮罩**，不透明度 ≥0.55。理由不是美观：半透明面板叠在 4,600 万面上，文字对比度无法保证。
3. **一次最多一个模态**：需要"在许愿里再确认"时，确认框**替换**许愿面板，不叠加。

**机检**：`probe-hud-occlusion.mjs`【待建】，3 分辨率（1280×720 / 1920×1080 / 2560×1440）× 4 模式（avatar/build/create/wish），读所有可见 HUD 的 `getBoundingClientRect()` 两两求交。判据：常驻三元与新增元素交面积必须为 **0**；允许集只有白名单（面板×面板、toast×任意 ≤2.6s、info×prompt 当前**不允许**，是待修项）。

### 4.4 无障碍

**① 色觉。** 语义色三套：`--cyan` 交互 / `--gold` 目标 / `--magenta` 玩家（`style.css:3-4`）。问题不在配色，在"只用颜色编码状态"：建造的可放置/不可放置若只做红绿，红绿色盲会失去唯一信号。规则：状态必须**颜色 + 形状**双编码。机检：截图的 deuteranopia 变换后两态**平均亮度差 ≥15%**。这个 15% 是本卷定的，**无标准依据**，可调。

**② 字号。** 现状 `.hint` **11px**（`:96`）、`#stats` 12px（`:41`）、`.dock-btn` 13px（`:49`）、`#interact-prompt` 14px（`:133`）。规则：正文 ≥12px、可操作 ≥14px。并提供 1.0/1.25/1.5 三档缩放——现在全是硬编码 `px`，改 `html{font-size}` 无效，须先引入 `--ui-scale` 并改 `calc()`（D1 的改动）。

**③ 键位自定义。** `localStorage['cq_keymap']`，与 `cq_coins`/`cq_yinde`/`cq_peach`（`interact.ts:31-33`）、`cq_builds`（D4 §6.3）同一命名空间。重绑必须做**同上下文冲突检测**：同一 `code` 映射到两个 action 即拒绝并提示冲突方，不允许后者覆盖。

**④ 动效与焦点。** `prefers-reduced-motion` 下关闭目标闪字、toast 淡入、相机 `lerp`（`player.ts:415-416`），**但不关闭状态变化本身**——没有动画不等于没有反馈。`style.css` 全文无 `:focus` 规则，补 `:focus-visible{outline:2px solid var(--cyan);outline-offset:2px}` 是零成本。

**不做手柄**：无输入路径、无图标、无焦点导航，三件事都要重做。

## 8. 自认最弱的三段

1. **§2.5 与 §2.6 全是候选，不是结论。** 我没跑过 `probe-frame-attrib`，"50ms 来自 GC / 降档 / 阴影 / HUD"四条说法**一条都没有证据**。我给的是可证伪的实验设计。如果 H1 不成立，S-A/S-B/S-C 加起来可能只有 1–2ms，对 p95 毫无影响——**本卷的削减项有可能一条都不解决问题**。这句必须留在正文，不能藏进附注。

2. **§1.5 的键位裁决是设计判断，没有用户测试。** 三条与主流肌肉记忆冲突：`Tab` 当背包（MC 是 `E`）、`Shift` 在建造下反向、左键锁指针改双击。理由成立不等于玩家能接受，真正的验证要 20 人以上可用性测试，本卷没条件做。实装后若玩家说"按 E 打不开背包"，那不是 bug，是这条裁决错了。

3. **§4.4 的 15% 亮度差阈值是我定的，没有标准依据。** WCAG 有对比度标准（正文 4.5:1、大字 3:1），但"CVD 模拟下两态亮度差"没有现成阈值。15% 是"能看出区别"的经验值，写进断言是为了让它**可被推翻**。同理 §4.3 的"遮罩不透明度 0.55"也是审美判断。

**一条不算在三条内、但必须写在交付前的风险**：本卷所有响应目标（L0 ≤16.7ms、L1 ≤100ms）都以"主线程不被长时间占用"为前提，而这个前提**现在不成立**——v96 的 p95 是 50ms，意味着每 20 帧就有一帧占掉 3 个 vsync。所以 §2.1 的分级表在当前包体上有一半条目天然达不到，不是设计错，是 §2.5 的归因还没做。**它是"应该达到的样子"，不是"现在达到的样子"。**
