# D9 UI/UX 与交互

> **本卷服从 D0《重建纲领》的 ADR-4、ADR-5、ADR-6、ADR-7，以及 §3 写作纪律第 4 条（禁止跨卷许诺）。**
>
> - **ADR-5（代码在进程外执行，跨界只传数据）**：决定「3–5 分钟」这个时长从哪来——它只可能来自**沙箱构建档**（180s 硬超时 + 排队 + 校验 + 加载），不是普通许愿。本卷的进度 UI 因此必须能覆盖 0.3 秒到 5 分钟四个数量级，而不是一套「转圈」打天下。
> - **ADR-6（运行期只保留轻量评审）**：决定 3s / 30s 两档的上限是**产品约束**，不是性能目标。UI 必须在 30s 档**先问再等**，不允许默默转 30 秒。
> - **ADR-4（打包态只有资产热替换）**：决定「撤销」只能是**数据层回滚**（几何、碰撞、LOD、存档），不能指望 HMR 或重新加载页面。
> - **ADR-7（性能预算前置）**：决定进度条本身也要过帧预算——它不能每帧触发布局。这一条在现有代码里**已经被违反**（§5.1），本卷给出改法。
>
> ADR-1/2/3（坐标、几何分层、确定性）在本卷只引用结论，不涉细则。
>
> 行号基线：工作树 `806fa79`（v93）+ v96 未提交改动，**未锁 commit**。

## 0. 一条设计前提：玩家要的不是「快」，是「别骗我」

D5 §6.3 已经把「立即」拆成三种语义：≤300ms 直接出、≤3s 给确定性进度、≤30s 先问再等。本卷在这三条之上补第四条，因为 ADR-5 引入了一个新的时间尺度：

| 档 | 时长 | 触发 | UI 形态 |
|---|---|---|---|
| L0 | ≤300ms | 词表直命中（L1 复用档） | **不出进度条**，直接出结果 + 一次高亮 |
| L1 | ≤3s | 本地参数档（默认） | 确定性进度：「正在装配 · 3/5」，不转圈 |
| L2 | ≤30s | 云端深度许愿（用户显式点） | **先弹确认**「这次要约 30 秒，要等吗？」→ 四段进度 |
| L3 | **3–5 分钟** | 沙箱构建档（ADR-5 的第 2 段） | 五阶段 + 可取消 + 可后台 + 可读失败原因 |

**L3 不是常态，是本卷必须覆盖的最坏档。**它之所以是 3–5 分钟而不是 30 秒，因为它是唯一一条「从零构建一份新几何」的路径：子进程 180s 硬超时 + 排队 + 四道预算门 + 加载。D5 的 3s 档走的是「预烘焙部件重挂」，不构建新几何，两者不是同一件事。

**这条区分必须写进 UI 文案**，否则玩家会把「深度构建」当成「系统卡了」。L3 必须由玩家显式选择，且选择前显示「约 3–5 分钟」；不允许 L1 失败后偷偷升级。

## 1. 许愿输入

### 1.1 形态：一条命令条，不是一个全屏弹窗

现有 HUD 是纯 DOM（`src/ui/ui.ts`，478 行），底部有 8 个 dock 按钮，`Esc` 关面板、`H` 隐藏全部 UI、`T` 传送、`B` 图鉴、`M` 海图、`F1` 帮助、`J` Boss 出手、`V` 切模式、`F` 攻击、`E` 交互。**空闲且语义合适的键只剩 `G`**（Grant / 许愿），本卷取它。

```
[ 默认态 ]  底部中央一行淡字： 「按 G 许愿 · 想要什么就说什么」
[ 展开态 ]  ┌──────────────────────────────────────────────┐
            │ 我要一条会飞的龙                              │  120 字上限
            ├──────────────────────────────────────────────┤
            │ [一条金龙] [一盏引魂灯] [一座三间小屋]           │  示例 chips
            │ 深度构建 ☐ 约 3–5 分钟        剩余 12 次 · 71%  │  模式 + 额度
            └──────────────────────────────────────────────┘
```

三条形态规则：

1. **不遮视野**：命令条高度 ≤96px，从底部上滑 120ms，不改变相机、不暂停世界。玩家可以一边看着街上一边打字——这是「在城里许愿」而不是「打开一个表单」；
2. **不抢焦点直到玩家点它**：`G` 只展开，不自动聚焦输入框（避免手机端弹键盘遮住半屏）；再按一次 `G` 或点输入框才聚焦；
3. **退出走模态栈**：`Esc` 先收命令条、再关面板、再回默认。现有 `ui.ts:95` 只关面板，**本卷要求改栈式**——对既有代码的第二处改动。

### 1.2 示例提示：三条，对应三个真实可产出物

示例不是装饰，是**校准玩家预期**的工具。三条分别对应 D5 的三个样例与 D4 的三种产物类型：

| 示例 | 为什么是它 | 产出 |
|---|---|---|
| 「我要一条金龙」 | 覆盖**造物**（`kind: 'beast'`），且是玩家最想要的东西 | 952 面、1 次 draw |
| 「一盏引魂灯」 | 覆盖**道具**（`kind: 'prop'`），小、快、成功率高 | ≤400 面 |
| 「一座三间小屋」 | 覆盖**建筑**（`kind: 'building'`），会走用地六级检查 | ≤120,000 面 |

点 chip 不是「填入文字」那么简单——它应该**同时把模式切到对应档**（小屋自动提示「需要一块空地」），否则玩家点了之后仍然会问「为什么它说没地方」。

### 1.3 校验：三道早期拦截，全部在发请求之前

| 拦截 | 触发 | 表现 | 为什么必须前置 |
|---|---|---|---|
| **空 / 全空白** | 去掉空白后长度为 0 | 提交按钮 `disabled`，不显示错误（空输入不是错误） | 发一次空请求会浪费一次 token 预算，且返回的必然是「没听懂」 |
| **超长** | >120 汉字 | 100 字起计数变黄；120 字硬上限，第 121 字**打不进去**（不是提交时才报错） | 静默截断最伤：玩家以为说了，系统只收到一半 |
| **不可实现** | 本地词表未命中 **或** 命中 D6 §5.1 的五类硬边界 | 就地提示「这个做不到，因为…；要不要试试…」+ 一个可点的替代 chip | 让它走到议会再拒，是 3 秒换一句「不行」；在输入框里拒，是 0 秒换一条路 |

**「不可实现」的判定不能靠模型**。它必须是本地规则：词表命中（D5 §1.2.1 的 24 个量词 + 部件名）+ 五类硬边界（越界、越阶、越预算、越形制、越用地）。这样它才能在 **0ms** 内给出反馈，而不是等一次网络往返。

**中文输入法是最容易漏的坑**：`Enter` 在 IME 组合期是「确认候选词」，不是「提交」。必须监听 `compositionstart / compositionend`，在组合期内屏蔽提交。这条不写进断言就会在第一次真人测试时暴露。

### 1.4 额度可见，但不喧宾夺主

命令条右下角一行小字：`剩余 12 次 · 71%`。它让「深度许愿被当成默认」不可能发生（D5 §6.4 场景三）。只在该**展开态**显示（常驻会变成压力）；低于 20% 变黄、低于 5% 变红并提示「只剩 N 次」；用尽后 `L2/L3` 禁用，`L0/L1` 仍可用（本地档不烧 token）。

## 2. 3–5 分钟的过程 UI

### 2.1 五阶段：权重来自「谁真的花时间」

| 阶段 | 权重 | 可计数？ | 计数来源 | 上限 |
|---|---:|---|---|---:|
| 解析 | 2% | 是 | 词表命中数 / 槽位求解数 | 200ms |
| 生成 | 13% | **否** | 模型流式 token（不可预知总量） | 30s |
| 构建 | 70% | 是 | 沙箱 `emit()` 的部件计数 / 180s | 180s |
| 校验 | 10% | 是 | 四道门（面/包围盒/内存/确定性）1..4 | 2s |
| 加载 | 5% | 是 | bundle 五段（读/解压/校验/装配/上传） | 300ms |

**权重是「上限占比」的近似**：构建 180s 是唯一有硬上限的长阶段，其余四段合计 30–120s，70% 给构建偏保守。**但权重必须运行时重算**：走 L1（3s 档）时构建段不存在，权重退化为 解析 40% / 生成 45% / 校验 10% / 加载 5%，否则进度条会在 15% 停 2 秒再跳 100%。

### 2.2 可计数就给百分比，不可计数就给「活动指示」

这是本卷最重要的一条 UI 纪律：**禁止假进度**。

- **可计数阶段**（解析、构建、校验、加载）：显示真实比例。构建阶段的 `emit()` 次数是沙箱能上报的，四道门是 4 个离散点——这些都是真的；
- **不可计数阶段**（生成，即模型流式输出）：**不显示百分比**，显示 `已生成 1,240 字 · 12s` 与一个不确定态的活动条（来回扫，不填充）。因为模型输出的总长度事先不可知，任何百分比都是编的；
- **不显示「剩余 43 秒」**。只显示区间：「约 1–2 分钟」。假精确比模糊更伤信任——玩家会拿秒表对。

进度值本身必须**单调不减**。允许「停在 15% 等生成结束」，不允许「从 60% 退回 40%」——回退会让玩家以为任务重启了。

### 2.3 取消：一个按钮，三个动作

```
点击「取消」 →
  ① UI 立即置灰并显示「正在中止…」（≤100ms，不能等子进程）
  ② 子进程 SIGTERM；500ms 未退则 SIGKILL（ADR-5 的强杀条款）
  ③ 释放已产出的部分 bundle（ArrayBuffer 置空 + 不写缓存）
  ④ 不重试、不自动降级；已花的 token 记入会话预算，但不再产生新消耗
```

**取消按钮在「加载」阶段必须禁用**。理由：加载阶段只剩 300ms，而挂载是原子的（≤16.7ms 单帧完成）；在这个窗口里允许取消，只会制造「半挂载」——几何在、碰撞没在，或反之。**「不能取消」比「取消到一半」诚实。**

### 2.4 后台继续：收起不等于取消

命令条展开态在 L3 下会占掉底部 96px，玩家很可能想边走边等。所以：

- 收起（`Esc` 或点面板外）→ 任务**继续**，HUD 右上角出现一个小环（直径 18px，`transform: rotate` 驱动，不触发布局）；
- 完成 → toast 一行「造物已就绪 · 按 G 放置」+ 小环消失；
- 失败 → toast 一行「没做成：<原因> · 按 G 看详情」；
- **队列深度 = 1**：上一个还在跑时再按 `G` 不发起第二个，提示「上一个还在做（约 N 分钟）」。理由不是性能，是认知——两个同时跑的进度条，玩家不知道等哪个。

### 2.5 失败原因：错误码 → 人话 → 下一步

三段式，缺一不可。只给错误码是给工程师看的，只给人话是给玩家看的，**只有「下一步」才是产品**。

| 错误码 | 人话 | 下一步（可点） |
|---|---|---|
| `E_BUDGET` | 「这个想法要 32,000 个面，单件上限是 20,000」 | 「帮我简化到 2 万面以内」 |
| `E_UNSAFE` | 「这段描述里有不能执行的内容，已拦下」 | 「换一种说法重说」 |
| `E_TIMEOUT` | 「构建超过 3 分钟，已中止」 | 「减少部件再试」/「改用简单版」 |
| `E_PLACE` | 「这里放不下：<压路/压水/压房/坡太陡>」 | 「帮我找最近的一块空地」 |
| `E_SCALE` | 「尺寸超出可玩范围（0.85–1.15 倍）」 | 「回到默认尺寸」 |
| `E_NO_MODEL` | 「深度许愿还没开放，现在只能用本地档」 | 「用本地档试试」 |

**「下一步」必须是可点的动作，不是一句建议。** 一句「请调整后重试」等于什么都没说——玩家不知道往哪调。这张表里每一条都对应一个真实可执行的操作，这是 D6 §5.5「把不行变成一条路」在 UI 层的落地。

## 3. 出现在玩家 100m 内

### 3.1 为什么是 100m：一个上界、一个下界

「出现在玩家 100m 内」是需求原话。它在工程上要拆成两个界：

- **上界 100m**：超过它，「出现在我身边」就失效——看不到细节，也走不过去确认。更要紧的是，D6 §4.5 的用地六级检查要求「盖在哪」必须可见，100m 外的落点无法目视验收；
- **下界 8m**：贴脸生成会挡视线、会穿模、会落在玩家脚下。第三人称相机距离是 2.5–16m（`player.ts:188` 的 `camDist`），8m 已经在相机之外，但仍在一眼可及的范围内。

中间再切一刀：**60m**。8–60m 是「走过去两步」的舒适区，60–100m 是「看得见但要跑一趟」的提醒区。于是三档：

| 距离 | 判定 | UI |
|---|---|---|
| 8–60m | PASS | 绿色预览 |
| 60–100m | WARN | 黄色预览 + 「有点远，要走 10 秒」 |
| <8m 或 >100m | BLOCK | 红色 + 「太近了会挡路」/「太远了，走近点」 |

### 3.2 落点不是「随机找一个空位」，是「沿着玩家视线找」

默认落点算法（不给玩家看，只给结果）：

```
以玩家为圆心，沿当前视线方向 ±30° 的扇区内，从 12m 起、每 2m 一环向外搜；
每环取 5 个角度（-30/-15/0/+15/+30），第一个通过用地六级检查的点即默认落点；
扇区内找不到 → 扩到 360° 全环；全环 60m 内找不到 → 提示「附近没有空地，要不要换个地方」。
```

**为什么沿视线**：玩家说「我要一条龙」时，脑子里已经有它站的位置——通常就是正前方。随机落在背后，第一反应是「放错了」，而不是「那里没地方」。所以搜不到就给「换个地方」的选项，不在 100m 处强行兜底：把造物丢在 100m 外，等于让玩家走 10 秒去确认一个可能还要重放的东西。

### 3.3 预览：半透明幽灵 + 地面圆盘 + 三色

| 元素 | 规格 | 作用 |
|---|---|---|
| 幽灵体 | 原几何、透明度 0.35、无阴影、`depthWrite: false` | 看清形体与朝向 |
| 线框 | 同一几何的 `EdgesGeometry`，1px | 在浅色地面上也能看清轮廓 |
| 地面圆盘 | 半径 = 包围球半径、贴地 +0.02m、颜色随状态 | 表达「占地范围」，这是用地检查的可视化 |
| 朝向箭头 | 长 2m，从圆盘边缘指出 | 让「R 旋转」有意义 |

三色不是装饰，是**用地检查的实时反馈**：绿 = 六级全过；黄 = 过了但有警告（压到了步道边缘、坡度接近上限）；红 = 有一条硬规则没过，圆盘上同时显示是哪一条（「压路」「压水」「压房」「坡太陡」）。

### 3.4 微调：只动矩阵，不动几何

| 操作 | 步长 | 改什么 |
|---|---|---|
| `W/A/S/D` | 0.5m（= 1 体素格） | 位置 |
| `R` | 15° | 绕 y 旋转 |
| 滚轮 | 0.5m/格 | 距离（沿视线前后） |
| `Shift` + 上述 | ×4 | 快速粗调 |

**关键约束：微调不重建几何。**位置、旋转、缩放三类参数全部走实例矩阵（D5 §6.4 场景一已经写明），几何只在「换部件/改 `girth`」时重建。否则玩家连按 20 次方向键就是 20 次重建，每次 2ms 也是 40ms 的卡顿，而且完全没有必要。

**微调不写进 `CreationSpec`**。spec 是「它是什么」，位置是「它此刻在哪」；写进去会让同一个造物因摆放位置不同而得到不同 hash，D4 的 A5 立刻失效。

### 3.5 失败回退：给一个「最近的合法点」

用地检查失败时，除了变红和说明原因，还要做一件事：**在 8 个方向上以 2m 步长外扩，找到第一个绿点，画一个半透明标记**，并给一行「这里不行，最近的空地在左前方 14m」。

这条的成本很低（8 方向 × 最多 30 步 = 240 次 AABB 查询，<1ms），但它把「失败」变成了「一次点击就能继续」。D6 §4.5 已经论证过六级检查很便宜、必须前置；本卷补的是**前置之后怎么办**——只告诉玩家「不行」是不够的。

## 4. 可撤销与许可

### 4.1 两段式：预览期与落地期

| 阶段 | 玩家已付出 | 撤销方式 | 成本 |
|---|---|---|---|
| **预览期**（幽灵态，未提交） | 一次生成（token 已花） | `Esc` 直接丢弃 | 零（几何未挂载、未写存档） |
| **落地期**（已提交，10s 内） | 生成 + 挂载 + 碰撞 + 存档 | 点 toast 上的「撤销」或 `Ctrl+Z` | 一次事务回滚 |

**分界线是「提交」这个动作**，不是时间：预览期停多久都能直接丢；落地期 10s 是 D6 §2.7 定的窗口。

### 4.2 撤销 = 五项事务，不是「删掉模型」

| 项 | 回滚动作 | 漏了会怎样 |
|---|---|---|
| 几何 | `remove` + `geometry.dispose()` | 显存泄漏，`memory.geometries` 只增不减 |
| 碰撞 | 用旧包围盒重建一次 `walkSurface` 局部 | 看得见但走不进去，或看不见却能撞 |
| LOD | `LodManager.unregister(id)`（M1 才有） | 组数只增不减，远景永久多一个空组 |
| 存档 | 删除该条 `persist:true` 记录 | 重进游戏它又回来了 |
| 缓存 | **保留**（按 hash 可复用） | 重放同一条要重新构建，白花一次 token |

最后一行是**故意的**：撤销不等于「销毁证据」。几何还在缓存里，玩家改主意再放一次时不需要重新生成。只有缓存超限时才会被 LRU 淘汰。

### 4.3 撤销的三条边界

1. **只撤最近一次**。无限栈要为每份几何保存逆操作，不划算；玩家要的只是「刚才那个放错了」；
2. **预览期不占撤销栈**。没提交的东西没有「撤销」，只有「取消」；
3. **撤销后不自动重试**。理由同 §2.3：撤销的意思是「不要了」。

### 4.4 `persist:false`：临时造物的完整语义

D0 ADR-8.3 的原话是「`persist:false` 的生成物不得写入存档，避免存档膨胀」。本卷把它展开成四条可判定的规则：

| 规则 | 判据 |
|---|---|
| 不进存档 | 存档文件字节数与生成前**逐字节相等** |
| 不进存档索引 | 图鉴/收藏列表里没有它的 id |
| 退出即清 | 重启后场景里不存在同名对象 |
| UI 必须标注 | 预览与落地后都显示「临时」角标，不能只靠玩家记 |

**为什么「临时」必须可见**：玩家花了 3 分钟生成的东西，如果没有任何标记，他会默认它被保存了。第二天回来发现没了，那是**信任损失**，不是功能缺陷。

### 4.5 许可：默认「先看看」，不是默认「留下」

| 选择 | 语义 | 默认 |
|---|---|---|
| 临时（`persist:false`） | 只在这个会话里存在 | **是** |
| 留在城里（`persist:true`） | 写进存档，重进还在 | 否，需玩家点一次 |

默认临时，是因为**生成物的默认状态应该是「未决定」**，而不是「已承诺」。玩家点「留在城里」时才发生一次显式授权——这和 D0 的「对外动作要显式批准」是同一条纪律在游戏内的投影。

存档成本的提示阈值：单件 bundle ≤2MB 时不提示；>2MB 时提示「这个会占 3.1MB 存档」。配额：每人 ≤50 个 `persist:true` 生成物、≤64MB；超限时最旧的转临时，并告知。

### 4.6 「存档零增长」怎么证明

不是看文件大小「差不多」，是**逐字节比对**：

```
① 记录生成前存档文件的 sha256（含 index 与 blob 两份）
② 生成一个 persist:false 的造物，挂载、走动、交互
③ 退出到主菜单再进（触发一次完整保存）
④ 再算 sha256，必须与 ① 相等
```

`probe-wish-persist`（D9·C8）就按这四步跑。**只要有一个字节不同，就说明有东西漏进了存档**——哪怕只是时间戳或计数器。

## 5. 无障碍与性能

### 5.1 现有进度条正在每帧触发布局（一处必须改的既有代码）

这不是「建议优化」，是**已经存在的缺陷**。两处代码合起来构成了完整的布局抖动链：

```ts
// src/main.ts:37
bar.style.width = (p * 100).toFixed(0) + '%';
```

```css
/* src/style.css:25-26 */
.load-bar i { display: block; height: 100%; width: 0%; ...
  transition: width .25s; }
```

写 `width` 会触发布局；`transition: width` 让浏览器在 250ms 内**每一帧都重算布局**。载入有 33 步，即 33 次写宽：

```
33 次 × 250ms = 8.25s 的布局动画
载入总时长 ≈ 11.6s
⇒ 约 71% 的载入时间里，有一根正在做布局动画的进度条
```

**这条开销在软件光栅的 CI 里看不出来，在低端机上就是「载入时鼠标都卡」的直接原因。**

**改法（唯一正确解）**：

```css
.load-bar { contain: layout paint; }        /* 把布局影响关在容器内 */
.load-bar i {
  display: block; height: 100%; width: 100%;
  transform: scaleX(0); transform-origin: left center;
  transition: transform .25s; will-change: transform;
}
```

```ts
bar.style.transform = `scaleX(${p})`;   // 只走合成层，零布局
```

改完之后：`offsetWidth` 在整个载入期间恒定，变化的只有 `getComputedStyle(el).transform`。这就是 D9·C5 的判据。

**顺带修一处**：`.load-tip` 每步写 `textContent`（`main.ts:38`）也会触发布局；给 tip 固定高度 + `contain: layout paint`。

### 5.2 三条硬指标

| 指标 | 阈值 | 判据 |
|---|---|---|
| 进度条布局次数 | **0** | 每帧读 `offsetWidth`，全程不变 |
| DOM 写入频率 | ≤1 次/帧 | 用 rAF 合并；同一帧多次进度只取最后一次 |
| 主线程单次阻塞 | ≤16.7ms（L1/L2）/ ≤50ms（L3 构建期） | `probe-blocking` 的 p95 |

**为什么 L3 允许 50ms**：构建在子进程里，主线程只收进度与渲染；50ms 是「掉到 20fps 但不至于卡死」的量级。**但动画仍不能触发布局**——掉帧与抖动是两件事。

### 5.3 屏幕阅读器：可计数才报数

```
可计数阶段：role="progressbar" aria-valuemin="0" aria-valuemax="100"
            aria-valuenow="<真实值>" aria-valuetext="构建中，第 12/40 件"
不可计数阶段：role="status" aria-live="polite"
              只播报阶段名与已用时间，**不带 aria-valuenow**
```

**不可计数阶段不设 `aria-valuenow`**：读屏会把它当真实进度念出来（「百分之三十」），而那个数是编的。宁可只说「正在生成」。

`aria-valuenow` 必须**单调不减**且 ≤100；阶段切换时一次性跳到该阶段的起点值，不允许回退。

### 5.4 低端机降级

`QUALITY.low`（`engine.ts:29`）下，许愿 UI 同步降三档：

| 项 | high / med | low |
|---|---|---|
| 幽灵体材质 | 半透明原材质 + 线框 | **只画线框**（省一次透明排序） |
| 部件缩略图 | 128² 离屏渲染 | 64²，或直接用内置剪影 |
| 进度 UI | 五阶段 + 环形活动条 | 一行文字（「构建中 · 第 12/40 件」） |
| 预览刷新 | 每帧 | 每 3 帧 |

**降级不降信息**：low 档仍然显示阶段名、真实计数、取消按钮。省的是像素，不是可理解性。

### 5.5 弱网：只影响 L2，不影响 L0/L1

本项目是 Electron 本地应用，L0/L1 完全不联网。只有 L2（云端深度许愿）会遇到网络问题，处置三条：

1. **8s 无首字节 → 重试 1 次**（不是 3 次；重试次数是成本，不是礼貌）；
2. 重试失败 → **降级到 L1 本地档**，并明确告知「云端没连上，先用本地档给你一个」；
3. 全程必须有取消按钮。**任何超过 1s 的等待，没有取消按钮就是扣留人质。**

## 6. 验收断言

全部落 `probe-wish-*.mjs`（**待建**），判定只有 `PASS` / `BLOCK` + 退出码。D9 的断言全部是**打包态**——它们要读真实 DOM、真实键盘事件、真实存档文件。

| # | 断言 | 判据 | 探针 |
|---|---|---|---|
| C1 | 空/空白不发请求 | 输入 `""`、`"   "`、`"\n\t"` 三种，提交按钮 `disabled`，网络层请求计数 **0** | `probe-wish-input` |
| C2 | 超长硬拦 | 输入 120 字可提交；第 121 字**打不进去**（`value.length` 停在 120），计数显示 `120/120` 并变红 | 同上 |
| C3 | 五阶段单调 | 采样 100 次进度值，序列**单调不减**；每个 ≥200ms 的阶段至少出现 1 帧；不出现「构建」早于「生成」 | `probe-wish-progress` |
| C4 | 取消彻底 | 点取消后 1s 内：子进程消失（`tasklist` 无残留）、`cancelled` 标记为真、场景对象数回到取消前、无重试请求 | `probe-wish-cancel` |
| C5 | 进度条零布局 | 载入全程每帧读 `offsetWidth`，**恒定不变**；`transform` 的计算值单调变化 | `probe-progress-layout` |
| C6 | 落点三档 | 8–60m PASS、60–100m WARN、>100m BLOCK、<8m BLOCK；四档各一个样本 | `probe-wish-placement` |
| C7 | 10s 撤销 | 生成 → 撤销后：对象数、`memory.geometries`、存档 sha256 **三项全等于生成前**；缓存仍在（同 hash 再生成耗时 ≤ 首次的 10%） | `probe-wish-undo` |
| C8 | `persist:false` 零增长 | 生成 → 退出到主菜单 → 重进：对象不存在；存档 sha256 与生成前**逐字节相等** | `probe-wish-persist` |
| C9 | 无障碍 | `aria-valuenow` 单调不减且 ≤100；不可计数阶段该属性**不存在**；`role` 在两种模式间正确切换 | `probe-wish-a11y` |

**C5 是唯一一条针对既有代码的断言**：它现在是 **BLOCK**（§5.1 的 `width` + `transition`），改完才可能 PASS。列进来是因为没有机检，「进度条不抖」很容易被下一次「美化」改回去。

**C7 的第三项（缓存仍在）容易被写成「缓存清空」**：撤销的语义是「把这个东西从这个位置拿掉」，不是「销毁它」。如果撤销同时清了缓存，玩家改主意再放一次就要重新构建——3 分钟的等待乘以二。

## 7. 不做与未决

### 7.1 明确不做

| 不做 | 理由 |
|---|---|
| 全屏 modal 许愿窗 | 遮住世界，与「在城里许愿」冲突；命令条够用 |
| 语音输入 | 要麦克风权限与 ASR 依赖，中文市井语料识别质量无数据 |
| 多轮聊天式许愿 | 议会有 3 轮硬上限，聊天气泡会让玩家以为可无限聊，且每轮都是 token |
| 进度条显示「剩余 N 秒」 | 假精确；生成时长不可预知 |
| 无限撤销历史 | 要存每份几何的逆操作；玩家需要的只是「刚才放错了」 |
| 许愿时暂停世界 | 世界在跑才有市井感；暂停会把游戏切成编辑器 |

### 7.2 未决

- **U1**：`Esc` 改栈式会改变 `ui.ts:95` 的既有语义（现在是一次关所有面板），需 lead 确认；
- **U2**：L3 是否显式标「深度构建」——标得太显眼玩家不敢点，太隐蔽点了以为卡死。本卷取「默认折叠」，属产品判断；
- **U3**：`persist:true` 的配额（50 个 / 64MB）按「存档读取 ≤2s」倒推，无实测。

## 8. 自认最弱的三段

1. **§2.1 的阶段权重（2/13/70/10/5）是推算，没有任何一次真实的 L3 运行数据。**仓库里既没有 `CreationBundle`，也没有沙箱构建器。若真实构建只要 20s 而排队与校验花了 40s，这套权重会让进度条在 15% 停很久再猛跳——那正是本节反复要避免的「假进度」，只是换了一种假法。

2. **§5.1 的「8.25 秒布局动画」是上界，不是实测。**算法是「33 次写宽 × 250ms 过渡」，但真实的 `transition` 会在下一次写值时被打断并重新计时，所以实际处于布局中的时长可能明显小于 8.25s。我没有跑过 `PerformanceObserver` 去数 layout 次数。**结论（`width` + `transition` 会触发布局）是确定的，量级（71%）是估的。**

3. **§3.2 的落点搜索没有做可用性验证。**「沿视线 ±30° 扇区、12m 起每 2m 一环」是我按第三人称相机的常识定的，但宋代街巷的实际宽度、摊贩占位、桥面坡度都没有纳入。真实场景里很可能出现「扇区内全是房子，全环搜索要转 8 次」，而每次转都会让玩家觉得「它怎么跑我后面去了」。这条只能靠真人试玩暴露，纸面上推不出来。

最后补一句**不算在三条内**的：本卷所有键位（`G` 许愿、`R` 旋转、`Ctrl+Z` 撤销）都经过与现有 `player.ts` / `ui.ts` 的逐一比对，确认未被占用；但**没有在真机上试过中文输入法 + 快捷键的冲突**（输入框聚焦时 `Ctrl+Z` 应走文本框撤销，不是造物撤销）。这个模态冲突必须由实现者按「焦点优先」处理。
